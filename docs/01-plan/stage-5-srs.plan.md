# Stage 5 — 복습 (M5: SM-2 · 오늘의 복습 · 플래시카드)

> 상위: `study-app.plan.md` v0.4 §10 · 설계: `../02-design/study-app.design.md` §4.5(srs 연동), §4.7, §5.7
> 선행: Stage 3 (attempts 파이프라인) — Stage 4와 병행 가능 · 포함 기능: F09, F10

## 목표

간격반복이 "오늘 복습할 것"을 골라주는 루틴 완성. 계획서 §10의 규칙을 그대로 구현한다.

## 작업 체크리스트

### 1. 백엔드 — SM-2 엔진 (`services/sm2.py`)
- [ ] 순수 함수 `update(card, q) -> card`: 표준 SM-2 —
      오답(q<3): rep=0, interval=1, EF 유지 / 정답: 1회차 1일→2회차 6일→이후 interval×EF /
      EF' = EF + (0.1 − (5−q)(0.08 + (5−q)×0.02)), 하한 1.3
- [ ] **단위 테스트 필수** (pytest): 오답 리셋, 1→6→EF 진행, EF 하한, 경계 q값 — 이 프로젝트에서 유일하게 테스트를 강제하는 모듈 (날짜 계산 버그는 눈에 안 보이게 학습을 망침)
- [ ] q 매핑 (계획서 §10): 퀴즈 정답(문항 평균시간 이하)=5 / 정답(초과)=4 / wrong_only 재도전 정답=3 / 오답=1, 플래시카드 안다=4·모른다=1
- [ ] 카드 생성: 해당 문서의 **첫 attempts 또는 첫 플래시카드 판정 시** 자동 생성 (반입 시 아님)
- [ ] attempts 트랜잭션에 SM-2 갱신 통합 — 응답의 `srs.due_date` 채우기

### 2. 백엔드 — 복습 큐
- [ ] `GET /api/srs/today`: `due_date<=오늘`, 우선순위(오답노트 미해결 > 기한초과 오래된 순),
      상한 `settings:srs.daily_limit`(기본 30)
- [ ] `POST /api/srs/answer`: 플래시카드 판정용 (attempts를 남기지 않는 경로)
- [ ] dashboard `today_review` 카운트 채우기

### 3. 프론트엔드
- [ ] 홈 "오늘의 복습 N개" 버튼 → 복습 세션: 문제는 퀴즈 카드, 개념/플래시카드는 카드 뒤집기 — 혼합 큐를 순서대로 소화, 완료 시 요약
- [ ] **플래시카드 모드** `/flashcards` (설계 §5.7): 3D 뒤집기 애니메이션(CSS transform),
      스와이프 제스처(터치)+키보드(스페이스 뒤집기, ←모른다/→안다), 남은 장수
- [ ] 문서 상세에 SRS 상태 표시(다음 복습일, EF)
- [ ] 설정에 복습 상한 변경 UI

## 완료 기준 (DoD)

1. pytest 통과: SM-2 시나리오 테스트 전부 green
2. 어제 틀린 문제가 오늘 복습 큐에 나타남 (interval=1 확인)
3. "안다" 연속 판정 시 다음 복습일이 1→6→(6×EF)일로 늘어나는 것을 문서 상세에서 확인
4. 복습 큐가 상한(30) 초과분을 자르고, 오답노트 미해결이 먼저 나옴
5. 폰에서 플래시카드 스와이프 판정이 자연스럽게 동작 (시나리오 S1 완성)
