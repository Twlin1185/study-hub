## 목표

끝났을 때, "확률과 확률분포" 문서 안에서 `![[DOC-xxxx]]` 참조 하나로 기존 "산술평균" 문서가 **그 자리에 임베드 카드로 펼쳐져 보이고**, 같은 모듈 문서를 여러 상위 문서가 재사용한다. 구간 가리기·접기로 암기형 열람이 되고, 문서·구간 이동 버튼이 동작하며 — 이 모든 확장에서 **정답·해설이 새로 유출되는 경로가 0**이다.

## 작업 체크리스트

> 권장 순서: **1(해석 API·인덱스) → 2(임베드 렌더) → 3(가리기·접기·이동) → 4(편집 도우미·사용처 표시) → 5(테스트) → 6(문서·매뉴얼)**.

### 1. 백엔드 — 임베드 해석 API·참조 인덱스

- [ ] **임베드 해석 엔드포인트(신규 1개, 설계 §4.19 계약)**: doc_no 목록 배치 조회 → 항목당 `{doc_no, title, type, content, is_active}`**만** 반환. **answer·explanation은 응답 스키마에 존재하지 않는다**(불변 규칙 1 — QuizCard가 같은 렌더러를 쓰므로 계약 수준 봉인). 존재하지 않는 doc_no는 부재 표시로 반환(404 아님 — 배치 부분 성공)
- [ ] 본문 파서(서버): content에서 임베드·링크 참조 추출(D1 문법) — 저장(documents POST/PATCH)·반입(commit) 시 `document_relations(relation='embeds', created_by='embed')` **동기화**(본문에서 사라진 참조 행은 삭제, 본문이 단일 출처·행은 파생 인덱스)
- [ ] **전량 재계산 경로 확보**(R20): 기존 문서 전체를 재파싱해 embeds 인덱스를 재구축하는 관리 함수 1개(도입 시 1회 백필 겸용 — 새 테이블·마이그레이션 없이 인덱스가 언제든 재생성 가능함을 보장)
- [ ] 문서 소프트 삭제 시 "N개 문서에 임베드됨" 경고 정보 제공(embeds 역참조 집계 — 기존 사용처 표시 계약에 필드 추가 여부는 설계 §4.19에서 확정). **삭제 차단은 하지 않는다**(§6.3 원칙)

### 2. 프론트 — 트랜스클루전 렌더 (MarkdownView 확장)

- [ ] MarkdownView에 참조 문법 처리 추가(D1·D2 채택 플러그인) — **공용 모듈 1곳 수정으로 전 화면 일관 적용**, 화면별 분기 금지
- [ ] 임베드 카드: 대상 문서 본문 렌더 + 출처 배지(DOC-번호·제목) + [원문 열기] — 스타일은 토큰만
- [ ] **순환·깊이 방어**: 중첩 깊이 상한(D3) + 방문 집합 순환 검출 → "순환 참조" 자리표시자(무한 재귀·무한 fetch 0)
- [ ] **자리표시자 3종**: 순환 / 삭제된 문서(is_active=0 — 내용 미노출, 복원 시 재표시) / 존재하지 않는 참조 — 문구는 설계 §4.19 확정안
- [ ] 해석 호출은 배치·캐시(D3 확정안) — 한 문서 열람에 임베드 수만큼 개별 요청을 쏘지 않는다
- [ ] **학습 의미론 불변 확인**: 임베드 열람이 임베드 대상 문서의 study_progress·SRS·attempts에 어떤 기록도 만들지 않는다(열람한 것은 상위 문서 — 이중 진도 방지)

## DoD (완료 정의)

1. 개념 모듈 문서 1개를 **서로 다른 상위 문서 2곳 이상에서 임베드**해 각 문서 안에서 내용이 그 자리에 보인다(라이브 확인 — 사용자 예시 시나리오 재현).
2. 순환 참조·삭제된 참조·존재하지 않는 참조가 각각 자리표시자로 안전하게 표시된다(렌더 크래시·무한 재귀·무한 요청 0).
3. **임베드 해석 경로로 정답·해설이 내려오는 응답 0** — 퀴즈·플래시카드 화면 포함 전 화면에서(응답 스키마 부재로 보증 + 스모크 확인).
4. 가리기·접기·이동(문서 칩·헤딩 앵커)이 PC·폰에서 동작하고, 시각효과는 토큰만 사용(다크 모드 공짜).
5. 임베드 열람이 대상 문서의 진도·SRS에 기록을 만들지 않는다.
6. embeds 인덱스는 본문 재파싱으로 전량 재구축 가능하다(재계산 함수 멱등 — 본문이 단일 출처).
7. DDL 변경 0건·Alembic 0건 (설계 §4.19에서 재확인 — 어긋나면 착수 중단 후 보고). 신규 엔드포인트는 임베드 해석 1개뿐.

## 이 단계에서 하지 않는 것

- **블록/구간 단위 트랜스클루전**(`![[DOC-0012#절]]`) — 문서가 이미 개념 단위 모듈이라는 전제와 중복. 실수요 확인 후 v1.x+ 후보로 계획서에 먼저 확정.
- **참조 대상 삭제 차단·강한 참조 무결성** — 소프트 삭제 원칙과 충돌. 자리표시자 + 삭제 시 경고로 해결(계획서 F43 확정).
- **임베드 내용의 FTS 색인 포함** — 검색은 정본 문서에서 이미 걸린다(이중 히트 방지).
- **임베드 문서의 퀴즈 출제 범위 자동 편입** — 출제 범위는 기존 분류 연결·북마크로만.
- **WYSIWYG 편집기·실시간 미리보기 강화** — DocEditor는 텍스트 폼 + 삽입 도우미까지.
- **문서 버전 관리** — R4 결정 유지(updated_at만).
- **rehype-raw(원시 HTML 렌더) 도입** — XSS 표면 확대. D2에서 directive 계열이 기각될 때만 재검토(그 경우 새니타이즈 계획을 설계에 먼저).
