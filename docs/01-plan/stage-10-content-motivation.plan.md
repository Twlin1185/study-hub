## 목표

자격증을 고르고 회차를 고르면 **기출 한 회차가 앱 안에서 반입까지 완결**되고(수집→LLM 정리→미리보기→승인 — 신규는 수집기뿐, 나머지는 기존 파이프라인 재사용),
매일의 학습이 **스트릭·일일 목표로 눈에 보인다**(홈 위젯·히트맵·복습 완료 화면 연동).

- [x] **크롤링 예의 공통 장치**(registry): robots.txt 확인(캐시 24h, 비허용 시 수집 거부+대안 안내) · 사이트별 **최소 2초** 전역 스로틀(도메인 락 — 목록·문항·이미지 전부, 오류 시 지수 백오프, 병렬 금지) · User-Agent `StudyHub-Personal/1.0` · 자격증/회차 목록 메모리 캐시(TTL 24h) · SSRF 사설/루프백 차단
- [x] 회차 정규화 키(`YYYY-N`) 산출 + **병합·큐넷 우선 선정**(같은 키 양쪽 존재 시 qnet 채택, comcbt는 `also_on`) — 자동 대체 전환 없음(실패 시 사용자가 어댑터 지정 재시도) · `fetch_service.list_exams` + 단위 테스트

### 2. 백엔드 — 어댑터 2종 (F35-2, 설계 §4.13)
- [x] `comcbt.py` — 자격증 검색·회차 목록·회차 수집. **실측 확정**(셀렉터 상수 모듈 상단 집약): robots `Allow:/`, 홈 730종목 `xe/{mid}` 맵, 게시판 회차 글 목록, `YYYY-N` 키. ⚠ **문항 본문은 정적 HTML에 없음**(인터랙티브 JS CBT 앱 + 회차별 PDF 첨부) → `FetchedExam` 대신 **PDF 첨부 다운로드→convert(LLM 구조 추출)** 경로로 구현(추측 셀렉터 배제 — 설계 §4.13 원칙). 설계 가정(HTML 구조 추출)과 상이 — **설계 §4.13 실측 노트(2026-07-25)에 반영 완료**
- [x] `qnet.py` — **F35-1 다운로드 경로(registry SSRF·크기 상한·스로틀) 재사용**하는 `fetch_exam`. ⚠ q-net.or.kr는 robots가 점검 오류페이지·공개문제 카탈로그가 JS 포털이라 **목록 실측 불가** → `search_certs`/`list_exams`는 빈 목록+`available:false` 안내 스텁(추측 셀렉터 배제), 우선순위 1·비공개 제외 원칙 유지. 포털 구조 확정 시 qnet.py 목록 부분만 채우면 병합·우선순위가 자동 작동 — **설계 §4.13 실측 노트(2026-07-25)에 반영 완료**
- [x] 그림 문제: 이미지 다운로드(registry 스로틀) → `sources/images/` 저장(R2 관례) → content Markdown 링크(`_save_fetch_images`, `FetchedExam` 경로). 원본 불변 준수 (현재 comcbt는 PDF 경로라 이미지가 PDF 내장 — 코드 경로는 구현·대기)
- [x] 출처 기록: `documents.source_detail`("YYYY년 N회 M번") + `sources.note`(수집 URL·어댑터 id) — 프롬프트 강제 지시(`_fetch_directives`)

### 3. 백엔드 — 반입 잡 연결 (F35-2, 설계 §4.13)

### 4. 백엔드 — 목표·스트릭 (F26, 설계 §4.13)

## 완료 기준 (DoD)

1. [사이트에서 가져오기] → 자격증 검색 → 회차 선택 → 예상 사용량 확인 → 실행 → 미리보기 → 승인 반입 — **한 회차가 앱 안에서 완결**되고, 분류 트리에 "자격증/필기/YYYY년 N회"가 자동 생성됨
2. 양쪽 사이트에 있는 회차는 목록에서 **큐넷 채택**으로 1건만 노출(comcbt는 also_on 표기), 이미 반입한 회차에 "이미 반입됨" 배지
   — ※ 실측 각주(2026-07-25): qnet 목록이 스텁(`available:false`)이라 **큐넷 우선 병합은 현재 실동작으로 확인 불가** — 병합·우선순위 로직은 단위 테스트로 검증됨, 실동작 확인은 qnet 목록 구현 시(설계 §4.13 실측 노트)
3. 그림 문제가 이미지 포함으로 반입됨 — 이미지는 `sources/images/`에 저장, 본문 Markdown 렌더에 표시
4. 수집 요청 로그에서 **동일 사이트 요청 간격 2초 이상** 확인, robots 비허용 경로는 수집 거부 + 대안 안내
5. 파싱 실패 시 원문 HTML 없이 "사이트 구조 변경 가능성" 메시지 + [URL로 반입] 대안 버튼 동작. 반입된 문항의 내용 오류는 기존 F30 신고·재생성으로 처리됨
6. 확인 스텝 없이 수집 실행 불가 — 예상 사용량·재배포 금지 고지가 항상 표시되고, 한도 기억 상태면 경고 배너 노출
7. 일일 목표 설정 → 문제를 풀면 홈 스트릭 위젯 게이지·히트맵 링·복습 완료 배지가 **같은 판정으로** 갱신됨. 목표 미설정이어도 스트릭(활동 기준)은 동작
8. 오늘 활동이 없는 아침에도 어제까지의 스트릭이 유지 표시되고, 활동 시 +1 반영
9. §6.2 DDL diff 0 · Alembic 마이그레이션 0건 확인. 기존 heatmap·convert API 호출부(파라미터 없는 기존 사용) 응답 불변
