## 확정 규약 (구현 전 결정 — 이 문서 + api §4.29 ⑦ + screens §5.3 S36이 정본)

### A. 편집 진입점 전수·통합 분기 (FB-5 이행 — "하나 남기고 다 놓치는" 사고의 원천 차단)

**진입점 전수표(2026-08-19 코드 실측 — `<DocEditor`·`<DocBlockEditor` 전수 grep)**:

| # | 진입점 | 현재 | 이 단계 후 |
|---|---|---|---|
| ① | 문서 상세 `/docs/:id` [편집] | **분기 이행 완료(stage-35)** — DocBlockEditor | 유지(무변경) |
| ② | `/docs/new` (신규 작성 전용 라우트 — `DocEditPage`) | 구 편집기(DocEditor variant="page") | **통합 분기** |
| ③ | `/docs/:id/edit` (수정 전용 라우트 — `DocEditPage`) | 구 편집기 | **통합 분기** |
| ④ | 탐색 `Explore` [+ 문서](create 모달) | 구 편집기(DocEditor 모달) | **통합 분기** |
| ⑤ | 커리큘럼 `CurriculumDetail` [+ 문서 추가](create 모달) | 구 편집기 | **통합 분기** |
| ⑥ | 커리큘럼 `CurriculumDetail` 문서 행 [편집](edit 모달) | 구 편집기 | **통합 분기** |

- ②~⑥은 **전부 공용 `DocEditor` 1곳을 경유**하므로 개조 지점은 **DocEditor 내부의 본문·해설 편집
  위젯 분기 1곳**이다(진입점별 복붙 금지). 분기 조건 = stage-35 규약 F 그대로: **퇴로 토글 ON** 그리고
  ⓐ 전환 문서이거나 ⓑ 메모리 변환이 미지원 0으로 성립(신규 작성은 빈 문서 = 항상 성립) → 본문·해설이
  블록 표면. 그 외 → 기존 `MarkdownFieldEditor` 그대로. **제목·type·choices·answer·difficulty·태그·
  스타일 등 폼 필드는 기존 폼 유지**(D7 1차 — 문서 표면으로의 흡수는 하지 않는다).
- **토글 OFF = 전 진입점에서 구 편집기 완전 복귀**(퇴로 불변 축). 구 편집기 잔존 한계는 수용·매뉴얼
  명시: stage-35 검토 D-5(구 편집기 인라인 모델의 `{w=}` 리터럴 표시 — 손실 0)는 **수정하지 않는다**
  (통합 후 구 편집기는 퇴로 전용이라 노출 빈도가 급감 — 배선 비용이 효용을 넘는다).
- 통합 후 **전환 해제를 유발하는 클라이언트 경로 = 토글 OFF의 구 편집기뿐**이 된다(stage-35 규약 F의
  "신규 작성·모달 저장 = 전환 해제" 알려진 문제의 해소가 이 단계의 존재 이유 절반). 서버 내부 경로
  (F30/F44 등 — stage-35 전수표)는 무변경.

### B. 신규 작성 저장 = POST 블록 동반 (api §4.29 ⑦ [S36] — 신규 엔드포인트 0)

- `POST /api/documents`가 §4.29 ②와 **같은 동반 규칙·얕은 검증·상한**으로
  `content_blocks`↔`content` · `explanation_blocks`↔`explanation` 쌍을 받는다(한쪽만 = 422
  `projection_required`). 동반 생성된 문서는 **태생 전환**(`blocks_version` 서버 사본 — §4.28 ② 전례).
- **블록 미동반 POST = 종전 계약 그대로 미전환 생성**(하위 호환 무변 — 구 편집기·반입 경로(F40/F42/F45
  등 서버 생성 전부)는 1바이트도 변하지 않는다).
- 에러 3종·봉인(§4.29 ⑤·⑥) 그대로 적용. 목록·batch 무변경 유지.
- 편집(PATCH) 파이프라인은 **stage-35 자산 그대로 재사용** — 어댑터 호출은 반드시 사이드카 동반
  (`fromBlockNoteResult` 경유 — 새 `fromBlockNoteBlocks` 직접 호출부 0. stage-35 규약 D 계승),
  자동 저장·저장 상태 4종·IME 보류·microMark 접힘 고지·표면별 `sidecarRef` 분리(F-4 보정분) 전건 계승.

### C. D7 1차 — `choices`·오답노트 메모 인라인 리치 (저장 계약 무변)

- **저장 = 기존 문자열 필드 그대로**(`documents.choices`·review-notes 메모 — DDL 0·API 0).
  편집 UI도 기존 폼 입력 유지 — 인라인 방언(F52 마이크로 3종·`:t[]{}`·굵게 등)을 **문법으로** 쓴다.
- **렌더만 확장**: 보기(choices)·메모가 표시되는 지점 전수(퀴즈 카드·문서 상세·학습 모드·인쇄·오답노트 —
  **전수 조사 목록은 F-3에서 작성해 완료 기록에 표**)에서 인라인 방언을 렌더한다. 기존 인라인 렌더
  자산(F51/F52 — 공용 MarkdownView 인라인 계열) 재사용 — **보기 전용 신규 렌더 경로 금지**.
- **채점·봉인 무접촉이 계약**(불변 규칙 1): choices는 원래 quiz/session 응답에 포함되는 표시 데이터고,
  정답·해설 봉인은 서버 계약(§4.29 ⑤)이 담당한다 — 이 항목의 **서버 diff는 0**이다. 블록 필드가
  quiz/session·resolve-embeds에 새로 실리는 경로도 0(기존 봉인 유지 확인 = B-2).
- 문법 표시가 깨지는 기존 문서(방언을 안 쓴 choices)는 **렌더 diff 0**이 계약 — 방언 문법이 없는
  문자열은 종전과 동일하게 보여야 한다.
- **문제 블록 구조화(choices의 블록 재설계)는 하지 않는다** — v2.x 백로그(별지 §10 D7 확정 기록).

### D. 문서 임베드 리치 표면 격상 (FB-3 — R20 봉인과의 정합이 계약)

- 편집 표면의 `docEmbed` 블록(현재 = 원자·제목 추종 카드)이 **대상 문서 본문을 카드 안에 읽기 전용으로
  렌더**한다. 데이터는 **`POST /api/documents/resolve-embeds`(§4.19) 재사용**(신규 API 0) — 이 응답은
  **answer·explanation·style·블록 필드 부재 봉인**(R20·§4.26 ②·§4.29 ⑤)이 이미 걸려 있어 편집 표면이
  새 정답·해설 유출면을 열지 않는다. **봉인 응답 밖의 필드를 다른 API로 보충하는 경로 금지.**
- 렌더는 **공용 `MarkdownView` 재사용**(프로젝션 소비 — D5 정합. 임베드 전용 렌더 경로 금지).
  카드 안은 **읽기 전용**(클릭해도 그 자리 편집 없음 — D11-ⓑ 착수 금지)이며 [원문 열기]·접기 토글 제공.
- **중첩 임베드는 1단만 펼친다**(카드 안의 임베드는 기존 리더 F43 관례와 같은 축약 표시) —
  순환 참조로부터의 방어를 겸한다. 미해결·삭제 대상은 기존 자리표시자 칩 관례.
- 상세 UI(접기 기본값·카드 스타일)는 구현 재량 — 리더의 F43 임베드 카드와 시각 관례를 맞춘다.

### E. Notion UX 마감 (엔진 표면 완성 — 전부 프론트)

- **슬래시 메뉴 정비**: 항목 전수표를 만들어(코어 블록 + 콜아웃·수식·참조 3종·임베드 — stage-34 이식분)
  한국어 라벨·그룹·검색 별칭을 정리한다. 항목 추가/삭제가 아니라 **정합·발견성 마감**이다.
- **드래그 재배열**: 코어 사이드 메뉴(드래그 핸들) 활성·동작 확인 — 재배열 후 **사이드카(블록 id 키)
  정합 유지**가 계약(id는 이동해도 불변이므로 성립해야 한다 — 깨지면 버그로 수정), s33/s34 회귀 무변.
- **표 열 정렬 편집 UI**(별지 §5.4 코어 범위 제약 3번의 소유 이행): 표 선택 시 열 단위 정렬(좌/중/좌우
  없음/우) 편집 UI. 정렬 상태는 편집 세션 동안 UI가 소유하고 저장 시 사이드카 `table:align` 규약으로
  직렬화 — **열 증감도 UI가 정렬 배열을 함께 갱신**하므로 "열 증감 시 인덱스 어긋남"은 편집 UI 경로에서
  소멸한다(2026-08-17 판정 완료 사항의 재론이 아니라 그 판정이 예정한 마감이다).
- **안정 undo**: 표면별 undo 격리 재확인(U-2 전례 — 제목·폼 필드 undo가 블록 표면을 되돌리지 않는다.
  DocEditor 통합으로 폼+블록 혼합 표면이 늘어나는 단계라 필수) + 드래그·표 편집·바꾸기가 각각
  **undo 1단위**로 묶인다.
