## 확정 규약 (구현 전 결정 사항 — 이 문서가 정본)

### A. 왕복 "동형"의 정의 (DoD 판정 기준)

Markdown→블록→Markdown 왕복에서 바이트 동일은 **요구하지 않는다** — mdast를 거치는 순간 표기(마커 종류·
이스케이프 형태·들여쓰기 폭·강조 중첩 순서)는 정규형으로 수렴하는 것이 정상이다. 대신 3계약을 요구한다:

1. **정규형 동등(1차 왕복)**: 원본과 투영본을 **동일 remark 파이프라인**(s30-roundtrip.mjs와 같은 플러그인
   세트: parse+gfm+math+directive+remarkStudy 2종)으로 각각 파싱한 mdast를 정규화 함수 N에 통과시켜
   deep-equal. N의 정의: ⓐ `position` 제거 ⓑ 인라인 트리를 **(텍스트, 마크 집합) run 배열로 평탄화**하고
   인접 동일-마크 run 병합(강조 중첩 순서 `***a***` 류의 파싱 모호성 흡수) ⓒ 블록 구조·순서·속성(`:t` 값,
   링크 URL·title, 참조 대상, 목록 ordered/start, 코드 lang 등)은 그대로 비교.
   - **허용되는 차이**: 마커 표기(`*`↔`-`, `__`↔`**`), 이스케이프 형태, 목록 들여쓰기 폭, 헤딩 닫힘 해시,
     강조 중첩 순서.
   - **불허**: 텍스트 내용의 어떤 변화든(공백 1문자 포함), 마크 집합 변화, 속성 값 변화, 블록 구조·순서 변화.
   - **N의 명시적 예외 2건**(2026-08-15 구현 중 확정 — 암묵 확장 금지 원칙에 따라 여기 등재한다.
     검증 스크립트 `s32-normalize.mjs`가 이 정의를 따른다):
     - **ⓓ 블록 가장자리 공백 트림** — 문단·헤딩·표 셀의 앞뒤 공백은 CommonMark 파서가 항상 버리는
       자리다(`&#32;` 같은 수치 문자 참조로 우회 표기는 가능하나 방언·에디터가 그 표기를 쓰지 않는다).
       문단 안 임베드가 블록으로 승격될 때 남는 꼬리 공백이 유일한 발생원이며, 변환기와 N이 **같은
       규칙**으로 떨어낸다. 그 외 위치의 공백은 여전히 1문자도 불허다.
     - **ⓔ list 컨테이너 해체** — 규약 B가 목록을 `listItem` 단위로 못박았으므로 N도 컨테이너를 걷어내
       항목 시퀀스로 편다. 단 **목록 경계는 보존**한다(마커·구분자 변경 = CommonMark의 목록 분리
       표기이므로 `groupBreak`로 표현·비교한다). 같은 마커로 이어진 목록만 하나로 합쳐진다.
2. **고정점(2차 왕복)**: 1차 투영본을 다시 블록→Markdown 재왕복하면 **바이트 동일**이어야 한다
   (정규 직렬화는 1회 왕복 후 안정 — 저장 반복으로 본문이 흔들리지 않는다는 계약).
3. **이스케이프 방어**: 사용자가 문법 문자를 평문으로 입력한 텍스트가 블록에 담겼을 때, 투영→재파싱이
   같은 평문을 복원해야 한다(조용한 본문 변형 0 — s30 HAZARDS 계약 계승). 이스케이프 과잉 방지
   (단어 내부 `_` 비이스케이프, URL 백슬래시 0)도 s30 ②-4 계약을 그대로 계승한다.

### B. M32 블록 팔레트 (스키마에 등재하는 타입 — 코퍼스가 커버하는 현행 문법 전부)

- **블록**: paragraph · heading(1~6) · listItem(bullet/ordered — **중첩은 children**, GFM 체크박스 속성 포함) ·
  quote · codeBlock(lang) · table · mathBlock(`$$`) · image(캡션·**크기**) · divider(`---`) ·
  callout(`:::note[제목]` — F52) · docEmbed(`![[DOC-nnnn]]` — 문단 밖 블록) ·
  **sourceFallback**(팔레트 밖 mdast 노드의 원문 Markdown 슬라이스 보존 — 아래 D 참조).
- **인라인**: styledText(마크 집합: bold·italic·strike·underline(`++`)·highlight(`==`, 색)·spoiler(`||`)·
  ink/bg/size(`:t` — 팔레트 ∪ #rrggbb 화이트리스트는 기존 규칙 그대로)) · inlineCode · inlineMath(`$`) ·
  link(url·title) · refChip(doc/anchor, **별칭 유무 구분** — 아래 C) · hardBreak · softBreak.
- 목록은 mdast처럼 컨테이너(list)로 싸지 않고 **listItem 블록 단위 + children 중첩**으로 둔다 — BlockNote
  구조와 동형이라 M33 어댑터가 얇아진다. list 컨테이너↔listItem 변환은 변환기가 흡수한다.
- 문서 루트 = `{ version: 1, blocks: [...] }`. 블록 공통 필드 = `id`(동형성 비교에서는 제외) +
  `meta?`(**`meta.provenance` 형태만 예약** — 계획서 §5.4 캡처 예약 이행. 필드 정의만, 소비 코드 금지).
- **이 단계에서 등재하지 않는 타입**: TOC·웹 임베드·이미지 크롭·다단·문제 블록(M35 이후) — 스키마는
  타입 추가가 가능한 구조(discriminated union + version)면 족하다. 미리 만들지 않는다(YAGNI).

### C. 참조 칩 스키마 — §5.4 재설계 요구와의 교차 검증 (계획서 147행 이행)

refChip 스키마는 §5.4 요구 ④("칩의 Markdown 프로젝션은 기존 F43 문법으로 강등")와 모순되지 않아야 한다.
스키마가 보장할 것:
- **별칭 없는 칩**(라벨 = 대상 제목 추종)과 **사용자 지정 라벨 칩**을 구분 저장할 수 있을 것 —
  전자는 `[[DOC-0012]]`, 후자는 `[[DOC-0012|라벨]]`로 왕복. 라벨 추종형이 제목 문자열을 스키마에
  굳혀 버리면 ③(제목 변경 추종)과 모순 — **추종형은 라벨 문자열을 저장하지 않는다.**
- 선택 텍스트 승계안 ②-(a)(선택 텍스트 → 칩 라벨)는 "사용자 지정 라벨 칩"으로 표현 가능해야 한다
  (= 별칭 문법으로 왕복 가능). 앵커 칩 `[[#절 제목]]`·임베드 `![[DOC-0007]]`(별칭 문법 없음)도 각각 왕복.
- 피커·클릭 동작 등 UX 자체는 **M33에서 확정** — 여기서는 "스키마가 어느 결정을 택해도 막지 않는가"만
  판정하고 결론을 이 문서 완료 기록 + 계획서 §5.4 ④에 한 줄로 기록한다.

### D. 손실·미지원 처리

- **M32 팔레트 범위에서 프로젝션 손실 = 0이 계약이다**(강등 발동 0). 손실이 불가피한 문법이 발견되면
  게이트 규칙(말미)에 따라 처리 — 임의로 강등 규칙을 만들어 통과시키지 않는다.
- 팔레트 밖 mdast 노드(원시 html 노드 등)는 **sourceFallback 블록**(원문 슬라이스 보존, 투영 = 원문 그대로)
  으로 감싼다 — 왕복 자명 통과 + M34 지연 마이그레이션의 안전망. fallback 발생은 스크립트가 집계·보고한다.

### E. 이미지 크기 방언 확장 표기 확정 (계획서 §5.4 130행 "표기는 M32에서 확정" 이행)

- 표기: `![캡션](/images/...)` **직후 부속 표기 `{w=<px>}`** (예: `![캡션](/images/x.png){w=400}`.
  `h=`는 예약만 — 비율 유지 원칙이라 1차 미사용). 변환기가 image 노드 + 후행 텍스트의 `{...}`를 병합
  해석/직렬화한다 — **remark 플러그인 추가 없음**(파서 1개 원칙 무접촉).
- 리더(`MarkdownView`/`remarkStudy`) 반영은 **M33~M34로 이월**(D9 — 기존 렌더러 무수정). 그때까지
  이 표기는 실데이터에 등장하지 않으므로(문서 저장 경로 미연결) 평문 노출 문제도 없다.
- 확정 표기는 계획서 §5.4 해당 행에 반영한다(체크리스트 5-1).
