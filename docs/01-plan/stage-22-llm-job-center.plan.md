## 목표

끝났을 때, 어느 화면에 있든 좌하단 버튼(모바일은 좌측 드로어)으로 **모든 LLM 작업의 진행·대기·최근 완료를 한 곳에서** 볼 수 있고, 대기 작업은 비용 0으로·실행 중 작업은 부분 과금을 알린 뒤 **취소**할 수 있으며, **일시정지는 "다음 작업부터 보류"라는 정직한 의미**로만 동작하고, 엔진 선택이 있는 작업 화면 어디서나 **그 엔진의 모델을 1회성으로 바로 고를 수** 있으며(미선택 = 설정값), 응용 모의고사 생성 중 화면을 떠났다 돌아와도 **진행 표시가 자동 복원**된다. DDL·Alembic·DB 쓰기·settings 키는 전부 0, 신규 엔드포인트는 4개뿐이고, 아무것도 누르지 않은 사용자의 기존 동작은 현행과 완전히 같다.

> 권장 순서: **1(잡 목록) → 2(취소·일시정지) → 3(model 파라미터) → 4(작업 센터 패널·진입점) → 5(EngineSelect 모델·복원 훅) → 6(테스트) → 7(문서)**. 1·2는 `convert_service` 잡 레코드 구조에 수렴 — 순차 권장. 3은 F47 헬퍼 확장이라 독립. 프론트 4·5는 계약(§4.24·§5.14)으로 병렬 착수 가능, 실기동 연결은 백엔드 완성 대기.

### 1. 백엔드 — 전역 잡 목록 (설계 §4.24 ⓐ·결정 ①)

- [x] `GET /api/llm/jobs` 신설(`routers/llm.py`) — `{queue: {paused, concurrency: 1}, items: [...]}`. items는 `_JOBS`에서 파생: `job_id`·`kind`·`status`·`label`·`engine`·`model`(유효 적용값 — §4.23 ⑤ 산출 + 이번 요청 오버라이드)·타임스탬프 3종·`progress`(running만 — §4.11 그대로)·`error_info`(error만)·`ref`(kind별 참조 id — §4.24 ⓓ 표 전수). 정렬 = running → queued(등록순) → 종료(최신순). **LLM 0·DB 0.**
- [x] **label 서버 합성**(kind별 — 파일명·회차 라벨·문서 doc_no/제목·범위 라벨·사례 수 수준): 프론트 포맷 분기 금지(§4.10 `notes` 관례). **정답·해설·LLM 산출 원문은 어떤 필드에도 미포함**(불변 규칙 1·§4.11 — 목록 응답 스키마 수준에서 부재).
- [x] 잡 레코드에 목록 파생에 부족한 필드(kind·label 재료·ref)가 없으면 `_new_job_base` 확장(값 추가만 — 기존 필드·상태 계약 불변).

### 2. 백엔드 — 취소·대기열 일시정지 (설계 §4.24 ②③·ⓑ)

- [x] `POST /api/llm/jobs/{job_id}/cancel` — 상태 전이 전수: `queued → cancelled`(큐 제거·비용 0) · `running → cancelled`(중단) · 그 외(done·error·cancelled) = **409 CONFLICT**("이미 완료된 작업입니다 — 결과가 보존돼 있습니다") · 미존재·TTL 만료 = 404. 응답 `{status:'cancelled', usage?}`(마지막 진행 usage — 부분 과금 정직 표기).
- [x] **running 중단 구현**: CLI 엔진 = 서브프로세스 **트리** 종료(**Windows 실측 과제** — terminate가 자식(claude/codex 프로세스)까지 죽이는지 확인, 실패 감지 시 잡은 cancelled 확정 + 서버 로그 경고·응답에 내부 상태 미노출 — R24) · API 엔진 = 스트림 중단(연결 종료). 부분 LLM 산출물 폐기(preview 미생성) · 이미 저장된 `sources/` 원본 유지(불변 규칙 4).
- [x] **취소-완료 레이스 = 완료 승리**: 잡 레코드 종료 상태 갱신을 직렬화(단일 워커·잠금 — 구현 재량)해 먼저 도달한 상태가 확정 — 완료가 먼저면 409 + 결과 보존(**취소가 완료 결과를 지우는 경로 0**), 취소가 먼저면 이후 도착 산출물 폐기.
- [x] 상태 값 `'cancelled'`를 전 kind 상태 응답(§4.10 convert/regenerate·§4.20 answer-key/explain·§4.21 applied·§4.22 improve)에 **순수 추가** — 기존 값·필드 불변, 각 상태 조회 코드의 값 확장 여부 전수 확인.
- [x] `POST /api/llm/queue/pause`·`POST /api/llm/queue/resume` — 인메모리 paused 플래그(멱등·재시작 시 해제). paused 중 **다음 잡 시작만 보류**(running 무영향 — 동시 1개라 이것으로 완결), 잡 등록(시작 API)은 허용(대기 적재). 워커의 다음 잡 픽업 지점 1곳에서 판정.

## DoD (완료 정의)

**자동 검증 가능 항목** (구현·검토에서 증명):

1. **전역 가시화**: 전 8 kind 잡이 `GET /api/llm/jobs`에 나타나고(진행·대기·TTL 내 종료), label·상태 문구는 서버 완성 값 그대로다 — 목록 응답에 정답·해설·LLM 산출 원문 필드가 스키마 수준으로 부재.
2. **취소의 정직한 계약**: queued 취소 = LLM 0·비용 0 제거, running 취소 = 중단 + `'cancelled'` 종료 상태 + 부분 usage 동봉, 취소-완료 레이스 = 완료 승리·409(완료 결과를 지우는 경로 0).
3. **일시정지 = 대기열 수준만**: pause 중에도 running 잡을 멈추는 코드 경로가 0이고(다음 잡 픽업 지점 1곳만 판정), **LLM 호출 중간 재개 경로 자체가 없다**. paused는 인메모리(재시작 시 해제).
4. **model 파라미터 계약**: 8곳(9개 진입점) 전수 공통 헬퍼 경유 — auto+model·소목록 밖 = 422, 유효값 = 그 잡 1회만 적용(settings 무변경), 미지정 = 현행과 바이트 수준 동일, 폴백 시 다음 엔진 설정값 재산출.
5. **재진입 복원**: 응용 모의고사 생성 중 이탈→재진입 시 진행 패널이 자동 복원되고(원 결함 해소), 적용 화면 6곳 전수가 공용 훅 1개를 공유한다(화면별 localStorage 신설 0 — ImportQueue 기존 복원 불변).
6. **DDL 0건·Alembic 0건·DB 쓰기 0·settings 키 0·신규 엔드포인트 4개**(§4.24 재확인 — 어긋나면 착수 중단 후 보고). 저장은 인메모리(잡 레코드 값 확장·paused 플래그)뿐.

**사용자 이행 항목** (실 LLM 비용 — 자동 실행하지 않음):

7. **취소·복원 실측**: 실 잡 running 취소 1회(프로세스 트리 종료·부분 과금 usage — R24 기록) + 응용 모의고사 재진입 복원 1회 — 결과를 완료 기록에 기입.

## 이 단계에서 하지 않는 것

- **LLM 호출 중간 일시정지·재개 없음** — 스트리밍 1회 실행이라 중간 상태 재개가 원리상 없고, "재개" = 재호출 = 과금 중복(§4.24 ③ 기각 확정 — 재제안 시 근거 필요). 일시정지는 대기열 수준(다음 잡 보류)뿐.
- **잡 이력 DB 영속화 없음** — 인메모리·TTL 1시간 유지(서버 재시작 시 목록 소실 수용 — 변환 결과는 F40-① 디스크 보존이 방어). 이력 보존 실수요가 확인되면 계획서 먼저(R18 판단 관례).
- **신규 엔진 추가 없음** — 레지스트리 3종 그대로(F47 관례 — 엔진 추가는 별도 계획 등재 먼저).
- **동시 실행 확대 없음** — convert 잡 큐 동시 1개 불변(§4.10) — 취소·일시정지는 그 위에 얹는 제어일 뿐.
- **작업 센터 내 잡 재시작 버튼 없음** — 재시작 = 원 시작 API의 새 잡(시작 컨텍스트는 각 화면에 있다 — [화면으로 이동]으로 유도).
- **모델별 비용 추정 세분화 없음** — estimate(`assumed` 대략치)·사용량 안내 관례 불변(F47 관례 유지).
- **pause 상태 영속화 없음** — settings 저장 안 함(재시작 시 해제 — 정직 명시, YAGNI).
- **하단 탭바 변경 없음** — 모바일 탭 5개 유지(F39 "탭 추가 금지" 관례 — 진입은 좌측 드로어).
- **F44 답지·F45 생성 잡의 실패 사례 수집 확장 없음** — F46 범위 결정 그대로(반입 경로 우선 — 확장은 계획서 먼저).
