## 목표

끝났을 때, 해설 없는 기출 문항들이 — 답지 파일 하나를 올려 **매칭 미리보기에서 골라 승인하는 것**으로 일괄 채워지고, 답지가 없는 문항은 문서 상세에서 **LLM 풀이를 생성해 초안을 보고 승인**하는 것으로 채워진다. LLM 생성분은 해설 서두 마커로 **원본 유래와 항상 구분**되고, 승인(apply) 없이 DB가 병합되는 경로 · 기존 정답/해설이 덮어써지는 경로 · 퀴즈 응답 계약이 변하는 경로가 전부 0이다.

## DoD (완료 정의)

1. 해설/정답 없는 기출 문항이 **답지 파일 1건 반입 → 매칭 미리보기 → 선별 승인**으로 채워진다(라이브 완주 — 실답지 1건).
2. 답지가 없는 문항이 **LLM 풀이 생성 → 초안 확인 → 승인**으로 채워지고, 반입 후 해설 서두 마커로 **원본 유래와 항상 구분**된다.
3. **미승인 생성분이 조용히 병합되는 경로 0** — documents 병합 쓰기는 apply 2개 엔드포인트뿐(잡 완료·업로드·미리보기 조회는 DB 무변경 — 코드 검토 + 테스트로 증명).
4. 매칭 실패·모호 문항은 "매칭 안 됨"으로 표시되고 병합 대상에서 제외된다(**오병합 0** — 결정론 매칭 테스트).
5. **기존 정답·해설을 덮어쓰는 경로 0**(빈 필드만 병합 — conflict는 표시·skip).
6. quiz/session·exam 응시 응답 계약 불변(정답·해설 미포함 그대로 — 회귀 스모크) + 퀴즈 진행·시험 응시 화면에 explain 진입점 0.
7. 실행 전 사용량 안내 없이 LLM이 호출되는 경로 0(답지 = estimate 확인 스텝, 풀이 = 확인 다이얼로그).
8. **DDL 변경 0건·Alembic 0건**(§4.20 재확인 — 어긋나면 착수 중단 후 보고). 신규 엔드포인트는 7개뿐(answer-key 4 + explain 3).

## 이 단계에서 하지 않는 것

- **F45 응용 문항 생성** — 별개 기능(M19). 이 단계는 기존 문항의 빈 필드 보완만.
- **자동 일괄 풀이 생성**(범위 전체를 큐에 돌리기) — 풀이 생성은 문항 단위 수동 실행만(비용·R21 통제).
- **기존 정답·해설의 덮어쓰기·교정** — F30 오류 신고·재생성과 수동 편집이 담당(이 경로는 빈 필드만).
- **반입 미리보기(§4.3) 단계 내 보완 흐름** — 결정 ①에서 기각(반입 후 경로로 충분 — 재제안 시 근거 필요).
- **답지 가공 결과의 디스크 보존**(`import/auto/` 류) — 인메모리 TTL만. 재가공 비용이 실사용에서 아프면 계획서(R18)에 먼저 확정.
- **`explanation_source`·생성 이력의 DB 저장** — 응답 전용(§4.17 관례). 이력 필요가 실측되면 계획서 §6.2 갱신 + Alembic 세트로 먼저.
- **이미지 답지 OCR 등 추출 강화** — 엔진의 기존 능력 그대로(§4.18 매트릭스), 추출 불가는 `match_unavailable`로 정직하게 표시.
- **source_detail의 회차 문자열 파싱** — 자유 텍스트 신뢰 불가. 회차 구분은 범위 선택이 담당.

## 리스크

- **R21(계획서 §15)**: LLM 생성 해설의 오개념 — 기본 제외·수동 승인·마커 상시 표기·F30 사후 교정 + **이 단계에서 표본 검증**(체크리스트 5절).
- **오병합**: 번호 기반 매칭이 잘못된 문항에 병합될 위험 — 서버 결정론 매칭(LLM 판단 배제) + 모호·부재의 명시적 제외 + 빈 필드만 병합(틀려도 기존 데이터 무손상)이 3중 방어. 통합 답지(여러 회차)는 번호 충돌로 unmatched 다발 — 화면 안내로 회차 단위 범위를 유도.
- **답지 자체의 오류**(오타·정답 정정 전 판) — 기계로 못 잡는다. 최종 방어선은 R7 사람 검토(미리보기)와 F30 사후 신고 — 기존 관례와 동일.
