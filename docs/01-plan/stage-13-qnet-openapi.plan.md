# Stage 13 — 큐넷 공식 오픈API · 사설 어댑터 제거 (M13: F35 3단계 실가동 + comcbt·cbtbank 제거)

> 상위: `study-app.plan.md` **v0.16** §14(M13), F35 2단계 "제거 이력"·3단계 명세 · 설계: `../02-design/study-app.design.md` **v1.13** **§4.13(S13 갱신 — 단일 어댑터)** + §5.9(실패 렌더·프론트 변경 최소 원칙)·§5.11(데이터 그룹 서비스키 카드)
> 선행: Stage 12 완료(M12 — fetch 병합·우선순위(qnet=1)·FetchedFile/FetchedExam 경로·진행 패널·`exam_key?` 전부 가동, **qnet만 목록 스텁(`available:false`)** — stage-10 "qnet JS 포털 역설계" 제외, stage-12 "하지 않는 것"의 별건 후속이 이 단계)
> 포함 ①: **F35 3단계** — 공공데이터포털 공식 오픈API **"국가자격 공개문제 조회 서비스"**(`apis.data.go.kr/B490007/openQst`)로 큐넷 목록·상세·첨부 반입을 채운다. **역설계·스크랩이 아닌 공식 계약** — 유예 결정(R14 실측 사례)의 번복이 아니라 해소.
> 포함 ②: **사설 사이트 어댑터 전면 제거**(comcbt·cbtbank) — 앱이 **GitHub 공개 저장소 + 테스터 배포**로 전환(2026-07-27)되면서 "개인 PC 단독 사용 = 사적 이용" 전제가 무너졌다. 사설 사이트 DOM을 겨냥한 수집 코드를 공개 배포하지 않는다(근거·트레이드오프·기각 대안 = 계획서 §14 F35-2 "제거 이력"이 단일 출처).
> **한 단계에서 신규 구현 + 제거를 함께 하는 이유**: 다중 어댑터 전제(우선순위 병합·날짜 자연 키·`also_on`/`refs` 재시도·level_hint 오병합 방지)가 제거로 소멸하므로, qnet을 그 위에 얹지 말고 **단순한 단일 어댑터 형태로 새로 짜는 편이 총비용이 낮다.**
> **수용한 트레이드오프(사용자 확정)**: 기사급 **필기 CBT 기출의 자동 수집 경로가 사라진다**(큐넷 공개문제에는 필기 기출이 없음 — 공단 비공개). 필기 기출은 이후 **F35-1 URL 반입 / 파일 반입(수동)** 으로만 처리한다. 학습 루프·이미 반입된 문서는 영향 없다.
> **스키마(§6.2 DDL) 변경 없음 — Alembic 마이그레이션 0건.** 근거는 계획서 §14 F35-3 명세: 서비스키 = 루트 `secrets.json`(F34 전례 — DB/settings 금지), 목록 = 기존 메모리 캐시(24h), 출처 = `sources.note`(artlSeq·API URL), 회차·경로·imported = 기존 categories·source_detail 파생. **어댑터 제거도 DDL·마이그레이션 0건** — 어댑터 id는 스키마가 아니라 `sources.note` 자유 텍스트에만 등장한다(아래 "데이터 영향 검토" 절).
> 불변 규칙 재확인: **서비스키 write-only**(응답·로그에 원문 금지 — 요청 URL 로깅 시 serviceKey 마스킹, F34 전례) · **`fileUrl` JWT 유효 1시간(에러 941) → 상세 조회와 첨부 다운로드는 같은 잡에서 즉시 연속 수행**(목록·캐시에 fileUrl 저장 금지) · `sources/` 원본 불변 · 개인 학습 전용·재배포 금지 고지 · 실행 전 예상 LLM 사용량 안내 · 도메인 2초 스로틀·50MB 상한·SSRF 검증 기존 장치 유지(오픈API 호출도 동일 적용 — 30 TPS 대비 과잉 여유지만 일관성).

## 목표

공공데이터포털 서비스키를 설정에서 한 번 등록하면, 자격증 검색→회차 목록에 **큐넷(공단 정본) 공개문제가 나타나고**, 반입 실행 시 **첨부 PDF가 FetchedFile 경로로 convert→미리보기까지 완결**된다. HWP만 있는 공개문제도 원본은 확보되고 다음 행동이 안내된다(조용한 스킵 없음).
동시에 **사설 어댑터(comcbt·cbtbank)를 걷어내고 병합 로직을 단일 어댑터 형태로 단순화**한다. 끝났을 때 코드베이스에 사설 사이트 참조는 0건이고, **과거 그 경로로 반입된 문서·원본·이미지는 하나도 사라지지 않는다.**

## 작업 체크리스트

> 권장 순서: **1(제거·단순화) → 4(데이터 영향 점검) → 2·3(qnet 구현) → 5(프론트) → 6(문서·매뉴얼)**. 제거를 먼저 하면 단순해진 병합 위에 qnet을 얹게 되어 중간 상태 복잡도가 낮다. 제거만 끝난 시점에도 앱은 정상 동작해야 한다(qnet은 키 미등록 스텁 = 기존 동작).

### 4. 데이터·마이그레이션 영향 검토 (제거에 따른 필수 점검)

- [ ] **기존 반입 문서 = 전량 보존.** comcbt·cbtbank 경로로 반입된 문서·분류·`sources` 레코드·`sources/` 원본 파일·`sources/images/` 이미지에 **손대지 않는다**(불변 규칙 3 소프트 삭제·규칙 4 원본 불변). 정리 스크립트·일괄 삭제·`is_active` 변경 **금지**
- [ ] **`sources.note`의 출처 문자열 보존**: `"comcbt · {url}"`·`"cbtbank · {url}"` 형태 기록은 **역사적 사실**이므로 마스킹·치환하지 않는다. 이 값을 파싱해 분기하는 코드가 있는지 확인하고(있다면 어댑터 존재 여부에 의존하지 않도록), 없으면 그대로 둔다
- [ ] **어댑터 id를 참조하는 상태·캐시 점검**: 목록 캐시(`registry._CACHE`)와 robots 캐시는 **프로세스 메모리 전용**(재시작 시 소멸) — 정리 대상 파일 없음을 확인. `settings` 테이블·`secrets.json`·백업 스냅샷에 어댑터 id 키가 없는지 확인하고, 발견되면 **읽기 시 무시**(삭제 마이그레이션 없이 무해 잔존) 방침 적용
- [ ] **잡 이력(convert jobs) 영향 없음 확인**: 과거 `kind='fetch'` 잡 레코드가 남아 있어도 조회·표시가 깨지지 않을 것(어댑터 id는 표시 문자열일 뿐 — 미등록 id도 그대로 렌더). 필요하면 이름 폴백을 "(지원 종료된 출처)"로 표시
- [ ] **재반입 불가 안내**: 과거 사설 출처로 반입된 회차는 이후 F30 재생성·재반입 시 자동 수집이 불가능하다 — 관련 안내 문구가 필요한지 확인(재생성은 저장된 문서 기준이라 통상 무영향, 실측으로 판단)
- [ ] **DDL diff 0 · Alembic 리비전 0건** 재확인(어댑터 제거는 스키마와 무관)

### 5. 프론트 — 설정·반입 화면 (설계 §5.9·§5.11)
- [ ] 설정 ⑤ **데이터** 그룹에 "큐넷 오픈API" 카드(F34 API 키 카드 UX 미러) — 키 입력·즉석 검증(실패 사유 표시)·등록 후 suffix 마스킹 표시·삭제 버튼 + 발급 방법(공공데이터포털 활용신청) 안내 소표기. **7번째 그룹 아님 — F38 6그룹 수 불변**, 그룹 내 카드 추가만
- [ ] 반입 [사이트에서 가져오기] ①~④ 스텝: **렌더 로직 변경 0이 정상** — qnet `available` 전환·배지·목록은 응답 메타 그대로 렌더(어댑터별 분기 코드가 있으면 제거 — 어댑터 격리 검증 겸용). 허용되는 변경은 1절의 **타입 유니온 축소·이름 폴백 맵 정리**뿐
- [ ] 실패 렌더 확장: `unsupported_format` — "원본은 sources/에 저장됨" 안내 + [파일 반입으로 이어가기] 버튼(기존 error_info 렌더에 kind 1종 추가). `parse_failed` 대안 버튼은 **[URL로 반입]·[파일로 반입]** 로 정리(다른 어댑터 재시도 경로는 `also_on`이 항상 비어 사문화)
- [ ] 어댑터 notice에 **커버리지 한계 문구** 노출 확인: "큐넷 공개문제는 실기 위주 — 필기 기출은 URL·파일 반입으로 추가하세요"(기대치 어긋남 방지, 계획서 §14 F35-3)

## 완료 기준 (DoD)

1. **키 미등록**: 어댑터 목록에 qnet `available:false` + 등록 안내 notice — 기존 스텁과 동일 동작(회귀 없음), 반입 화면에 오류·빈 화면 없음
2. **키 등록**: 잘못된 키는 즉석 검증 실패 사유가 표시되고 저장되지 않는다. 올바른 키는 suffix만 표시되고 `secrets.json`에만 존재(DB·settings·백업 스냅샷에 0건) — 서버 로그 전수에서 원문 키 0건
3. 자격증 검색(예: "품질경영기사")에 큐넷 결과가 나오고, 회차 목록이 최신순으로 렌더된다 — 응답의 `also_on`은 전부 빈 배열, `refs`는 `{qnet: …}` 단일 항목(단일 어댑터 계약 확인)
4. 큐넷 공개문제 반입: 상세 조회→첨부 다운로드→convert→미리보기 완결(FetchedFile 경로). 잡 로그에서 상세 조회와 다운로드가 **같은 잡 내 연속 수행**(1시간 토큰 내)임이 확인되고, 분류 경로가 "자격증명/실기/…"로 생성된다
5. HWP만 있는 공개문제: 원본이 sources/에 저장되고 `unsupported_format` 안내 + [파일 반입으로 이어가기]가 렌더된다 — 조용한 스킵·무한 대기 없음
6. 쿼터·키 오류(22·30/31) 상황에서 사람 말 안내 확인 — 원문 XML/JSON 미노출
7. 같은 검색·회차 목록 반복 조회 시 24h 캐시로 오픈API 재호출이 없다(쿼터 소모 로그로 확인). 요청 간격 2초·병렬 없음 유지
8. 기존 경로 회귀 없음: **URL 반입(F35-1)·파일 업로드 반입·convert 파이프라인**, `exam_key?` 전달·폴더명 파생, 키 삭제 후 스텁 복귀, `GET /images/{filename}` 과거 수집 이미지 열람 — 단위 테스트 + 스모크
9. §6.2 DDL diff 0 · Alembic 마이그레이션 0건 · `sources/` 원본 파일 변경 0건 · `secrets.json` 외 위치에 키 저장 0건
10. **제거 검증**: 코드베이스(백엔드·프론트 **소스·주석·테스트·설정**)에서 `cbtbank`·`comcbt` **참조 0건**(대소문자 무시 전수 검색). 허용 예외는 **문서와 사용자 데이터뿐** — 계획서(§14 F35-2 제거 이력·R14·로드맵 M10/M12)·설계(§4.13 폐지 규칙·헤더 이력)·과거 stage 문서·이 문서, 그리고 **DB `sources.note`의 과거 출처 문자열**(보존 대상). `frontend/dist` 등 빌드 산출물은 재빌드 후 0건. **사용자 매뉴얼에는 남지 않는다**(현재 기능 설명 문서 — 6절에서 재작성)
11. **데이터 보존 검증**: 제거 전후로 문서 수·`sources` 레코드 수·`sources/` 파일 수·`sources/images/` 파일 수가 **동일**하고, 과거 사설 출처로 반입된 문서가 정상 열람·풀이·복습된다(오답노트·SM-2 영향 없음). 삭제·마스킹 0건

## 이 단계에서 하지 않는 것

**시험일정 조회 API 연동(`categories.exam_date` 자동 채움)** — 별건 유예(수동 D-Day 등록(S4)으로 충분한지 실수요 확인 후, 계획서 §14 F35-3에 v1.x+ 후보로 기록만),
**qualgbCd C/W 확장**(과정평가형·일학습병행 — T 국가기술자격만, 실수요 후), **HWP 서버측 변환**(LibreOffice 등 의존 추가 금지 — 원본 저장 + 파일 반입 폴백으로 충분),
**게시물 `contents` HTML 본문 구조화**(첨부가 정본 — 본문은 사용하지 않음), **운영계정 승급·쿼터 관리 UI**(개발계정 일 1,000건이면 개인 사용에 여유 — 에러 22 사람 말 안내로 충분),
**필기 CBT 기출 확보 시도**(공단 비공개 — 이 API로도 미제공. 사설 어댑터 제거로 자동 경로가 없어졌고, 이는 사용자가 수용한 트레이드오프 — 필기 기출은 URL·파일 반입으로), **Q-Net 웹 포털 스크랩·역설계**(오픈API가 대체 — 스텁 유예 건 종결),
**제거된 어댑터의 대체재 물색·다른 사설 사이트 어댑터 신설**(정책상 금지 — 계획서 §14 F35-2·설계 §4.13 강제 조항 0), **과거 반입 데이터 정리·출처 문자열 마스킹·재수집**(보존이 원칙),
**FetchedExam 인터페이스·이미지 저장 분기 삭제**(사용 어댑터가 없어도 계약으로 유지 — 되살리기 비용만 큼), 다회차 배치 반입(한 번에 1회차 유지).
