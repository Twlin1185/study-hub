### A. 참조 칩 UX 재설계 확정 (§5.4 요구 ①~④)

**① 대상 선택 = 피커 필수(하드코딩·무피커 삽입 금지)**

- 진입: 툴바 [참조] 버튼 + 슬래시 메뉴 `/참조`(문서 링크 칩) · `/임베드`(문서 임베드 블록) · `/앵커`(문서 안 앵커).
- 피커 = 인라인 팝오버 1개(3종 공용): 검색 입력 → **`GET /api/search?q=`**(디바운스 250ms) 결과 목록 +
  **최근 열람 문서**(로컬 최근 목록 — 신규 API 0). 키보드 ↑↓·Enter·Esc 지원.
- **앵커 칩(`[[#절 제목]]`)은 자유 입력을 받지 않는다** — **현재 노트의 heading 블록 목록**에서 고른다
  (ⓕ target 도메인 문제의 원천 차단). 도메인 밖 제목은 목록에 **비활성 + 사유**로 노출한다(숨기지 않는다 —
  왜 못 쓰는지 보여야 사용자가 제목을 고칠 수 있다).
- 문서 임베드는 **블록**(docEmbed)으로 삽입한다(문단 안 임베드는 기존 데이터 수용 전용).

**② 선택 텍스트 보존 = (a) 승계 채택, 실패 시 (b) 폴백 — 조용한 삭제 0**

- 선택 없음 → 커서 위치에 삽입, **추종형 칩**(`label` 미저장).
- 선택 있음 → 선택 텍스트를 **라벨 후보**로 삼아 규약 B(`isSafeRefText`) 검사:
  - **통과** → 지정 라벨형 칩(`[[DOC-0012|선택텍스트]]`)으로 치환 — 글자가 사라지지 않고 라벨로 남는다
    (2026-08-15 사용자 피드백 "글자가 사라지면서 참조 문서 7이 되는" 현상의 해소 지점).
  - **미통과** → **삽입을 강행하지 않는다**. 선택을 유지한 채 피커에 사유 + 라벨 입력란을 띄우고,
    [라벨 없이 삽입](= 선택 해제 후 커서 삽입 = (b))·[취소]를 제공한다.
- **어떤 경로에서도 사용자의 텍스트를 조용히 지우거나 바꾸지 않는다.**

**③ 라벨 규칙·칩 클릭 동작**

- 기본 = **추종형**(라벨 문자열을 저장하지 않고 대상 문서 제목을 표시 — 제목이 바뀌면 자동 추종. M32 규약 C).
  제목 조회는 `POST /api/documents/resolve-embeds`(§4.19) **배치 재사용**(편집 세션 메모리 캐시 — 신규 API 0).
- **사용자 지정 라벨 허용** — 피커의 라벨 입력란, 또는 칩 팝오버 [라벨 편집]. [제목 추종으로 되돌리기]로 언제든
  추종형 복귀(= `label` 삭제). 지정 라벨형은 대상 제목이 바뀌어도 라벨을 유지한다(경고 표시 없음 — YAGNI).
- 미해결 대상(`found:false`)·삭제된 문서 = **자리표시자 칩**(중립 토큰 색 + 사유) — 기존 F43 자리표시자 문구 계승.
- **칩 클릭 동작 = 표면에 따라 다르다(일관 규칙)**:
  - **편집 표면(노트 편집)** = 팝오버 열기(대상 제목 · [문서 열기] · [라벨 편집] · [대상 변경] · [삭제]).
    편집 중 클릭이 곧바로 라우팅되면 편집 흐름이 끊긴다 — 원자 인라인 콘텐츠의 표준 동작.

    리더는 1바이트도 수정하지 않으므로 자연히 충족된다(D9).

**④ 문법 왕복 = M32 결론 그대로** — 추종형 `[[DOC-0012]]` · 지정 라벨형 `[[DOC-0012|라벨]]` ·

### B. 참조 칩 라벨·target 문자 도메인 (M32 전달 사항 ⓒ·ⓕ) — **거절 정책 + 단일 판정 함수**

- **판정 함수 1개**: `frontend/src/editor2/schema/refDomain.ts`의 **`isSafeRefText(s): boolean`** 을 신설하고
  **라벨과 target 양쪽에 같이 적용**한다(둘의 금지 집합이 실질적으로 같다 — 함수를 미리 쪼개지 않는다: YAGNI).
  - 금지: `]` · `|` · 개행(구조적 불가) · **인라인 문법을 여는 문자** `*` `` ` `` `~` `$` `[` `:` `_`(강조 위치) ·
    선행·후행 공백 · 빈 문자열. 내부 공백·탭은 **허용**(파서가 보존한다 — M32 실측).
  - **M32 검증 스크립트(`s32-roundtrip-blocks.mjs` 계열 ⑥)가 이 함수를 import하도록 전환**한다 —
    도메인의 단일 출처를 코드에 두고 스크립트와 UI가 갈라지는 것을 막는다(스크립트 수정은 허용 접촉점).
- **정책 = 거절(치환 금지)** — 도메인 밖 문자를 앱이 몰래 제거·치환하는 것은 M32의 "조용한 본문 변형 0" 계약과
  충돌한다. 위반 시 입력 시점에 사유를 보여주고 사용자가 고치게 한다.
  - **유일한 자동 정리 = 가장자리 공백 트림**(파서가 어차피 버리는 자리 = 표기 정규화이지 값 변경이 아니다.
    M32 규약 A의 예외 ⓓ와 같은 논리).
- **target 경로별 적용**: doc/embed target = 피커가 고른 문서의 `doc_no`(정규식 `DOC-\d{4,}`) — 자유 입력 경로
  자체가 없다. anchor target = 현재 노트 heading에서 선택 + `isSafeRefText` 필터.
- **역방향(반입 데이터)**: 도메인 밖 target·label을 가진 기존 데이터는 M32 변환기가 이미 **평문 강등**으로
  처리한다(텍스트 보존 = 손실 0). 어댑터는 **새 규칙을 만들지 않고** 그 결과를 그대로 표시한다.

### C. 마이크로 마크 중첩 차단 (M32 전달 사항 ⓐ) — **상호 배타 + 대체**

- `++`(밑줄) · `==`(형광) · `||`(스포일러) 3종을 **"마이크로 그룹"** 으로 묶어 **한 구간에 최대 1개**만 허용한다.
  이미 다른 마이크로 마크가 걸린 구간에 새 마이크로 마크를 적용하면 **대체(replace)** 한다(라디오 동작).
  - 근거: 적용을 무시(차단)하면 사용자는 버튼이 고장 난 것으로 읽는다. 대체는 결과가 즉시 눈에 보이고 되돌리기 쉽다.
  - 안내 토스트는 만들지 않는다 — 툴바 버튼의 active 상태 표시로 충분(과설계 금지).
- CommonMark 마크(bold·italic·strike)와의 조합은 **자유** — 변환기가 `MARK_ORDER`로 CommonMark를 바깥에 둔다.
- **강제 지점 3곳**: ① 툴바·단축키 커맨드를 감싸는 어댑터 1곳(`editor2/adapter/marks.ts`)
  ② 역방향 변환(BlockNote→앱 블록)의 **방어적 정규화**(2개 이상이면 `MARK_ORDER` 우선 1개만 남기고 **집계 보고**)
  ③ 붙여넣기 경로(HTML `u`+`mark` 중첩 유입) — 같은 규칙으로 1개로 접는다.

### D. inlineImage 어댑터 (M32 전달 사항 ⓑ) — **원자 인라인 커스텀 스펙**

- 채택: `createReactInlineContentSpec`(content:`"none"`, props = url·alt·title·width) — refChip과 같은 메커니즘
  (M31 스파이크에서 성립 확인).
- **블록 승격을 기각한 이유**: 문단 안 이미지를 블록으로 올리면 문단이 쪼개져 **왕복 무손실이 깨진다**.
  M32가 `inlineImage`를 스키마에 넣은 이유가 정확히 그 손실 방지였다(`blocks.ts` 주석 참조).
- **에디터에서 새로 삽입하는 이미지는 언제나 블록 이미지**(내장 `image`)다. 인라인 이미지는 **기존 데이터 수용
  전용**(보존·표시·삭제만 가능, 새로 만드는 UI 없음). 크기 조절 UI도 블록 이미지에만(내장 `previewWidth` ↔ `{w=}`).

### E. 블록 메타데이터 입력 도메인 (M32 전달 사항 ⓔ) — **UI가 도메인 밖을 받지 않는다**

- **콜아웃 variant = 고정 목록만**: `note` · `warn` · `tip` · `fold` · `hide`(자유 입력 금지 → directive 이름이
  `.`·`:`로 붕괴하는 경로 소멸). 목록 밖 variant를 가진 기존 데이터는 **보존만**(표시는 기본 스타일).
- **콜아웃 title(`[제목]`) = `isSafeRefText` 재사용 검증**(규약 B와 같은 함수 — 라벨류 통일). 위반 = 실시간 거절.
- **`{key=value}` 속성 자유 편집 UI를 만들지 않는다** — 기존 데이터의 `attrs`는 어댑터가 보존만 한다.
  따라서 M32가 경고한 **키·값 도메인 문제는 "입력 경로 없음"으로 해소**된다(수렴 = 값 변경이므로 회피가 정답).
- 코드 블록 info 문자열 = stage-33 규약 E 그대로(드롭다운만·자유 입력 없음).
- `:t` 색·크기 = **기존 화이트리스트 그대로**(팔레트 7색 ∪ `#rrggbb` ∪ size 3종 — `palette.ts` 단일 출처.
  편집기 v2가 새 색 규칙을 만들지 않는다 — 불변 규칙 5).

- **HTML 붙여넣기(`text/html` 있음)** = 기존 `frontend/src/utils/htmlPasteMarkdown.ts` 화이트리스트 계약(R30·S30 ④) **재사용**

### I. 코어 범위 제약 7종 (stage-33 어댑터 실측 — 2026-08-16 신설. 배정 정본 = `editor-v2.plan.md` §5.4 말미 표)

어댑터가 미지원으로 보고하는 사유 중 **방언이 아니라 순수 CommonMark/GFM**인 것이 7종 있다:
`listItem:spread`(느슨한 목록) · `listItem:groupBreak`(인접 목록 경계) · `table:align`(GFM 열 정렬) ·
`inline:hardBreak`(경성 줄바꿈) · `link:title` · `image:title`/`image:height` · `block:meta`.
**이 단계의 방언 팔레트에는 없던 항목이며, 소유자가 없어 stage-35(M34)에서 기존 문서가 통째로 폴백으로
떨어질 수 있다**는 것이 등재 사유다(검토 지적).

| 구분 | 항목 | 이 단계의 의무 |
|---|---|---|
| **흡수(이 단계 소유)** | `inline:hardBreak` · `link:title` · `image:title`/`image:height` · `block:meta` | **왕복 보존**한다. 경로 후보 = ⓐ **잔여 속성 사이드카**(BN이 못 담는 속성을 **블록 id 키**로 보관 → 역변환에서 복원) · ⓑ **원자 인라인 커스텀 스펙**(hardBreak — 규약 D inlineImage와 같은 메커니즘). **내장 블록 스펙 재정의는 1차 후보가 아니다**(내장 UI 재구현 비용). **전부 기존 데이터 수용 전용** — 새로 만드는 UI를 만들지 않는다 |
| **사용자 판정 대기(R34)** | `listItem:spread` · `listItem:groupBreak` · `table:align`(열 증감 시) | **흡수하지 않는다. 손실 수용으로 임의 확정하지도 않는다.** 이 단계는 **명시적 미지원 보고를 유지**(조용한 손실 0)하고, 필요하면 표본 수·영향 범위를 정리해 보고만 한다. `table:align`은 **열 수 불변 조건의 왕복 보존까지는 시도**(정렬 **편집 UI**는 M35 = stage-36 범위). 판정 시한 = **stage-35 착수 전** |

- **유입 경로 주의**: 노트는 신규 저장소라 BlockNote로 만든 문서에는 이 값이 생기지 않지만,
  **규약 G의 붙여넣기 경로**(HTML→방언 Markdown→`markdownToBlocks`)로는 `hardBreak`·`link:title`이
  **실제로 유입된다**. 흡수 4종의 우선순위가 여기서 나온다.
- 흡수를 시도했다가 불가로 판명되면 **임의 강등 금지** — 사유와 표본 수를 정리해 사용자 보고(게이트 표
  "왕복에서 조용한 손실 발견" 행 = R34 경로).

### 계획서 표현과 의도적으로 다르게 간 지점 (전부 근거 포함)

1. **`t` = BlockNote 스타일 1개**(propSchema `'string'` = `JSON.stringify(AttrPair[])`) — 지시서 G-1의
   "ink/bg/size 3개 스타일"과 다르다. 앱 스키마의 `t`는 `AttrPair[]`로 **화이트리스트 밖 값·미지 키·비-ASCII
   키·중복 키·순서까지** 보존하는데, 3개 화이트리스트 prop으로 쪼개면 코퍼스의 `:t 화이트리스트 밖`·
   `:t 속성 중복 키`·`:t 비-ASCII 속성 키`·`:t 속성 값 백슬래시` 표본이 **조용히 손실**된다(DoD 2 위반).
   렌더·툴바 상태는 `interpretTextStyle(pairs)`로 파생한다.
2. **`highlight` = boolean 스타일**(지시서 "값 보유: 색"과 다름) — 앱 스키마 `InlineStyles.highlight?: true`와
   1:1이며, 색은 `:t{bg=}`가 담는다(F52 문법이 그렇게 갈린다).
3. **콜아웃 `variant`에 propSchema `values` 화이트리스트를 걸지 않았다** — 걸면 `:::노트[…]` 같은 비-ASCII
   variant 기존 데이터가 스키마 적재에서 **거부·치환**된다. 고정 목록(note·warn·tip·fold·hide)은 **입력 UI
   제약**으로만 쓰고, 목록 밖 값은 보존 + 기본 스타일로 표시한다(규약 E의 의도 = **새 입력 경로 차단**이지
   기존 데이터 거부가 아니다).
4. **원자 인라인 4종에 `styles` prop 추가**(지시서에 없던 prop) — BlockNote가 커스텀 인라인 노드의 mark를
   **되읽기에서 버린다**는 실측 때문이다. 없으면 `참조 칩 서식 안`·`:t 안 참조` 표본이 실제 스키마 적재에서
   서식을 잃어 "방언 미지원 0"이 성립하지 않는다.
5. **`fromBlockNoteBlocks`의 사이드카 인자는 선택**이고, 집계 보고가 필요한 호출부용으로
   `fromBlockNoteResult(blocks, sidecar?) → { document, microMarkCollapses }`를 따로 뒀다(**기존 시그니처 파괴 0**).
6. **원자 서식 가드 = 버튼 비활성화**(대안이던 `styles` prop 직접 갱신 기각) — `styles`는 어댑터가 마크를
   실어 나르는 **전송로**라 툴바가 거기에 쓰면 마크 병합 규칙(`MARK_ORDER`·마이크로 상호 배타·`:t` 쌍 병합)이
   두 곳에 생기고 텍스트·원자 혼재 선택에서 active 판정까지 갈라진다. 비활성화는 **눈에 보이는 상태**이고
   저장분과 어긋나지 않는다. 가드 대상 = `refChip`·`inlineImage`·`inlineFallback`·`lineBreak`·**`math`**.
7. **"형광 끄기"가 `t.bg`도 함께 지운다** — F52에서 형광펜과 바탕색은 **같은 시각 채널의 두 표기**다

### 프로젝션 손실 목록 초안 (DoD 10 — **M36 입력**)

1. **인라인 수식에 걸린 서식** — `math` 스펙 propSchema가 비어 담을 자리 없음. `inline:mathStyles`로
   **보고 유지**(코퍼스 표본 0건). 툴바 입력은 원자 가드로 차단. 흡수하려면 **자체 수식 스펙으로 전환**해야 한다.
2. **원자 가드의 원리적 한계** — BlockNote **코어 버튼과 그 단축키(`Ctrl+B` 등)** 는 막지 않는다. 원자가 포함된
   선택에 코어 마크를 얹으면 그 원자의 마크가 저장·재로드에서 사라진다. 사라지는 것은 사용자의 **텍스트가
   아니라 원자에 얹은 표현 속성 하나**이고, 코어 키맵을 통째로 감싸려면 커맨드 레이어 확장이 필요해 **M35 범위**
   (`toolbar/atoms.ts` "알려진 한계"에 기록).
3. **같은 블록·같은 href·서로 다른 link title** → 마지막 값이 남는다(허용 · 주석 명시).
4. **`table:align`은 열 수가 바뀌면 버려진다**(의도 — 열 증감 시 정렬 배열의 대응이 성립하지 않는다).
5. **run 경계의 `\n`은 서식을 잃는다** — BlockNote가 `hardBreak` PM 노드를 앞 run에 `\n`으로 붙이며 그 노드의
   mark를 무시한다. 어댑터에서 "run 끝의 `\n` = 서식 없음, run 안쪽의 `\n` = run 서식 유지"로 양방향을 맞춰
   **실질 영향은 Markdown 투영 무변**.
6. **콜아웃 본문의 시각적 소속** — children이 BlockNote 중첩 그룹으로 렌더돼 콜아웃 상자 "**바깥 아래**"에
   붙는다. `notes.css`에서 좌측 보더+들여쓰기로 이어 붙였으나 **한 상자로 감싸는 마감은 M35**.
7. **수식이 든 문단을 통째로 선택하면 방언 서식 버튼 6종이 비활성**으로 보인다(원자 가드에 `math`를 넣은
   결과 — **의도한 비용**).
8. **`:t` 혼합 선택에 색·크기를 적용하면 다른 run의 미지 속성이 소멸한다**(검토 경미-2 — 2026-08-16 추가).
   `toolbar/textStyle.ts`의 `setTextStyleKey`는 `getActiveStyles()`(선택 **head 한 곳**)의 `:t` 쌍을 읽어
   **선택 전체에 덮어쓴다**. 그래서 `:t{x=1}`처럼 화이트리스트 밖 속성을 가진 run이 섞인 구간에 색을 적용하면
   그 run의 미지 속성이 조용히 사라진다 — `t`를 통짜 JSON으로 둔 이유("손실 0")와 어긋나는 유일한 지점이다.
   **정확히 고치려면 run 단위 병합 API가 필요**한데 BlockNote의 스타일 적용은 선택 전체 단위라, 어댑터가 아니라
   **툴바 커맨드 레이어의 확장(M35)** 이 있어야 한다. 실사용 노출도는 낮다(미지 속성은 반입 데이터에서만 온다).
9. **마이크로 마크 접힘이 사용자에게 고지되지 않는다**(검토 중요-1의 잔여분 — 2026-08-16 추가).
   저장 경로가 `fromBlockNoteBlocks`를 부르며 `fromBlockNoteResult().microMarkCollapses` 집계를 버리므로,
   역방향 방어적 정규화(규약 C 강제 지점 ②)가 마이크로 마크를 접어도 배너가 뜨지 않는다. **툴바 우회로
   (기본 밑줄 버튼)와 붙여넣기 경로는 이번에 닫았으므로**, 남은 유입 경로는 **편집기 밖에서 만들어진
   `content_blocks`에 마이크로 마크 2개 이상이 겹쳐 있는 경우**뿐이다(노트는 신규 저장소라 현재 표본 0).
   `documents`를 탑재하는 **stage-35에서 유입 경로가 열리므로** 그때 고지 결선을 함께 볼 것.

### DoD 12 이행 중 발견된 결함 (2026-08-16 — 사용자 실사용 보고)

사용자가 위 표의 **undo/redo** 항목을 실사용으로 확인하다 "**한글 입력 중 `Ctrl+Z`가 안 먹는다**"를 보고했다.
계획상 undo/redo는 **이 단계에서 동작해야 하는 항목**이므로(M35로 미룬 것은 "안정 undo **강화**"뿐 —

| 번호 | 결함 | 원인(실측) | 처리 |
|---|---|---|---|
| **U-1** | **한글 조합 중 `Ctrl+Z`/`Ctrl+Shift+Z`/`Ctrl+Y` 무반응.** 영문이거나 조합이 끝난 뒤(스페이스·문장부호·방향키·클릭)에는 정상이라 "가끔 안 먹는다"로 보인다 | `prosemirror-view`의 `editHandlers.keydown`이 맨 앞에서 `if (inOrNearComposition(view)) return;` 으로 빠진다. 그 함수는 `view.composing`이면 무조건 true → **조합 중에는 키맵 자체가 돌지 않는다**(BlockNote가 건 `Mod-z → editor.undo()` 포함). 윈도우 한글 IME는 다음 자모·스페이스·이동 전까지 현재 음절의 조합을 유지하므로 타이핑 직후의 `Ctrl+Z`는 사실상 항상 이 경로다.
