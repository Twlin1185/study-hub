## 2. 기능 실태 — 계획서 §4 서술의 실측 검증

## 5. 스파이크 실측 (워크트리 `frontend/src/editor2/poc/` · PoC 라우트 `/editor2-poc`)

### 5.1 방언 커스텀 스펙 3종 — 전부 성립
| 스펙 | API | 확인 동작 |
|---|---|---|
| 형광펜(F52 `==`) | `createReactStyleSpec` propSchema:"string" — **값(색 이름) 보유 스타일 성립** | 토큰(`--mark-*`) 결선 렌더 + `toggleStyles({highlight:'yellow'})` 적용 확인 |
| 스포일러(F52 `\|\|`) | `createReactStyleSpec` propSchema:"boolean" + **React 상태 갖는 렌더** | 가림 표시 + **클릭 공개 동작 확인**(리더 뷰 동작의 에디터 내 재현 가능) |
| 참조 칩(F43) | `createReactInlineContentSpec` content:"none"(원자) | 비편집 칩 렌더·삽입·한 단위 삭제 확인 — 참조 3종·문서 임베드 칩의 일반형 |
- 함의: F52 인라인 방언·F43 칩 계열이 **전부 이 3개 API 패턴 안**이다. 콜아웃·문제 블록은
  `createReactBlockSpec`(같은 계열)로, 이식 공수는 "스펙 정의" 수준으로 수렴.

### 5.2 번들 (R32-c — 빌드 실측, min / gzip)
| 대상 | 도입 전 | 도입 후 |
|---|---|---|
| 초기 청크 index.js | 1,577.3KB | **1,577.7KB (+0.4KB / gzip +≈0.1KB)** — 지연 로드로 초기 영향 사실상 0 |
| PoC 지연 청크 | — | 924KB / **gzip 271KB** + CSS 230KB / gzip 36KB |
| 온디맨드(내부 동적 로드) | — | 419KB / gzip 81KB + 75KB / gzip 27KB |

  PWA 캐시 대상 증가는 R37대로 기록. **수용 판정.**

### 5.3 테마 토큰 결선 — 성립
`--bn-colors-*` CSS 변수 ↔ `tokens.css` 변수 매핑 **CSS 96줄**로 라이트/다크 완전 결선(불변 규칙 5 준수,
하드코딩 0 — invariant-scan PASS). 슬래시 메뉴·툴바·에디터 표면 전부 앱 토큰을 따름을 두 테마에서 스크린샷 확인.

### 5.4 장문 편집 반응성 (혼합 블록 하네스: 헤딩·중첩 목록·서식 문단·한글 장문)
| 블록 수 | 문서 교체→페인트 | 단타 키다운→페인트(60타 평균/최대) |
|---|---|---|
| 1,000 | 163ms | — |
| 3,000 | 733ms | **15ms / 16ms** |
| 6,000 | 2,925ms* | **28.6ms / 30ms** |
- *전체 문서 일괄 교체(최악 경로) 기준 — 열람 전환(M34 지연 변환)의 상한 근사. 탭 상태에 따라 최대 6.4초까지
  관측(가상화 부재의 대가). **단타 지연은 6k 블록에서도 2프레임 이내 = 합격.**
  60자/초 수준 폭주 연속 입력 시 프레임 밀림(평균 418ms)이 있으나 인간 타이핑 속도에선 비발생 아티팩트.
- 실사용 분포(§5.5: 실문서 평균 수백 자 = 수십 블록 이하)에서는 로드·입력 모두 즉답 영역.

### 5.5 저장 크기 — D1 조건 전반부 (실데이터 실측)
- `study.db` 실문서 **436텍스트(content 224 + explanation 212) 전건** 헤드리스 변환(server-util):
  **실패 0** · Markdown 96.6KB → 블록 JSON 322.7KB · 배율 **중앙값 ×2.54 · 전체 ×3.34 · P90 ×4.85**
  (최대 ×21은 수십 자 초단문의 고정 오버헤드 — 절대량 무의미).
- 외삽: 문서 5,000건 시 블록 JSON 총 **+3.7MB** — SQLite(WAL)에 무시 가능. 6k 블록 극단 문서 1건 = 2.3MB.
- 목록/검색/FTS/백업은 **Markdown 프로젝션(`content` 존치) 소비**라 대량 문서 표시 경로에 블록 JSON이
  아예 등장하지 않는다(설계 §5.2). → **"수많은 문서 관리·표시 문제없음" 지지.**

### 5.6 한글 IME — 자동화 한계와 대체 검증
(1차 피드백 반영 후 재확인 필요 — §5.7. 특히 ②는 ko 사전 적용 후 /이미지·/image 둘 다 매칭되어야 정상.)

### 5.7 사용자 실기기 1차 피드백(2026-08-15)과 반영 — 전건 해소
| 보고 | 원인 | 반영 |
|---|---|---|
| `/image`는 되고 `/이미지`는 안 됨 | IME 버그가 아니라 **사전(locale) 문제** — 기본 영어 사전이라 메뉴 항목명이 영어여서 한글 질의가 매칭될 수 없음 | `@blocknote/core/locales`의 **`ko` 사전 주입**(`useCreateBlockNote({dictionary: ko})`) → "/이미지" 필터 동작 브라우저 확인. 부수 이득: 슬래시 메뉴·서식 툴바·플레이스홀더 전면 한국어화. **M33 통합 요구사항으로 등재** |
| 스포일러 재클릭 시 다시 비공개 안 됨 | PoC 렌더가 공개 단방향으로만 구현(스파이크 결함, 엔진 무관) | 클릭 토글로 수정 |
| 드래그 선택 툴바에 형광펜·스포일러 없음 | 기본 툴바만 사용 중이었음 | `FormattingToolbarController` + `getFormattingToolbarItems()` 뒤에 **커스텀 스타일 버튼 3종**(형광펜·스포일러·참조 칩, 활성 상태 = `useActiveStyles`) 추가 — 커스텀 스펙의 **툴바 통합 성립 증거**(§5.1 보강). 통합 메모: `Components.FormattingToolbar.Button`은 `label`만으로는 화면 표시가 없다 — **`children`(텍스트/아이콘) 필수** |

## 7. 게이트 판정 논거

**D2 = 확정(위임 판단).** "압도적으로 유리" 판단의 근거:
- **vs A(자체 구현)**: 보류 목록(블록 조작·undo·표/수식 시각 편집·모바일)이 스파이크에서 **전부 기본
