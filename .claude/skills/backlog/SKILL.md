# /backlog <내용> — 등재 (계획서 먼저 · 코드 0)

관례(별지 §13 머리): **코드 착수 없음 — 등재·배정·권고까지만.** 결정 확정은 배정처(D 표·stage 편성)에서.

1. **인자 없음** → `powershell -ExecutionPolicy Bypass -File scripts/backlog-scan.ps1` 1회. `TODO`·DRIFT 항목만
   보고하고 끝. DRIFT의 `UNREGISTERED`는 아래 절차로 등재, `CHECK-CLOSED`는 종결 처리(§4 이동)를 제안.
2. **등재 (인자 있음)**:
   - 성격 판정: 결함 / 제안 / 질문 / 관찰. 결함이면 재현 여부를 먼저 — 필요하면 `/browser-debug`(보고만).
   - **코드 실측 1회**(짧게): 관련 컴포넌트·API 후보를 Grep해 "현행이 어떤지"를 1~2줄로 확정한다(별지 §13
     관례 — 실체를 붙여 등재). 파일 전체 Read 금지.
   - **번호**: 편집기·문서 표면·앱 UX 계열 = 별지 `editor-v2.plan.md` §13 마지막 `FB-n` + 1 (날짜 블록이 없으면
     `**YYYY-MM-DD (사용자 — 경위)**` 머리 + 표 머리 추가). 백엔드·반입·학습 루프 계열 = 마스터 계획 §14
     "v1.x 후보(로드맵 미배정)" 주석에 ③④… 추가.
   - **출처 행 작성**(정본): `| FB-n | 성격 | 내용(사용자 표현 보존) | 배정 |` — 배정 셀 = "미편성 — 후보 백로그" +
     분해·전제(착수 전 결정 필요 여부·R 연관·의존·라이선스 D10·DDL 여부) + "코드 0 — 등재만".
   - **등록부 행 작성**: `backlog.md` §1(후보) 또는 §2(결함·관찰)에 6열 1행 — ID = 출처 ID(FB-n) · 상태 =
     `미편성`/`미배정(실수요 확인 후)`/`보류(착수 금지)`/`감시` · 비고 = 편성 조건 + 버전 영향 초안(핵심/사소).
   - 리스크가 새로 드러나면 마스터 §15 R 행 추가(plan-architect 위임 — 번호 = 마지막 + 1) + 등록부 §3 1행.
3. **검증**: `backlog-scan.ps1` 재실행 → PASS.
4. **보고**: 부여 번호 · 성격 · 현행 실측 1줄 · 권고 배정(어느 후보 묶음과 동승할지 · 단독 핵심인지) ·
   다음 = `/stage-plan <ID>` 또는 "실수요 더 모은 뒤". 커밋 1개(문서만).
