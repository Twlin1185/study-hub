# /stage-review <n> — 단계 검토

1. 인자 n이 없으면: stage 문서들을 훑어 체크박스가 가장 많이 채워진 최신 단계를 대상으로 제안하고 확인받는다.
2. `stage-reviewer` 에이전트(opus)를 실행한다. 전달할 것: 단계 번호, stage 문서 경로, "DoD를 실행 수준으로 검증하라".
3. 결과를 사용자에게 전달할 때:
   - 판정(통과/조건부/반려)을 첫 줄에
   - 결함은 심각도순, `파일:라인` 링크 포함
   - "미검증" 항목(예: 폰 실기기 확인)은 사용자 확인 필요 목록으로 분리
4. 반려 판정이면 수정 방안을 제시하되 **수정은 하지 않는다** — 사용자가 `/stage-implement <n>` 재실행 또는 개별 수정을 결정한다.
5. bkit PDCA 연동: 검토 결과가 사실상 gap 분석이므로, 충족률 90% 미만이면 개선 반복을, 이상이면 다음 단계 착수를 권한다.
