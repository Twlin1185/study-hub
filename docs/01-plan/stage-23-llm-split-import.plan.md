## 현행 실측 (2026-08-04 — 상세는 plan §14 F49가 정본, 여기는 요지)

- **`too_large` 계약(§4.18 ⑤ — D2-⑥)**: A군 디코드·B군 추출 텍스트 공통 **200,000자** 상한, `phase='preparing'`(LLM 호출 전·비용 0) 판정, 안내 = "과목·회차 단위로 나눠 개별 파일로 반입" — 현행 앱의 대답은 수동 분할뿐. 이 상한 자체는 **불변**(단일 변환 입력 상한) — F49는 초과 시의 대안 경로.
- **F40-④ "서버측 자동 분할 금지" 문구 위치**: 설계 api.md §4.18 원칙 재확인(527행 부근)·§4.18 ⑤ 문구(569행 부근) — 두 곳에 S23 개정 예고 병기됨(원문 보존). §4.11의 "서버측 PDF 분할은 하지 않는다"(F40-④ `invalid_output` 서술)는 **별개 결정으로 불변** — F49는 추출 **텍스트**의 분할이지 PDF 파일 분할이 아니다.
- **전문 LLM 투입은 원리상 불가**: 98.9만 자급은 LLM 컨텍스트 자체를 초과 — 분석은 "기계 후보 산출 → 후보 오프셋+주변 발췌 표본만 LLM 투입" 구조만 성립(비용도 원본의 수 % 수준).
- **분류는 기존 기능으로 충족**: 변환 preview `suggest_categories`(LLM 제안→승인) + F40-③ `category_path` 고정 지시(사이트 반입 지시 생성기 공유) — 조각 라벨을 `category_path` 초안으로 전달하면 신규 분류 메커니즘 0.
- **잡 인프라(F48)**: 전 kind 8종 공유 인메모리 큐·전역 목록·취소·pause·공용 복원 훅 — 신규 kind는 값 확장(label·ref·라우트 매핑)만으로 현황·취소·복원 합류. 잡 시작 지점이 1곳 늘면 §4.23 ⓒ·§4.24 ⓒ "8곳 전수" 표 갱신 필요.
- **재배포 금지 고지 실측**: FetchImportWizard(사이트 반입)에만 렌더 — URL 반입 화면에는 없음. F49는 고지 정책 증감 0(확장은 범위 밖).
- **실측 미확정 1건**: `too_large` 종료 시 원본 `sources/` 저장 여부(§4.18은 unsupported·parse_failed만 명시) — 분할 플로우는 원본 저장(+오프셋 재절단)을 전제로 하므로 **착수 시 실측 후 §4.25에 확정 기입**.

## 착수 시 선행 절차 (잔여 결정 — 사용자 확정 후 [x] 처리·§4.25 신설)

- [ ] **D1. 결정 ㉮ 조각 목표 크기·조각당 상한** — 권고: 목표 3~6만 자(회차 관례) · 조각당 상한 20만 자(기존 `MAX_TEXT_CHARS` 재사용 — convert 계약 불변, [합치기] 결과 초과 시 합치기 거부 안내).
- [ ] **D2. 결정 ㉯ 원본 전체 상한(새 안전판)** — 권고: **2,000,000자**(실사례 2배 여유 — 초과 = 분할 플로우도 정직 거부, 무제한 금지). settings 화 안 함(D2-⑥ 관례).
- [ ] **D3. 결정 ㉰ 조각 수 상한** — 권고: **40개**(초과 = 거부·수동 분할 안내).
- [ ] **D4. 결정 ㉱ 잡 kind 형태** — 권고: LLM 정밀 분석만 신규 kind 1개(가칭 `split_analyze` — F48 값 확장 합류), 휴리스틱 스캔 = 동기(LLM 0·잡 불요), 조각 변환 = 기존 convert 잡 N개(신규 kind 아님).
- [ ] **D5. 결정 ㉲ 분할 상태 보존** — 권고: 경계 오프셋·라벨 JSON `import/split/` 최근 20건(R18 관례·git·백업 제외) — 조각 텍스트 무저장(원본+오프셋 재절단). **`too_large` 시 원본 저장 여부 실측 포함.**
- [ ] **D6. 결정 ㉳ 진입 UX·중복 방지·F46 연계** — 권고: `alternatives`에 `'split_import'` 신규 값(전방 호환 관례 — [분할 반입] 버튼), 상시 메뉴 없음 · 같은 원본(hash12) 재분할 = 기존 결과 재사용 우선 안내 · 정밀 분석 잡 실패의 F46 사례 수집 포함.
- [ ] **D7(문서). 설계 §4.25 신설** — 계약 정본화: 플로우 5단계·엔드포인트(분석 시작/상태/분할안/투입 — 개수는 결정 후 확정)·조각 커버리지 결정론 검증·**기존 결정·서술 개정 지점 전수 표**(F40-④ 두 곳 문면 개정·`too_large` 안내 문구·`alternatives` 값·§4.23 ⓒ/§4.24 ⓒ "8곳 전수" 갱신 — §4.24 말미 관례) + screens 절(분할 위저드) + plan §14 F49 확정 반영 + 이 문서 체크리스트 구체화.

## 목표

끝났을 때, 20만 자를 넘는 URL·파일 원본이 거부 안내로 끝나지 않고 — [분할 반입]으로 들어가 **무비용 휴리스틱 분석**(불확실할 때만 비용을 확인한 뒤 저비용 LLM 정밀 분석)이 만든 **분할안을 사용자가 확인·선택·[합치기]로 다듬고**, 선택 조각의 예상 변환 비용 합계를 확인한 뒤 기존 변환 대기열로 일괄 투입하며, 각 조각은 기존 미리보기→승인으로만 반입된다. 조각은 원문의 연속 부분 문자열(재작성 0·전체 커버리지 검증)이고, 작업 센터에서 현황·취소가 보이며, 어떤 단계도 승인 없이 LLM 비용을 쓰지 않는다. DDL·Alembic은 0건(목표)이다.

## DoD (완료 정의 — 골격, §4.25 확정 시 수치 고정)

**자동 검증 가능 항목**:

1. **비용 0 기본선**: 휴리스틱 분석·분할안 확인까지 LLM 호출 0 — LLM이 개입하는 지점(정밀 분석·조각 변환)은 전부 비용 확인 스텝 뒤에만 시작된다.
2. **조각 무결성**: 모든 조각이 원문의 연속 부분 문자열이고(재작성 0), 선택 전체의 합집합·순서·중첩이 결정론 검증된다 — 위반 산출은 투입 전에 구조화 거부.
3. **승인 게이트**: 조각이 미리보기 승인 없이 커밋되는 경로 0(R7) — 분할안 확인([선택 N조각])과 조각별 반입 승인의 이중 게이트.
4. **기존 경로 불변**: 20만 자 이하 원본의 반입 동작·계약이 현행과 완전히 같다(too_large 안내 문구·alternatives만 개정). §4.11 "서버측 PDF 분할 금지" 불변.
5. **F48 정합**: 신규 kind가 작업 센터 목록·취소·복원에 나타나고, 잡 시작 지점 전수 표(§4.23 ⓒ·§4.24 ⓒ)가 갱신돼 있다.
6. **DDL 0건·Alembic 0건**(목표 — 어긋나면 착수 중단 후 보고). 저장은 sources/·`import/split/` JSON·인메모리뿐.

**사용자 이행 항목** (실 LLM 비용 — 자동 실행하지 않음):

## 이 단계에서 하지 않는 것

- **전자동 반입 없음** — "링크만 주면 끝"은 컨셉 확정에서 명시 배제(2026-08-04): 분할안 확인(2단계)과 조각별 승인(4단계)은 생략 불가.
- **경계 문자 단위 편집 없음** — 조각 다듬기는 체크박스 선택 + 인접 [합치기]뿐(과설계 기각 확정 — 재제안 시 근거 필요).
- **PDF 파일 분할 없음** — F49는 추출 텍스트의 분할. §4.11 "서버측 PDF 분할 금지"(라이브러리 의존)는 불변 — pdf 경로(claude-cli 파일 전달)는 too_large 판정 자체가 없어 자연히 범위 밖.
- **부분 잘림 투입 없음** — "앞부분만 변환" 같은 조용한 손실 경로는 만들지 않는다(F40-④ 실질 계승 — 분할은 항상 전체 커버 조각 집합에서 사용자가 선택).
- **20만 자 상한(D2-⑥) 변경 없음** — 단일 변환 입력 상한 유지, 조각도 준수. 상한들의 settings 화 없음.
- **사설 사이트 어댑터 재도입 없음** — F49는 범용 반입 후처리(F35-2 제거 이력·재도입 금지 그대로).
- **재배포 금지 고지의 URL 반입 확장 없음** — 실측상 현재도 URL 반입에 고지가 없고, 고지 정책 변경은 이 기능 범위 밖(필요 시 별도 등재).
- **분할 이력 DB 영속화 없음** — `import/split/` 파일 JSON(R18 관례)뿐. 실수요 확인 시 계획서 먼저.
- **B군 구조 상한(xlsx 시트·행·열) 초과의 분할 없음** — 텍스트 길이 문제가 아님(기존 안내 유지).

## 리스크

- **R25(신설 — plan §15)**: 경계 오판(회차 혼합·문항 절단)·다단 비용 — 결정론 절단·커버리지 검증·2단계 사용자 확인·조각별 승인·오프셋 보존이 대응. 경계 품질 표본은 DoD 7(사용자 이행).
- **휴리스틱 커버리지**: 사이트·문서마다 헤더 형식이 달라 후보 0(구조 불명)이 잦을 수 있다 — 그 경우가 바로 LLM 정밀 분석의 존재 이유이며, 정밀 분석도 실패하면 수동 분할 안내 폴백이 상존(정직 실패 — 조용한 균등 분할 금지).
- **분할안 UI 복잡도**: 조각 40개급 목록의 선택·[합치기]·비용 합계가 모바일에서 다뤄져야 한다 — 위저드 스텝 분리·기존 Stepper 관례로 억제(화면 계약은 §4.25와 함께 screens 절에서 확정).
