# Stage 7 — 홈 커스터마이즈 · 레이아웃 UX (M7)

> 상위: `study-app.plan.md` v0.6 §5(F31~F33), §9 · 설계: `../02-design/study-app.design.md` §4.10(`home.layout`), §5 도입부(사이드바 접힘), §5.1(홈 편집 모드·D-Day 팝업), §7
> 선행: **Stage 6 완료 후 진행 (사용자 확정)** — v1 완성 지점은 이 단계 · 포함 기능: F31, F32, F33
> **순수 프론트엔드 단계 — 새 API 0개 · DDL 변경 없음.** 서버 저장은 기존 settings GET/PUT(`home.layout` 키)만 재사용.

## 목표

홈을 "내 순서·내 밀도"로 쓴다 — 위젯 드래그 재배치·숨김·열 수 선택이 저장되어 어느 기기에서든 재현되고,
D-Day는 홈에서 팝업으로 바로 고치며, 사이드바를 접어 태블릿·PC의 콘텐츠 영역을 확보한다.

## 작업 체크리스트

### 1. 홈 위젯 레이아웃 상태 (F31)
- [ ] 위젯 레지스트리 9종 확정(설계 §5.1): `continue`·`today_review`·`dday`·`heatmap`·`exam_progress`·`recent7d`·`accuracy_trend`·`weakness`·`bookmarks` — Home.tsx의 섹션들을 위젯 단위 컴포넌트로 분리
- [ ] `settings:home.layout` 읽기/저장 (JSON 규격은 설계 §4.10): 키 없으면 현재 기본 순서. 알 수 없는 id는 무시, 누락 id는 기본값(표시·마지막 순서)으로 보충 — 전방 호환
- [ ] 다열 렌더: `columns:'auto'`(뷰포트 기준 1/2/3열)·고정 1/2/3. **<640px는 항상 1열 강등**(order·col 순 평탄화), 열 수 축소 시 초과 col은 마지막 열로 클램프, 다열 시 컨테이너 폭 확장(설계 §5.1)
- [ ] 숨긴 위젯(visible=false)은 렌더뿐 아니라 해당 데이터 쿼리도 실행하지 않음(React Query `enabled:false`)
- [ ] 히트맵 반응형 주 수(설계 §5.1): 위젯 컨테이너 폭 기준(ResizeObserver)으로 표시 주 수 8~26주 유동, 항상 최근 N주를 오늘 기준 우측 정렬. 데이터는 기존 `stats/heatmap`으로 26주 1회 조회 후 클라이언트 슬라이스 — 리사이즈 시 재요청·새 API 없음

### 2. 홈 편집 모드 (F31)
- [ ] 홈 헤더 [편집] → 편집 모드: 위젯마다 드래그 핸들(≡)·숨김(눈) 토글, 상단 열 수 세그먼트(자동/1/2/3), [기본값 복원], [완료]=`PUT /api/settings` (취소 시 드래프트 폐기 — 저장은 완료 시 1회)
- [ ] 드래그&드롭 **Pointer Events 직접 구현**(pointerdown/move/up + setPointerCapture, 핸들에 `touch-action:none`) — **외부 D&D 라이브러리 금지**. 같은 열 내 순서 변경 + 열 간 이동(col 배정), 드래그 중 자리표시자 표시
- [ ] 폴백 컨트롤: 핸들 옆 ▲▼(순서)·◀▶(열 이동) 버튼 — 터치 스크롤 충돌·드래그 곤란 환경 대비 (모바일은 이 버튼만으로도 전체 편집 가능해야 함)
- [ ] 편집 모드 하단 "숨긴 위젯" 목록 — 탭하면 다시 표시로 복귀

### 3. D-Day 홈 팝업 편집 (F32)
- [ ] D-Day 위젯 헤더에 연필 아이콘 → 모달로 **설정 §5.11의 D-Day 관리(DDayManager) 컴포넌트 재사용** — 시험 분류 `exam_date` + 임의 D-Day 추가·수정·삭제 (새 로직 작성 금지, 기존 categories PATCH·settings `ddays.custom` 경로 그대로)
- [ ] D-Day 위젯은 데이터 0건이어도(visible이면) "등록된 D-Day 없음 + [추가]"로 표시 — 홈에서 첫 등록 가능 (기존 "0건 미표시" 관례의 명시적 예외, 설계 §5.1)
- [ ] 팝업 저장 시 dashboard 쿼리 invalidate → 배지 즉시 갱신

### 4. 사이드바 접힘 토글 (F33)
- [ ] 데스크톱/태블릿(≥768px) 사이드바에 접힘 토글(« / »): 접으면 **아이콘 전용 레일**(라벨 숨김, `title` 툴팁 유지)
- [ ] 상태는 zustand + localStorage `sidebar`(`'expanded'|'collapsed'`) — 서버 settings 아님, theme 관례(기기별 UI 선호). 저장값 없을 때 기본: 768~1023px(태블릿)=collapsed, ≥1024px(PC)=expanded
- [ ] 모바일(<768px)은 기존 하단 탭바 그대로 — 토글 미노출. 인쇄 뷰(print:hidden) 동작 불변 확인

## 완료 기준 (DoD)

1. **PC(≥1024px)**: 홈 [편집]에서 히트맵을 2열째로 드래그, 약점 Top10 숨김, 열 수 2 지정 → [완료] → 새로고침 및 **다른 기기 브라우저에서도 동일 레이아웃** (서버 settings 저장 확인)
2. **태블릿(768~1023px)**: 사이드바가 기본 접힘(아이콘 레일)으로 뜨고, 토글로 펼침 → 새로고침 후 유지(localStorage). 홈은 auto에서 2열 렌더
3. **폰(<640px)**: 열 수 2로 저장돼 있어도 1열 강등 표시. 편집 모드에서 드래그 없이 ▲▼ 버튼만으로 순서 변경·숨김 가능. 하단 탭바 정상
4. 홈 D-Day 위젯 연필 → 팝업에서 임의 D-Day(예: "접수 마감") 추가·수정·삭제 → 닫으면 배지 즉시 반영, 설정 화면(§5.11)과 동일 데이터임을 확인
5. [기본값 복원] → 초기 순서·전체 표시·auto 열로 복귀
6. 사이드바 접힘은 기기별(폰/태블릿/PC 각각 독립), 홈 레이아웃은 전 기기 공통 — 두 저장 위치가 설계대로 분리됨
7. 히트맵이 배치 폭을 따라감 — 1열(넓음)에서 주 수가 늘고 3열·폰(좁음)에서 최소 8주까지 줄며, 열 변경·사이드바 접힘 시 **네트워크 재요청 없이** 즉시 재계산
8. 백엔드 diff 0 — 새 엔드포인트·Alembic 마이그레이션 없음 확인

## 이 단계에서 하지 않는 것

위젯 크기 조절(리사이즈)·새 위젯 추가, 위젯별 개별 설정(히트맵 주 수 **수동 지정** 등 — v1.x 후보. 폭 기준 자동 조정은 이 단계 포함), 레이아웃 프리셋/다중 프로필, 홈 외 화면의 레이아웃 커스터마이즈, 사이드바 메뉴 항목 커스터마이즈, 외부 드래그 라이브러리 도입(dnd-kit 등), 홈 레이아웃의 기기별 분리 저장(서버 단일 레이아웃으로 충분 — 필요 확인 후 검토).
