# /browser-debug <증상> — 브라우저 재현·진단

전제: 서버는 사용자가 띄운 `http://localhost:8000` (Claude가 직접 구동하지 않는다).
접속 불가면 사용자에게 서버 기동을 요청하고 대기한다.

1. **코드 후보 특정 (짧게)**: 증상 키워드로 `frontend/src`를 Grep해 관련 컴포넌트·핸들러
   후보 1~3곳(`파일:라인`)을 잡는다. 이 단계에서 파일 전체를 읽지 않는다 — 후보 구간 몇 줄만.
2. **직접 vs 위임 판단**:
   - 왕복 1~2회로 끝나는 확인(콘솔 pattern 조회 1회, 페이지 텍스트 1회 등)은 메인 대화에서
     직접 — CLAUDE.md "브라우저 디버깅" 규약 준수.
   - **재현 조작이 여러 번 오가거나, 콘솔·네트워크를 추적해야 하면 `browser-debugger`
     에이전트에 위임한다.** 시끄러운 출력은 에이전트 컨텍스트에서 소화되고 메인에는 결론만 남는다.
3. **에이전트 프롬프트에 담을 것** (문서·코드를 통째로 다시 읽게 하지 말 것):
   - 증상 설명과 예상 재현 경로(화면·버튼 순서)
   - 1에서 찾은 후보 코드 발췌(파일 절대 경로 + 라인, 필요한 몇 줄만)
   - 검증할 가설을 명시 (예: "저장 API가 422를 반환하는지 확인")
   - 스크린샷·GIF가 꼭 필요한지 여부 (기본은 텍스트 수집)
4. **동시 실행 금지**: 브라우저 에이전트는 한 번에 1개만 — Chrome 연결을 공유하므로
   병렬로 띄우면 탭·포커스가 충돌한다.
5. **결과 중계** (한국어):
   - 판정(재현됨/재현 안 됨/부분)을 첫 줄에
   - 재현 절차와 핵심 증거 발췌, 원인 가설 `파일:라인`
   - 수정은 하지 않는다 — 사용자가 수정을 지시하면 그때 해당 dev 에이전트 또는 직접 수정으로 진행.
