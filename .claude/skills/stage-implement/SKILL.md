# /stage-implement <n> — 단계 구현 워크플로

인자로 받은 단계 번호 n에 대해 아래 순서를 따른다. 인자가 없으면 stage-status를 먼저 확인해 다음 미완료 단계를 제안하고 확인받는다.
`docs/01-plan/stage-<n>-*.plan.md`가 아직 없으면(로드맵에만 있는 단계) 구현 전에 `plan-architect`로 작업 지시서 + 설계 계약(§4.x)부터 확정한다 — 마스터 계획 로드맵에도 없는 번호면 구현하지 말고 사용자에게 보고.

## 0. 준비 확인
1. `docs/01-plan/stage-<n>-*.plan.md`를 읽는다 (작업 지시서).
2. 선행 단계 조건 확인: 이전 단계 문서의 체크박스가 대부분 `[x]`인지, DoD 관련 코드가 존재하는지. 미충족이면 **구현을 시작하지 말고** 사용자에게 보고.
3. `docs/02-design/study-app.design.md`에서 해당 단계 태그([S<n>]) 섹션과 관련 화면(§5)을 파악한다.

## 1. 작업 분배 (구현 = sonnet)
- 체크리스트를 **백엔드 묶음**과 **프론트 묶음**으로 나눈다.
- API 계약이 이미 설계 문서에 확정돼 있으므로, 서로 독립인 묶음은 `backend-dev`와 `frontend-dev` 에이전트를 **병렬로** 실행한다. 프론트가 백엔드 완성을 기다려야 하는 부분(신규 API 의존)은 순차로.
- 에이전트 프롬프트에는 반드시 포함: 단계 번호, 담당 체크리스트 항목 원문, 참조할 설계 문서 섹션 번호, "불변 규칙은 에이전트 정의 참조".
- **모델 승격 예외**: `services/sm2.py`(stage 5), `services/import_service.py`(stage 2), 학습 모드 UX(stage 3 §5.5)는 까다로우므로 해당 묶음만 `model: opus`로 호출한다.
- 설계 변경이 필요하다는 보고가 올라오면 구현을 멈추고 `plan-architect`로 결정 후 재개.

## 2. 통합 확인
- 백엔드: uvicorn 기동 → 신규 엔드포인트 스모크 호출. 프론트: `npm run build` 통과 + dev 서버로 신규 화면 동작 확인.
- 실패 시 해당 에이전트에 SendMessage로 수정 지시 (새 에이전트를 띄우지 말 것 — 맥락 유지).

## 3. 검토 (opus)
- `stage-reviewer` 에이전트 실행: 대상 단계 번호 전달.
- 치명/중요 결함 → 해당 구현 에이전트에 수정 지시 → 재검토. 최대 3회 반복, 그래도 남으면 사용자에게 판단 요청.
- 경미 결함은 목록으로 사용자에게 보고만 (수정 여부는 사용자 결정).

## 4. 마무리
- stage 문서 체크박스가 실제와 일치하는지 확인·갱신.
- 최종 보고: DoD 충족 현황(n/m), 검토 판정, 남은 결함, 다음 단계 안내.
- DoD의 "폰에서 확인" 류 항목은 자동 검증 불가 — 사용자가 직접 확인할 항목으로 명확히 안내한다.
