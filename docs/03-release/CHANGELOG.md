## 버전 체계 규약 (정본 — stage-45 확정 · 사용자 제안 채택 2026-08-31 · v2.00.1부터 발효)

| # | 규약 | 내용 |
|---|---|---|
| ① | 표기 | `v2.MM.PP` (현행 `v2.00.0` 표기 계승). 발행 시점 = 해당 stage의 최종 게이트 통과 |
| ② | bump 규칙 | **핵심 stage 완료 = MM+1·PP=1**(예 2.00.3→2.01.1) · **사소 stage 완료 = PP+1**(예 2.00.1→2.00.2). 발효 전 완료분(stage-39~42)은 소급 항목만 — 번호 재부여 없음. stage-44+45는 한 발행 단위 = v2.00.1 |
| ③ | 핵심/사소 판정 | **핵심** = 새 기능 표면·저장 계약(DDL/API) 변경·기능 퇴역 등 사용자 체감이 큰 stage(대체로 게이트 있는 로드맵 M급) · **사소** = 버그픽스·다듬기·문서·운영 정비. **stage 편성 시 머리말에 `버전 영향: 핵심/사소` 1줄 명기 의무**(애매하면 사용자에게 1회 질의). 소급 판정 금지 — 편성 시점 고정 |
| ④ | 버전 단일 출처 | 루트 **`VERSION` 파일**(한 줄, 예 `2.00.1`). 서버가 기동 시 읽어 `GET /api/app-version`의 `version` 필드로 노출 → 설정 화면 하단 표시. 발행 시에만 갱신 |
| ⑤ | stage 완료 절차 표준 항목 | **CHANGELOG 1항목 + (발행 시) VERSION 갱신 + stage-index 1행 갱신** + CLAUDE.md는 버전 줄 1곳만 |
