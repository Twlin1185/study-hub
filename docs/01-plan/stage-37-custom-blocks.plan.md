## 확정 규약 (구현 전 결정 — 이 문서 + api §4.30 + screens §5.3 S37이 정본)

### A. 목차(TOC) 블록 — `::toc`

- **스키마**: `TocBlock { type: 'toc' }` — **저장 데이터 0**(원자 블록·prop 없음). 목차 내용을
  저장하지 않는 것이 "자동 갱신" 요구의 답이다 — 렌더 시점 파생이라 갱신 동기화 문제가 애초에 없다
  (저장하면 헤딩 수정 때마다 stale — 원천 배제).
- **방언 정규형 = `::toc`**(속성 없음 — leaf directive). 속성 동반(`::toc{…}`)은 1차 미지원 —
  **기존 미지 directive 폴백 관례(sourceFallback)로 원문 보존**(손실 0·새 속성 예약도 하지 않는다,
  YAGNI). 왕복은 자명하게 동형(`::toc` ↔ TocBlock).
- **수집 범위 = 자기 표면**: 본문 표면의 TOC는 본문 헤딩만, 해설 표면은 해설 헤딩만(교차 수집 금지 —
  리더에서도 content/explanation 각각의 렌더 트리 안이라 같은 규칙이 자연 성립한다).
- **편집 표면**: 렌더 시점에 같은 표면의 heading 블록 전수를 수집해 수준 들여쓰기 목록으로 표시,
  클릭 = 해당 헤딩 블록으로 스크롤. 편집 중 헤딩 추가·수정·삭제 시 자동 반영(파생 렌더 — 공짜).
  헤딩 0개 = 빈 상태 문구(조용한 실패 없음). 수집 대상 수준 = 코어가 지원하는 헤딩 전부(필터 옵션 없음).
- **리더(remarkStudy)**: `::toc` → **헤딩 앵커 링크 목록**(§5.4 확정). 앵커 id는 **기존
  `refSyntax.slugifyHeading` 재사용**(F43 `HeadingAnchorChip`과 동일 도메인 — 새 슬러그 규칙 발명
  금지), 클릭 이동도 같은 관례(같은 렌더 루트 내 `scrollIntoView`). 중복 헤딩은 기존 앵커 칩 관례
  그대로(첫 일치 이동 — 새 규칙 없음). **인쇄 = 목록 그대로**(종이에서 링크 무동작 — 정상).

### B. 웹 임베드 블록 — `::web` + api §4.30

- **스키마**: `WebEmbedBlock { type: 'webEmbed', url: string, title?: string|null, meta?: {...} }` —
  `meta` = §4.30 응답 캐시(`description`·`siteName`·`image`·`favicon`·`fetchedAt` — 전부
  문자열|null, §4.30 응답 필드와 1:1). 캐시는 블록 prop 저장(§4.30 계약 — 블록 JSON이 소스·D1).
- **방언 정규형 = `::web{url="…"}` · `::web{url="…" title="…"}`**(§5.4 확정 문법). 직렬화는 이 두
  속성만·값은 항상 큰따옴표 인용(이스케이프는 remark-directive 표준 — 결정적 출력·고정점).
  **url 부재 또는 미지 속성 동반 = sourceFallback**(원문 보존 — 손실 0·비정규형을 스키마에 흡수하지
  않는다). 파싱은 무인용 속성도 수용(remark-directive 표준).
- **메타 캐시는 프로젝션 비대상**(directive에는 url·title만) — **명문화된 강등 손실**이다. 전환
  문서는 블록 JSON이 소스라 실손실 0. md→블록 재전환 시 meta 없음 = 텍스트 카드로 시작 →
  [메타 새로고침]으로 복원. **G-10에서 M36 프로젝션 손실 목록에 1항 기재**(R34 절차).
- **삽입 UX**: 슬래시(`/웹` 계열) 삽입 → URL 입력 → **§4.30 `POST /api/web-embed/preview` 1회
  조회 → prop 캐시**. 조회 실패는 삽입을 막지 않는다(URL만의 카드 = 정상 — §4.30 계약). 재조회는
  **[메타 새로고침] 명시 조작뿐**(열람·편집 진입 시 자동 재fetch 금지 — §4.30 계약). 일반 URL
  붙여넣기의 자동 임베드 변환은 **하지 않는다**(일반 붙여넣기 계약 유지 — FB-4 기본·YAGNI).
- **카드 렌더**: 저장 메타 기반 북마크 카드(제목 = `title` → 없으면 도메인 · 설명·썸네일·파비콘은
  있으면 표시). 썸네일·파비콘은 **원격 URL 그대로 로드**(서버 다운로드·저장 없음 — §4.30) · 로드
  실패·오프라인 = 텍스트 카드 강등(파비콘 자리 = 도메인 이니셜 폴백 — 조용한 실패 없음). 색은 토큰만
  (불변 규칙 5).
- **iframe 표면 확정(문서 충돌 정돈 — 2026-08-21 착수 판단)**: iframe 실임베드는 **편집 표면
  한정**이고 **리더·인쇄는 항상 카드**다. 근거: api §4.30 ③("인쇄·프로젝션(리더) 렌더에서 iframe
  금지")과 Design v1.41 색인("인쇄/리더 iframe 금지")이 계약으로 확정돼 있고 §4.30 본문은 무개정
  제약 — 별지 §5.4 비고의 압축 괄호("리더 렌더 … 화이트리스트만 iframe")와의 충돌은 **§4.30 ③
  우선으로 정돈**했다(별지 §5.4 비고에 정돈 문구 추기 완료). 리더(MarkdownView)는 퀴즈·학습·인쇄·
  임베드 등 전 화면이 공유하는 표면이라 iframe을 열지 않는 쪽이 R39 표면 최소화와도 정합.
  실사용에서 "열람 중 재생" 요구가 실측되면 별도 착수 전 결정으로 재론(v2.x 후보 — 임의 완화 금지).
- **iframe 화이트리스트(프론트 상수 1곳 — §4.30 ③)**: 1차 = **YouTube만**(`youtube.com`·
  `www.youtube.com`·`m.youtube.com`·`youtu.be` — watch/short URL을 embed URL로 변환해 삽입.
  프라이버시 강화 도메인 사용은 구현 재량). 확장 = 코드 수정(settings 키 0). iframe 속성 =
  `sandbox` 필수(재생에 필요한 최소 — `allow-scripts allow-same-origin` 계열) +
  `referrerpolicy="no-referrer"` + `loading="lazy"` + 전체화면 허용. 그 외 URL 전부 카드.
- **백엔드(§4.30 이행 지점)**: 신규 라우터+서비스(파일 구성은 재량 — 예: `routers/web_embed.py` +
  `services/web_embed_service.py`, `main.py` 등록). **SSRF 가드는 기존
  `services/net_safety.py` 재사용 필수**(`assert_public_host`·`is_blocked_ip`·
  `NoRedirectHandler`·매 홉 재검증 — §4.18 convert_service 전례·중복 구현 금지). HTTP 클라이언트 =
  **urllib 표준 라이브러리**(§4.30 말미 "기존 httpx 계열 재사용 — 구현 시 실측"의 실측 확정:
  백엔드에 httpx 없음·전 아웃바운드가 urllib — 신규 파이썬 의존 0). 메타 추출 = 표준
  `html.parser` 기반(OpenGraph `og:*` + `<title>` + favicon link — 외부 파서 도입 금지).
  §4.30 ② 전건: 스킴 2종 · 해석 IP 차단 · 리다이렉트 매 홉 재검증(최대 5회) · HTML 계열만 파싱 ·
  본문 512KB 스트리밍 조기 차단 · 5초 타임아웃 · 필드 1,000자 절단 · HTML 파싱 후 폐기 · 422 3종
  (`invalid_url`/`blocked_address`/`fetch_failed` — §3 코드 4종 불증) · **DB 쓰기 0·파일 쓰기 0**.
  구현 주의 1줄: 해석-접속 사이 DNS 리바인딩(TOCTOU)까지의 방어는 계약 밖 — §4.18 기존 수준과
  동일하게 맞춘다(과설계 금지·기존 관례 초과 금지).

### C. 이미지 크롭 — §4.27 재사용·원본 불변

- **진입**: 편집 표면의 image 블록 선택 시 [자르기] 조작(위치 = 블록 메뉴/툴바 — 구현 재량).
  크롭 UI = **자체 구현**(canvas + 자유 사각 선택 1가지뿐 — 비율 프리셋·회전·필터 없음·신규 npm 0).
- **제공 조건 2건(버튼 미노출로 처리)**: ① **자체 호스팅 `/images/` 경로만** — 외부 URL 이미지는
  canvas CORS 오염으로 내보내기가 기술적으로 불가 ② **GIF 제외** — canvas 내보내기는 정지 1프레임이라
  애니메이션이 조용히 소실된다(조용한 손실 금지).
- **저장 흐름**: canvas 크롭 → `toBlob`(**원본과 동일 MIME 유지** — png→png·jpg→jpeg·webp→webp,
  품질 파라미터는 구현 재량) → **`POST /api/uploads`(§4.27) 그대로 재사용**(매직 바이트 판별·해시
  파일명·중복 병합 자동 — 신규 엔드포인트 0·백엔드 diff 0) → 응답 `url`로 **image 블록의 url prop
  교체**. 크롭 적용은 **undo 1단위**(stage-36 규약 E 정신 — 되돌리면 구 url 복귀).
- **원본 불변(불변 규칙 4)**: 기존 파일에 대한 수정·삭제 호출 0 — 참조만 바뀌고 구 파일은 그대로
  남는다. 남은 구 파일의 정리는 **D8 고아 이미지 정리(사용자 확정 대기)의 소관이며 이 단계 무관** —
  관련 코드 0("하지 않는 것" 참조).
- **caption(alt)·`{w=}` 크기 표기 유지**: 크롭 후에도 블록의 캡션·폭 값을 보존한다(잘린 실폭보다
  큰 `w`는 자연 축소 — 자동 보정 여부는 구현 재량, 조용한 값 삭제만 금지).
