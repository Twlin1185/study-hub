### 2-A. 인라인 모델·직렬화 (이 단계의 심장)

- [ ] **A-2. 모델 → Markdown 직렬화(정규 표기 표)**: 굵게 `**` · 기울임 `*` · 취소선 `~~` · 밑줄 `++` ·

- [ ] **A-3. 재파싱 동형성 검사(안전 밸브 — ⑤(3))**: 직렬화 결과를 다시 파싱해 인라인 트리가 동형이 아니면

  임베드가 문단 안에 있는 경우)에서 "파싱 → 무편집 → 직렬화 = 원본 동일"을 구현 중 기계 검증하고 결과를

## DoD (Definition of Done) — 잠정

자동(구현·검토 세션에서 확인):
1. **문법이 화면에 드러나지 않는다**: 문단 블록을 클릭해 편집 상태로 들어가도 `:t[…]{…}`·`**`·`==` 등이
   보이지 않고, 색·형광펜·굵게가 입힌 그대로 보이며 타이핑된다.
2. **선택 → 서식 → 즉시 반영**: "abc"에서 "bc"를 선택하고 글자색 빨강을 적용하면 **그 자리에서 bc가 빨갛게**
   보이고, 이탈 시 저장 소스는 `a:t[bc]{c=red}` 형태의 Markdown이다(사용자 요구 원문 그대로의 검증).
3. **왕복 무손실**: 표본 문서에서 ⓐ 리치 표면 진입 → 무편집 이탈 = **value 1바이트 불변** ⓑ 한 글자만 변경 →
   **그 인라인 노드 밖 바이트 불변**(A-4 기계 검증 결과를 완료 기록에 수치로 남긴다).
4. **안전 밸브 동작**: 직렬화 결과가 재파싱 동형이 아닌 입력(예: 이스케이프가 필요한 문자 조합)에서
   **본문이 조용히 바뀌지 않고** 소스 편집 폴백 + 안내가 뜬다.
5. **붙여넣기**: HTML을 붙여넣어도 서식·태그가 들어오지 않고 텍스트만 들어간다. 이미지 붙여넣기는 F54 경로
   그대로 동작. **저장 본문에 HTML 태그가 렌더 가능한 형태로 들어가는 경로 0**.
6. **한글 IME**: 조합 중 서식 적용·조합 중 blur·조합 중 확정 3경로에서 글자 유실·중복·조합 강제 종료가
   없다(실 브라우저 실측 — 추측 확정 금지).
7. **편집기 밖 파급 0**: 읽기 전용 화면(문서 상세·학습·퀴즈·시험·플래시카드·오답노트·인쇄·임베드 카드)과
   편집·분할 모드 렌더 **diff 0**, `MarkdownView.tsx` 무변경(또는 기본값 prop 추가뿐임을 diff로 확인).
8. **소스 편집 블록 회귀 0**: 표·코드펜스·수식·임베드·콜아웃 블록은 S27 동작 그대로(리치 표면에 들어오지 않는다).
9. `npm run build` 0 에러 · `invariant-scan.ps1` PASS(신규 색 하드코딩 0) · `run-tests.ps1` 기존 통과 유지
   (백엔드 diff 0) · **`package.json` 신규 의존 0**(결정 ①이 권고안대로일 때).

사용자 이행(서버는 사용자가 직접 구동 — Claude는 서버를 남기지 않는다):
10. 실사용 확인 — PC에서 실제 문서 작성·편집 체감(서식 즉시 반영·저장 결과 확인·한글 입력).
    **폰 확인은 이 단계의 DoD가 아니다**(모바일은 3단계 — 그 전까지 폰에서 불안정하면 퇴로 토글로 소스 편집).

## 이 단계에서 하지 않는 것

- **결정 ①~⑧ 확정 전 구현 착수 금지** — 이 문서의 가장 강한 조항.
- **전면 WYSIWYG 없음** — 문서 전체를 하나의 contentEditable로 두고 블록 구조까지 DOM으로 다루는 형태는
  기각 유지(F55 기각 계승). 리치 표면은 **블록 단위·인라인 한정**.
- **원시 HTML 저장·렌더 없음 · rehype-raw 없음** — F43 D2 불번복(R30의 최종 방어선).
- **DOM 스크래핑 역직렬화(turndown류) 없음** — 직렬화는 인라인 모델에서만.
- **목록·인용 리치화, Enter 블록 분할·Backspace 병합, 블록 드래그 재배열 없음** — 2단계 후보.
- **모바일·터치 최적화 없음** — 3단계 후보(DoD 10에서 폰을 요구하지 않는 이유).
- **서식 보존 붙여넣기 없음** — plain text 강제(④). 확장은 계획서 먼저.
- **표·수식 시각 편집기 없음 · 자유 hex 색 없음**(팔레트 7색 고정 — F52 결정 ③).
- **자체 undo 스택 없음**(⑦).
- **백엔드·API·DB·설계 §4.x 신설 없음** — API 0건이므로 계약 정본은 screens §5.3 S30 절이 된다.

## 리스크

- **R29 왕복 직렬화 손실(이 단계 최대 리스크)** — 대응은 ⑤의 3층 계약 + 리치 대상 블록 화이트리스트 +
  DoD 3·4. "무편집 = 1바이트 불변"은 S27이 세운 계약이며 **F56이 그것을 물려받는다**(완화가 아니라 계승).
- **R30 붙여넣기 정화** — 1단계 plain text 강제로 표면 자체를 열지 않는다. 최종 방어선(Markdown 저장 +
  rehype-raw 기각)은 불번복.
- **R31 IME·모바일** — ⑥ 조합 규약과 React 재렌더 격리가 코어 계약. 모바일은 단계 분리 + 퇴로 토글.
- **R32 의존·문법 이중화** — 결정 ①에 종속. 도입안을 택할 경우 필수 조건 3건(자체 문법 왕복 표본 테스트 DoD ·
  렌더는 여전히 공용 `MarkdownView` 단독 · 번들 증가 실측 기록)을 이 문서에 먼저 반영한 뒤 착수한다.
- **S27 자산과의 결합도** — `EditablePreview.tsx`·`MarkdownFieldEditor.tsx` 두 파일에 집중되므로 같은 파일을
  건드리는 다른 단계와 **동시 착수 금지**(계획서 §14 F56 순서 관계).
