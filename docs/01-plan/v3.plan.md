# Study Hub V3 계획서 — 감사 기반 리팩토링 로드맵

> 상태: **Draft v0.1**(2026-11-10 작성 · 사용자 승인 "진행시켜! 너말대로 가보자" — 순서·게이트 권고안 채택). 이 문서가 V3 작업의 정본이다. 각 단계는 여기서 골라 `/stage-plan`으로 편성한다(stage 지시서가 세부 정본 — 이 문서는 범위·순서·완료 기준만).
> 근거: 2026-11-10 포괄 감사(백엔드 결함 · 프론트 결함 · 백엔드 아키텍처 · 프론트 아키텍처·UX 구조 · 개발 하네스 5갈래). UI/UX는 코드 기반 분석이며 실화면 조작 실측은 하지 않았다(§7 미검증).
> 한 줄 결론: **전면 리빌드 없음.** 재작성은 잡 모델 · LLM 호출 계층 · 프론트 API 타입 3곳뿐이고, 나머지는 유지 + 점진 개선이다.

## 1. 원칙

1. **긴 브랜치 금지** — 모든 단계는 독립 머지 가능한 stage로 쪼개 `v2.05.x`부터 순차 발행한다. 실사용 검증이 끊기지 않게 한다.
2. **안전망 먼저** — 구조를 건드리기 전에 테스트 기반과 CI(P1)를 깐다. 리팩토링 stage는 "동작 무변"을 테스트로 증명한다.
3. **성숙한 로직은 옮기되 다시 쓰지 않는다** — `convert_service.py`의 판별·신뢰 게이트·오류 문구는 실사용 결함이 반영된 지식이다. 분할은 이동이고, 재작성은 잡 러너·LLM 실행기에 한정한다.
4. **불변 규칙·기존 절차 유지** — CLAUDE.md 불변 규칙 1~10, DDL = 마스터 §6.2 + Alembic, 버전 판정 = CHANGELOG 머리 규약 ③(편성 시점 고정).
5. **v3.00.0은 §2 게이트 5항 전부 통과 시점에만** 찍는다. 날짜 목표는 두지 않는다.
