Study Hub 사용 설명서

기출문제와 학습자료를 쌓고, 학습 → 풀이 → 오답관리 → 복습의 루프를 돌리는 개인 학습 허브.

이 문서 하나로 설치부터 일상 사용까지 따라 할 수 있게 쓰였습니다 — v1.x 전체 기능 기준(큐넷 공개문제 반입 포함)입니다. · 갱신일: 2026-08-02 · 문서 위치: docs/manual/user-manual.html

1. 이 앱은 무엇인가

Study Hub는 내 PC에서만 도는 개인용 학습 웹앱입니다. 자격증 기출문제 PDF나 정리 노트를 구조화된 문서로 바꿔 쌓아두고, 시험별 커리큘럼으로 학습하고, 퀴즈로 풀고, 틀린 것은 오답노트와 간격반복(SM-2) 복습으로 되돌아옵니다. 서버는 집 안 네트워크에서만 접근하고, 데이터는 전부 로컬 파일(study.db)에 저장됩니다.

반입자료 → 문서→ 학습커리큘럼 순서로→ 퀴즈풀이 기록→ 오답노트틀린 이유 관리→ 복습SM-2가 날짜 결정→ 다시 퀴즈로…

한 번 세팅하면 매일 하는 일은 단순합니다 — 홈에서 [오늘 공부 시작]을 누르는 것. 복습 → 이어하기가 한 번의 탭으로 이어지고, 나머지는 앱이 골라줍니다. 시험이 다가오면 실전 모의고사(8장)와 D-Day 복습 강화(10장)가 마무리를 돕습니다.

2. 설치와 실행

필요한 것

  • Python 3.11+ — 백엔드(FastAPI) 실행용
  • Node.js 18+ — 프론트엔드 빌드용 (빌드해 두면 평소엔 필요 없음)
  • Claude Code (선택) — PDF·노트를 반입용 JSON으로 변환할 때 사용 (5장)

최초 1회 준비

  1. 백엔드 의존성 설치 
    cd backend
pip install -r requirements.txt
  2. 프론트엔드 빌드

    빌드 결과물(frontend/dist)을 백엔드가 함께 서빙하므로, 이후엔 서버 하나만 켜면 됩니다.

    cd frontend
npm install
npm run build

매일 하는 실행

  1. 서버 켜기 
    cd backend
uvicorn main:app --host 0.0.0.0 --port 8000

    창을 닫지 말고 켜 둡니다. 끄려면 Ctrl+C.

  2. 접속
    • PC: 브라우저에서 http://localhost:8000
    • 폰·태블릿: 같은 와이파이에서 http://<PC의 IP>:8000 — PC의 IP는 명령창에서 ipconfig를 쳐서 "IPv4 주소"(예: 192.168.0.15)를 확인
보안

이 앱은 로그인이 없습니다. 공유기 포트포워딩으로 외부(인터넷)에 열지 마세요. 집 안 네트워크 전용입니다. 데이터가 소중하다면 17장 백업을 먼저 읽어두세요.

개발 모드

화면 코드를 고치면서 쓸 때만 frontend에서 npm run dev로 개발 서버(5173 포트)를 따로 띄웁니다. 일반 사용이라면 위의 빌드+8000 포트 하나면 충분합니다.

4. 꼭 알아야 할 개념

문서 — 모든 콘텐츠의 단위

개념 정리든 기출문제든 전부 "문서"입니다. 문서마다 고유번호(DOC-0001)가 붙고, 타입은 4가지:

타입무엇예
concept개념 정리 (Markdown 본문)"정규화란 무엇인가"
question연습 문제 (보기·정답·해설)직접 만든 확인 문제
past_question기출 문제 + 출처"2023년 2회 17번"
flashcard암기 카드 (앞/뒤)용어 → 정의

분류 — 문서를 담는 트리, 단 소유하지 않는다

분류는 자격증 → 시험 → 과목 → 단원처럼 자유롭게 만드는 트리입니다. 중요한 규칙 하나: 한 문서는 여러 분류에 동시에 연결될 수 있습니다. "정규화" 개념 문서 하나를 정보처리기사와 SQLD 두 시험에 모두 연결하는 식이죠. 그래서 분류에서 문서를 "삭제"하면 실제로는 연결만 끊깁니다 — 문서 자체는 남아 있고, 다른 시험에서의 학습 기록도 무사합니다.

태그 · 원본 · 삭제

  • 태그(#정규화) — 분류와 별개의 가로 방향 라벨. 검색과 자동 분류의 재료.
  • 원본 — 반입할 때 넣은 PDF 등은 sources/ 폴더에 원본 그대로 보관되고, 앱은 절대 수정하지 않습니다.
  • 삭제는 보관 — 문서 삭제는 숨김 처리(소프트 삭제)입니다. 풀이 기록·통계는 깨지지 않습니다.

본문 작성 문법 — 다른 문서 끌어오기 · 가리기 v1.x

문서 본문(Markdown)에 몇 글자만 적으면 다른 문서를 그 자리에 펼치거나, 이동 버튼을 만들거나, 내용을 접어 두고·가려 둘 수 있습니다. 같은 설명을 여기저기 복사해 두는 대신 개념 문서 하나를 만들어 두고 여러 곳에서 끌어다 쓰는 방식입니다.

이렇게 적으면이렇게 보입니다
![[DOC-0012]] 임베드 — 그 자리에 DOC-0012의 본문이 카드로 펼쳐집니다(출처 배지 + [원문 열기]).
[[DOC-0012]] 링크 칩 — 내용은 펼치지 않고, 누르면 그 문서로 이동하는 작은 버튼.
[[#절 제목]] 같은 문서 안 이동 — 누르면 그 제목(헤딩) 위치로 스크롤합니다.
:::fold[제목] … ::: 접기 — 제목 줄만 보이고, 눌러야 펼쳐집니다(기본 접힘).
:::hide[제목] … ::: 가리기 — 내용이 흐리게 가려지고 탭하면 공개됩니다(암기·자가 테스트용).
  • 표시 이름 바꾸기 — 세 참조 모두 | 뒤에 원하는 말을 붙이면 그 말로 보입니다: ![[DOC-0012|산술평균]], [[#산포의 측도|여기]].
  • DOC-번호 확인 — 문서 상세 화면 위쪽(제목 옆)에 있습니다. 외우지 않아도 됩니다 — 아래 삽입 도우미가 대신 찾아 줍니다.
  • 제목 생략 가능 — :::fold, :::hide처럼만 써도 되고, 그때는 "접힌 구간"·"가려진 내용"으로 표시됩니다.
번호를 몰라도 됩니다 — 삽입 도우미

문서를 작성·편집할 때 본문 칸 오른쪽 위의 [＋ 참조 삽입]을 누르면 문서 검색 팝업이 열립니다. 임베드 / 링크 칩 중 하나를 고르고 문서를 선택하면 커서 자리에 문법이 그대로 삽입됩니다. 편집 칸 아래에는 문법 요약 한 줄이 항상 붙어 있습니다.

읽을 때 알아둘 것

① 임베드로 읽은 문서는 진도·복습에 기록되지 않습니다 — 기록되는 것은 지금 열고 있는 문서 쪽입니다 (같은 내용을 여러 문서에서 끌어다 써도 진도가 이중으로 오르지 않습니다).
② 펼침은 2단까지 — 임베드 안의 임베드까지만 펼치고, 그보다 깊으면 "깊이 제한으로 펼치지 않은 문서"라고만 표시됩니다. 서로를 끌어오는 순환이 생겨도 "순환 참조"라고 알려 주고 멈춥니다.
③ 대상이 없거나 지워졌을 때 — 지운 문서 자리에는 "삭제된 문서 … 복원하면 다시 보입니다", 번호가 틀렸으면 "존재하지 않는 참조"가 표시됩니다. 어느 쪽도 문서를 깨뜨리지 않습니다. 그래서 임베드가 걸려 있어도 삭제는 막지 않습니다 — 삭제 확인 창에서 "N개 문서에 임베드됨"이라고만 알려 줍니다.
④ 누가 나를 끌어다 쓰는지 — 문서 상세의 사용처 영역에 "이 문서를 임베드한 문서 N개" 목록이 나옵니다.

줄바꿈 · 수식 쓰기 v1.x

본문·해설 어디서나 다음이 지원됩니다 (이미 저장된 문서·해설에도 바로 적용됩니다):

  • 줄바꿈 — 그냥 Enter 한 번이면 화면에서도 줄이 바뀝니다. 빈 줄을 넣으면 문단이 나뉩니다.
  • 수식 — $…$(문장 속 수식), $$…$$(줄 전체 수식)에 LaTeX 문법을 쓰면 수식으로 예쁘게 표시됩니다. 예: $\bar{x} = \frac{1}{n}\sum x_i$. 수식이 아닌 곳에 $ 기호를 써야 하면 \$로 적으세요.

5. 자료 넣기 (반입)

반입은 "PDF나 노트를 → 문서 여러 개로" 바꿔 넣는 과정입니다. 길은 네 가지 — 미리 만들어 둔 반입 JSON을 넣거나(A), 원본 파일을 그대로 던지거나(B), URL 하나로(C) 넣습니다. 네 번째 사이트에서 가져오기(D)는 큐넷(Q-Net) 공개문제를 자격증·회차만 골라 통째로 가져오는 경로입니다.

필기 기출은 파일·URL 반입으로

공개돼 있는 기출 자료는 실기 공개문제 위주라, 기사·산업기사의 필기 기출은 자동으로 가져올 방법이 없습니다(방법 D로도 나오지 않습니다). 필기는 방법 A~C(파일·URL 반입)가 정식 경로입니다 — 그래서 이 경로에 여러 파일 한 번에 걸기 · 분류 경로 미리 지정 · 변환 결과 보관 같은 편의 장치가 붙어 있습니다.

방법 A — Claude Code로 변환해서 넣기

  1. JSON으로 변환 요청

    Claude Code를 열고 변환 프롬프트 템플릿(prompts/convert.md)과 함께 파일을 건넵니다. 예: "convert.md 규격대로 이 PDF를 반입 JSON으로 변환해서 import/ 폴더에 저장해줘".

  2. 반입 화면에서 파일 선택

    /import에서 생성된 JSON을 선택합니다. 원본 PDF도 함께 첨부하면 sources/에 보관됩니다.

  3. 미리보기에서 확인

    항목마다 상태 배지가 붙습니다 — 정상 / 중복 의심 / 오류. 중복 의심은 기존 문서와 나란히 비교해 보고 건너뛰기 · 새로 추가 · 병합 중 선택. 분류 연결 제안과 문제↔개념 관계 제안도 체크박스로 고릅니다.

  4. 반입 실행

    결과 요약(생성 N · 병합 N · 건너뜀 N)이 나오고, 새 문서로 바로 이동할 수 있습니다.

방법 B — 원본 파일 그대로 던지기 (여러 개 한 번에) v1.x

/import의 "원본 파일로 시작"에 PDF·이미지는 물론 docx·xlsx·md·txt·html·xml·csv 원본을 고르면(아래 지원 파일 포맷 표 참조), 앱이 PC에 설치된 claude CLI를 직접 불러 변환부터 해 줍니다. 파일은 한 번에 최대 10개까지 고를 수 있고, 고른 파일은 반입 대기열에 쌓여 순서대로 하나씩 변환됩니다.

  1. 파일 고르기 (최대 10개)

    여러 회차를 한 번에 골라 걸어둘 수 있습니다. 10개는 이미 대기 중인 파일과 새로 고른 파일을 합친 수이고, 넘으면 안내가 뜨며 추가되지 않습니다.

  2. (선택) 분류 경로 지정

    아래 "분류 경로 미리 지정하기"를 먼저 해 두면 변환 결과가 그 경로 하나만 제안합니다.

  3. 순서대로 변환

    파일 카드마다 상태 배지가 붙습니다 — 대기 / 변환 중 / 검토 대기 / 반입 완료 / 실패. 자세한 진행 패널은 지금 변환 중인 1건에만 보입니다. 브라우저를 새로고침하거나 껐다 켜도 목록과 상태가 그대로 복원됩니다.

  4. 완료된 것부터 검토·반입

    [검토]를 누르면 방법 A의 3단계(미리보기)로 들어가고, 반입을 마치면 [대기열로 돌아가기]로 다음 파일을 이어서 처리합니다. 미리보기·결과 화면에서도 대기열은 "검토 대기 N건" 요약으로 남습니다.

참고

방법 B는 우선 엔진(15장)이 PC에 설치·로그인되어 있어야 합니다. 없거나 실패하면 안내 메시지와 함께 방법 A로 하라고 알려줍니다. 실패한 파일은 목록에 남아 다음 순위 엔진을 쓸 수 있으면 [◯◯로 재시도](버튼 이름은 그 순간 다음 차례인 엔진 이름으로 바뀝니다)나 [건너뛰기]로 정리할 수 있습니다.

참고

지금 변환 중인 1건도 [취소]로 멈출 수 있습니다 v1.x — 다만 실행 중 취소는 이미 처리된 토큰만큼 요금이 발생할 수 있어 확인을 한 번 묻습니다(22장). 변환은 한 번에 하나씩만 돌아가므로(동시에 여러 개를 돌리지 않습니다) 뒤에 걸린 파일은 건너뛰기로 정리하면 됩니다. 또 새로고침한 뒤에는 브라우저가 파일 자체를 기억하지 못하므로, 그 파일을 다시 변환하려면 새로 고르면 됩니다.

방법 C — URL로 반입 v1.x

/import의 "URL로 시작"에 공개된 기출 PDF나 웹 페이지 주소를 붙여넣으면, 앱이 내려받아 변환까지 알아서 해 줍니다. URL 반입도 방법 B와 같은 대기열에 들어갑니다 — 파일과 URL을 섞어 걸어두고 완료된 것부터 순서대로 검토할 수 있습니다. 내려받은 원본은 파일 반입과 똑같이 sources/에 보관됩니다.

참고

공개 자료용입니다 — 로그인이 필요한 페이지는 안 되고, 너무 큰 파일(50MB 초과)이나 내부망 주소는 안전을 위해 거부됩니다.

분류 경로 미리 지정하기 v1.x

시작 화면(파일·URL 공통)의 접이식 "분류 경로 지정 (선택)"을 펼치면, 기존 분류를 고르고 그 뒤에 회차 같은 하위 경로를 덧붙일 수 있습니다 (예: 품질경영기사/필기 선택 + 2022년 2회 입력 → 완성 경로 미리보기가 그 자리에 표시됩니다). 지정해 두면 변환 결과의 분류 제안이 그 경로 하나로 통일되어, 미리보기에서 손볼 일이 거의 없어집니다. 대기열에서는 "모든 파일에 같은 상위 경로 적용"을 켜고 파일마다 회차만 따로 적으면 됩니다.

참고

경로를 지정해도 곧바로 반입되지는 않습니다 — 어디까지나 제안을 고정할 뿐이고, 실제 반입은 미리보기에서 승인해야 진행됩니다. 아직 없는 분류는 승인할 때 자동으로 만들어집니다.

변환 결과는 사라지지 않습니다 v1.x

변환이 성공하면 그 결과(반입 JSON)가 파일로 함께 보관됩니다. 덕분에 미리보기를 한 시간 넘게 열어두거나 서버를 껐다 켜도 같은 미리보기로 되돌아가 반입을 마칠 수 있습니다 — 되살아난 경우 화면 위에 "이전 미리보기를 복구했습니다 — 중복 판정은 현재 DB 기준입니다"가 표시됩니다 (그 사이 문서가 늘었다면 "중복 의심" 배지가 처음과 다를 수 있다는 뜻입니다).

  • [변환 JSON 내려받기] — 미리보기 화면과 실패 화면에서 변환 결과 파일을 직접 받을 수 있습니다. 받은 파일은 방법 A의 "반입 JSON 파일 선택"으로 그대로 넣을 수 있는 최후의 안전장치입니다. (내가 직접 올린 JSON으로 만든 미리보기에는 파일이 이미 손에 있으므로 이 버튼이 보이지 않습니다.)
  • 이미 반입을 마친 미리보기로 다시 반입하려 하면 "이미 반입이 완료된 미리보기입니다"라고 막아 줍니다 — 같은 자료가 두 번 들어가는 사고를 방지합니다.
보관 범위

보관되는 변환 결과는 최근 50건까지이고, 백업(17장)에는 포함되지 않습니다. 백업에 담기는 것은 DB와 sources/ 원본이므로, 최악의 경우에도 잃는 것은 "다시 변환하는 수고"뿐입니다.

변환이 실패했을 때

  • "응답이 중간에 잘렸을 수 있습니다" — 문항이 너무 많아 변환 결과가 끝까지 나오지 못한 경우입니다. 같은 파일로 다시 시도해도 대개 같은 결과이니, [파일 나눠서 다시 올리기]로 원본을 과목·회차 단위로 쪼개 올리거나 다른 엔진(15장)으로 재시도하세요.
  • "한도 초과" — 리셋 시각까지 기다리거나, 다음 순위 엔진을 쓸 수 있다면 [◯◯로 재시도]로 그 자리에서 이어갑니다 (15장).
  • 어떤 경우든 변환에 성공했던 결과는 그대로 남아 있습니다 — 위의 [변환 JSON 내려받기]로 회수하세요.

미리보기 경고 배지 — 자동 변환 결과만 v1.x

방법 B·C(원본 파일·URL 자동 변환)와 방법 D(사이트에서 가져오기)로 만든 미리보기는 LLM이 만든 지문·보기·정답이 원본과 실제로 맞는지 앱이 한 번 더 기계적으로 대조합니다. 문제가 의심되면 항목에 아래 배지가 붙고, 앞의 둘은 기본적으로 체크가 해제되어 반입에서 빠집니다 — 넣으려면 직접 체크해야 합니다. (방법 A처럼 직접 고른 JSON 파일에는 원본 대조 대상이 없어 이 배지가 붙지 않습니다.)

방법 D — 사이트에서 가져오기 (큐넷 공개문제) v1.x

/import의 [사이트에서 가져오기] 탭은 큐넷(Q-Net)이 공식으로 공개하는 "국가자격 공개문제"를 가져오는 경로입니다. 공공기관이 공개용으로 제공하는 자료를 정식 통로로 받아오는 것이라, 사이트 화면을 긁어오는 방식이 아닙니다.

먼저 읽어 주세요 — 여기에 있는 자료 / 없는 자료

큐넷 공개문제는 실기 작업형·도면 문제 위주입니다. 필기 기출과 필답형 실기 기출은 여기에 없습니다 — 예를 들어 품질경영기사를 검색하면 결과가 0건으로 나오는데, 이건 고장이 아니라 애초에 공개 대상이 아니라서 그렇습니다. 필기·필답형 자료는 방법 A~C(파일·URL 반입)로 넣으세요.

1) 서비스키 등록 (처음 한 번만)

  1. 공공데이터포털에서 활용신청

    공공데이터포털(data.go.kr)에 로그인해 "국가자격 공개문제 조회 서비스"를 찾아 활용신청합니다. 승인되면 마이페이지에서 서비스키(인증키)를 복사할 수 있습니다.

  2. 설정에 등록

    /settings → 데이터 그룹 → 큐넷 오픈API 카드에 서비스키를 붙여 넣고 저장합니다. 저장 전에 즉석 확인 호출을 한 번 해 보고, 키가 잘못됐으면 이유를 알려주며 저장하지 않습니다.

  3. 등록 후

    카드에는 끝 4자리만 보이고(원문 키는 화면에도 기록에도 남지 않습니다), 언제든 [삭제]할 수 있습니다. 키를 지우면 [사이트에서 가져오기] 탭은 다시 안내 화면으로 돌아갑니다.

키 보관 위치

서비스키는 데이터베이스가 아니라 프로젝트 루트의 로컬 파일(secrets.json)에만 저장되고 백업 zip에 포함되지 않습니다(17장). PC를 옮기면 다시 등록해야 합니다. LLM API 키와 같은 파일을 쓰지만 서로 덮어쓰지 않습니다.

2) 가져오는 순서

  1. 자격증(종목) 검색

    종목 이름 일부를 입력해 고릅니다. 결과가 없으면 "이 종목의 공개문제가 없습니다"라고 안내합니다 — 오류가 아니라 위에서 말한 커버리지 문제입니다.

  2. 회차(게시물) 선택

    공개문제 게시물 목록에서 하나를 고릅니다. 이미 넣은 회차에는 "이미 반입됨" 배지가 붙습니다. 목록 아래의 [안내문 N건 보기]를 누르면 시험 안내·집행 공지 같은 문제가 아닌 게시물도 볼 수 있습니다(평소엔 숨김).

  3. 예상 사용량 확인

    문항 수·대략적인 LLM 사용량과 "개인 학습 전용 — 수집물 재배포 금지" 고지를 확인해야 실행됩니다.

  4. 실행 → 미리보기

    첨부된 공개문제 PDF를 받아 변환한 뒤, 방법 A~C와 똑같은 미리보기 화면으로 이어집니다. 중복 확인·분류 제안·반입은 그다음부터 동일합니다.

회차를 알 수 없는 게시물

게시물 제목에 회차·날짜가 없는 경우가 많습니다. 이때 앱은 회차를 임의로 지어내지 않고 제목 그대로 목록에 올립니다 — 대신 "○○년 ○회" 분류 폴더가 자동으로 만들어지지 않으므로, 반입 후 미리보기 화면이나 문서 상세에서 원하는 분류에 직접 연결해 주세요.

압축파일(ZIP)만 있는 게시물

도면·과제가 ZIP 묶음으로만 올라온 게시물이 있습니다. 이 경우 변환은 되지 않지만 원본 파일은 sources/ 폴더에 그대로 저장되고, 화면에 [파일 반입으로 이어가기] 버튼과 함께 "압축을 풀어 PDF·이미지를 파일로 반입하세요"라고 안내합니다. 조용히 실패하거나 사라지는 일은 없습니다. (한글 파일이면 "한글에서 PDF로 저장한 뒤 파일 반입"으로 안내합니다.)

하루 호출 한도를 넘겼거나 키가 잘못됐을 때도 알 수 없는 코드 대신 "오늘 호출 한도를 초과했습니다 — 내일 다시 시도하세요"처럼 사람 말로 알려줍니다. 같은 검색·목록을 반복해 열어도 하루 동안은 저장해 둔 결과를 재사용하므로 한도가 낭비되지 않습니다.

변환 진행 상황 보기

변환이 도는 동안 진행 패널이 단계(다운로드 → 준비 → LLM 작업 중 → 결과 정리 → 미리보기)와 경과 시간, 누적 토큰·예상 비용, 대략적인 남은 시간을 실시간으로 보여줍니다. 브라우저를 새로고침해도 작업은 서버에서 계속됩니다 — 다시 열면 같은 작업의 진행이 이어서 보입니다. 여러 파일을 걸어둔 경우 이 패널은 지금 변환 중인 1건에만 보이고 나머지는 상태 배지로 표시됩니다. 또 반입 위저드 상단의 단계 표시(①②③)는 지나온 단계를 눌러 되돌아갈 수 있습니다.

이미 넣은 문제의 정답·해설 채우기 — 답지·해설지 반입 v1.x

앞의 방법 A~D는 새 문서를 반입하는 경로이고, 이 기능은 이미 반입된 문제 중 정답·해설이 비어 있는 곳만 답지·해설지 파일로 채우는 별도 경로입니다. /import의 [답지·해설지 반입] 탭에서 시작합니다.

  1. 분류 범위 선택

    답지를 적용할 분류 범위를 고릅니다(하위 포함). 회차 단위로 범위를 좁히기를 권장합니다 — 여러 회차가 섞인 통합 답지는 문항 번호가 충돌해 "매칭 안 됨"이 많이 생깁니다.

  2. 답지 파일 업로드

    이 단계는 텍스트만 추출합니다 — LLM을 부르지 않아 비용이 들지 않습니다.

  3. 예상 사용량 확인

    대상 문항 수(정답 없음·해설 없음 건수)와 예상 입력 토큰을 확인해야 다음 단계(LLM 가공)가 시작됩니다.

  4. 가공 → 매칭 미리보기

    답지에서 뽑아낸 문항 번호별 정답·해설이 범위 안의 문서와 자동으로 짝지어집니다. 항목마다 현재 상태(정답·해설 있음/없음)와 채워질 내용이 나란히 보이고, 원하는 항목만 골라 [선택 병합]합니다.

안심 — 기존 정답·해설은 절대 덮어쓰지 않습니다

이미 값이 있는 필드는 "이미 있음"으로 표시되고 병합에서 자동으로 건너뜁니다 — 채워지는 것은 빈 필드뿐입니다. 같은 답지를 여러 번 반입해도 안전합니다(멱등).

표시뜻
매칭 안 됨답지의 번호에 해당하는 문서를 찾지 못했거나(또는 그 반대) 번호가 모호한 경우 — 별도 목록으로만 보여주고 병합 대상에서 제외됩니다.
원문과 불일치 (창작 의심)산출된 해설이 답지 원문과 대조되지 않습니다 — 기본적으로 체크가 해제됩니다.
원문 대조 불가답지에서 텍스트를 뽑지 못해 대조를 못 했습니다 — 기본 포함, 반입 전 원본과 직접 대조를 권장합니다.
채울 내용 없음정답·해설이 이미 둘 다 있거나 답지에 값이 없어, 선택해도 실제로는 아무것도 반영되지 않는 항목입니다.
참고

반입한 답지 원본 파일은 서버 sources/에 보관되지만, 앱 화면에서 다시 열어보는 기능은 없습니다.

챕터(커리큘럼의 어느 단원이든)는 개념 → 문제 → 기출의 3단계 여정으로 이어집니다. 개념 트랙을 마치면 [문제 풀이로 이어가기] → 연습문제 퀴즈 → [기출로 마무리] → 기출 퀴즈 → 최종 완료 화면(단계별 정답률 + 틀린 문제 재도전 + [다음 챕터 ▶]) 순서입니다. 단계는 건너뛸 수 있고, 해당 타입 문서가 없는 단계는 자동으로 생략됩니다. [이어하기]는 첫 미완료 단계로 데려다 줍니다.

  • 커리큘럼의 3단 진도 — 각 챕터 행에 개념·문제·기출의 진행 표시(✓ ● ○)와 타입별 개수 칩이 붙고, [학습]·[문제]·[기출] 버튼으로 원하는 단계에 바로 들어갈 수 있습니다(하위 단원 포함). 순서는 권장 동선일 뿐 강제가 아닙니다.
  • 커리큘럼에서 문서 추가·편집 — 챕터를 펼치면 학습내용/문제/기출 탭별 문서 목록이 보이고, [+ 문서 추가](해당 분류에 자동 연결)와 행의 [편집]으로 문서 상세 화면을 거치지 않고 그 자리에서 작성·수정할 수 있습니다.

8. 실전 모의고사 v1.x

시험 형식 그대로 — 과목 구성, 제한 시간, 다 풀고 한 번에 채점 — 모의 응시하는 화면입니다. 퀴즈(/quiz)가 한 문제씩 즉시 채점하는 연습이라면, 모의고사(/exam)는 실전 리허설입니다.

구성하고 응시하기

  1. 모의고사 탭으로 진입

    퀴즈 화면 상단의 [일반 퀴즈 | 실전 모의고사] 탭에서 모의고사를 선택합니다.

  2. 시험 노드와 과목 선택

    트리에서 시험(예: "정보처리기사/필기")을 고르면 바로 아래 단원들이 과목 체크리스트로 나옵니다 (문제가 있는 과목은 기본 전체 선택). 회차 노드 1개만 고르면 "회차 그대로" 모의가 됩니다 — 그 회차 전체 문항이 원래 순서대로 출제됩니다.

  3. 조건 확인 후 [응시 시작]

    과목당 문항 수(기본 20) · 제한 시간(문항 수 기준 자동 계산, 수정 가능) · 합격선(기본 "과목 40점 과락 · 평균 60점 합격", 수정 가능) · 출제 순서(랜덤/순차)를 정합니다.

  4. 응시

    보기를 골라도 채점되지 않고 답안만 저장됩니다 — 답 변경, 이전/다음 이동이 자유롭습니다. 옆의 문항 네비게이터(폰은 하단 시트)에서 과목별 응답/미응답 현황을 보고 건너뛴 문제로 점프할 수 있습니다. 상단 타이머는 잔여 5분부터 경고색이 되고, 0초가 되면 미응답을 포함해 자동 제출됩니다. [제출]을 직접 누르면 미응답 개수를 확인한 뒤 제출합니다.

주의

응시 중 새로고침하거나 화면을 떠나면 시험이 사라집니다(경고가 뜹니다). 제출 전까지는 어디에도 저장되지 않습니다.

결과 리포트

  • 총점 + 합격/불합격 배지 — 총점은 과목 점수의 평균. 합격은 전 과목 과락 없음과 평균 합격선 이상을 둘 다 만족해야 합니다. 과락 과목이 하나라도 있으면 평균이 높아도 불합격입니다.
  • 과목별 점수 바 — 과락 컷 라인이 표시되고, 과락 과목엔 배지가 붙습니다.
  • 문항별 리뷰 — 제출 후이므로 내 답 vs 정답, 해설이 공개됩니다. 오답에는 퀴즈와 같은 틀린 이유 원탭 버튼이 있습니다.
  • [틀린 문제 재도전] · [오답노트 가기] — 틀린 문제(미응답 포함)는 자동으로 오답노트와 복습 스케줄에 합류해 있습니다. 별도 조작 불요.
  • 응시 이력 — 지난 응시들의 점수 요약이 함께 보입니다. 단, 상세 리포트는 결과 화면을 떠나면 다시 볼 수 없으니 필요하면 그 자리에서 확인하세요.
알아두기

미응답 문항은 오답으로 처리됩니다 — 몰라서 비운 것도 복습 대상이니까요. 채점은 항상 서버에서 하고, 응시 중에는 정답·해설이 절대 내려오지 않습니다.

AI 응용 모의고사 — 기출을 응용한 새 문항으로 실전 감각 늘리기 v1.x

모의고사 화면 상단의 [실전(기출) | AI 응용] 탭에서 AI 응용을 선택하면, 고른 범위의 기출·개념 문서를 근거로 LLM이 기출에 없던 새 응용 문항을 만들어 그 문제로 응시할 수 있습니다. 기출 문제를 그대로 재출제하는 기능이 아닙니다.

  1. 범위·문항 수·엔진 선택 → [생성 준비]

    분류 트리에서 범위를 고르고 문항 수(1~20개)와 사용할 엔진을 정합니다. 이 단계는 LLM을 부르지 않아 비용이 들지 않습니다 — 범위 안의 근거 문서 수만 확인합니다.

  2. 예상 사용량 확인 → [생성 시작]

    근거 문서 수(기출·문제·개념)와 예상 입력 토큰, 사용 엔진과 과금형을 확인해야만 다음 단계로 진행됩니다. 범위가 너무 넓어 근거 텍스트가 상한을 넘거나 근거 문서가 0건이면 여기서 안내와 함께 멈춥니다.

  3. 생성 진행 → 결과 요약

    생성이 끝나면 "요청 N개 중 M개 생성"을 있는 그대로 보여줍니다. 검증을 통과하지 못한 문항은 조용히 줄이지 않고 폐기 사유별 건수로 함께 표시됩니다(형식 오류·해설 누락·근거 확인 불가·원본과 중복 등). 요청보다 적게 생성됐으면 경고 배지가 붙습니다.

  4. [응시 시작]

    생성이 서버에 저장 완료된 뒤에만 응시할 수 있습니다. 이후 응시·타이머·문항 네비게이터·제출은 위의 실전 모의고사와 완전히 같은 화면을 그대로 씁니다.

생성 문항은 격리되어 저장됩니다

생성된 문항은 "AI 응용 모의고사"라는 별도 분류에만 연결되고, 문서 서두에 [AI 생성 문항] 마커가 항상 붙어 응시·문서 상세·오답노트·복습 카드 어디서든 기출과 구분됩니다. 일반 퀴즈·실전 모의고사·검색에는 섞여 나오지 않지만(범위를 직접 고르지 않는 한), 문서 목록·검색·통계 화면에서는 숨기지 않고 그대로 보입니다.

응시 전에는 사전 미리보기가 없습니다(시험 문제를 미리 보면 응시 자체가 무의미하므로). 대신 방어선은 응시 이후로 옮겨져 있습니다 — 결과 화면의 문항별 리뷰마다 [근거 문서] 링크로 그 문항이 어떤 기출·개념에서 나왔는지 바로 확인할 수 있고, 이상한 문항은 기존과 같은 [오류 신고] 버튼으로 신고합니다(16장 참고). 오답은 일반 모의고사와 똑같이 오답노트·복습 스케줄에 합류합니다.

이 탭 하단에는 AI 응용 응시 이력이 별도로 표시됩니다 — 실전 모의고사 이력과 점수 통계가 서로 섞이지 않도록 완전히 분리되어 있습니다.

알아두기

전 문항 객관식(4지선다)만 생성됩니다(단답·서술형 생성 없음). 생성 문항은 정식 개념으로 승격되거나 본류 분류로 옮겨지지 않습니다 — 오답으로 틀렸을 때만 복습 루프(오답노트·SRS)에 들어갑니다.

10. 복습과 플래시카드

"오늘의 복습"이 고르는 방법

문제를 처음 푸는 순간 그 문서에 보이지 않는 복습 카드가 생기고, SM-2 알고리즘이 다음 복습 날짜를 정합니다. 직관만 기억하면 됩니다:

  • 틀리면 → 내일 다시 나옵니다.
  • 맞을수록 → 간격이 늘어납니다 (1일 → 6일 → 그 이후는 점점 크게).
  • 빠르고 정확하게 맞으면 간격이 더 빨리 벌어지고, 겨우 맞으면 천천히 벌어집니다.

홈의 "오늘의 복습 N개" 버튼이 오늘 기한이 된 카드를 모아줍니다. 우선순위는 오답노트 미해결 → 기한을 오래 넘긴 순이고, 하루 상한(기본 30개)을 넘는 분량은 다음 날로 밀립니다. 문서 상세에는 복습 상태가 "3일 후 복습 예정"처럼 사람 말로 표시됩니다 (알고리즘 수치가 궁금하면 "자세히"를 펼치면 됩니다).

  • 복습량 확대 — 하루 상한이 시험 8~14일 전엔 1.5배, 7일 전부터는 2배로 늘어납니다.
  • 임박 시험 범위 우선 — 그 시험 범위에 속한 카드가 큐 앞쪽으로 옵니다(오답노트 미해결이 여전히 1순위).

  • 발동 중에는 복습 화면 상단에 "『시험 이름』 D-7 · 오늘 복습 60개로 강화" 같은 배지가 보입니다.
  • 원치 않으면 설정(학습 그룹)의 "D-Day 복습 강화" 토글을 끄면 됩니다(기본 켜짐). "접수 마감" 같은 임의 D-Day는 강화 대상이 아닙니다 — 시험 분류의 시험일만 해당됩니다.

  • D-Day 배지 — 시험일까지 며칠 남았는지
  • 시험별 진도 도넛 · 최근 7일 · 정답률 추이 · 자꾸 틀리는 개념 Top 10 · 북마크

데이터가 없는 위젯은 표시되지 않으므로, 처음엔 홈이 단출한 게 정상입니다.

일일 학습 목표와 스트릭 v1.x

설정(학습 그룹)에서 하루 목표를 문제 수와 공부 시간(분) 두 가지로 정할 수 있습니다 (비워두면 목표 없음 — 시간은 문제 풀이 시간 기준). 목표를 정하면:

  • 홈 스트릭 위젯에 오늘 진행 게이지("문제 12/20 · 15분/30분")가 보이고, 달성 시 배지가 붙습니다.
  • 히트맵에서 목표를 달성한 날은 셀에 링이 둘리고 툴팁에 "목표 달성"이 표기됩니다.
  • 복습 완료 화면에도 스트릭·목표 달성이 함께 표시됩니다.

스트릭(연속 학습일)은 목표와 무관하게 "그날 뭐라도 학습했는가"(문제 풀이 또는 개념 완료) 기준으로 이어집니다. 아직 오늘 공부를 안 한 아침에도 어제까지의 연속 기록은 끊기지 않고 유지 표시됩니다 — 하루가 끝나기 전엔 스트릭을 깨지 않습니다.

홈 화면 내 맘대로 바꾸기 — [편집] 모드

홈 오른쪽 위의 [편집]을 누르면 위젯 배치를 직접 바꿀 수 있습니다. 배치는 서버에 저장되어 PC·폰·태블릿 어디서든 같은 모습으로 보입니다.

  • 열 수 선택 — 기본값 자동은 화면 폭에 맞춰 1~3열과 위젯 분배를 알아서 조정합니다 (창을 넓히거나 사이드바를 접으면 실시간으로 열이 늘어남). 자동 모드에서는 배치가 미리보기로만 보이고, 1·2·3열 중 하나를 선택하면 직접 편집이 열립니다.
  • 드래그 재배치 — 고정 열 모드에서 핸들(≡)을 잡고 원하는 열·위치로 끌어다 놓습니다. 드래그가 불편하면 ▲▼(순서)·◀▶(열 이동) 버튼으로도 됩니다 (폰은 버튼만으로 전체 편집 가능).
  • 숨기기 — 눈(👁) 아이콘으로 안 쓰는 위젯을 숨깁니다. 숨긴 위젯은 데이터도 불러오지 않아 홈이 가벼워집니다. 하단 "숨긴 위젯" 목록에서 탭하거나 그리드로 드래그해 복귀.
  • [기본값 복원]으로 언제든 초기 배치로 되돌릴 수 있습니다. 저장은 [완료]를 누를 때 한 번만.
  • D-Day 즉석 편집 — D-Day 위젯의 연필(✏) 아이콘을 누르면 홈을 떠나지 않고 팝업에서 바로 추가·수정·삭제할 수 있습니다. 등록된 D-Day가 하나도 없어도 위젯이 보여 첫 등록이 가능합니다.
  • 사이드바 접기 — 사이드바 위 « 버튼으로 아이콘만 남는 좁은 레일로 접을 수 있습니다. 기기별로 따로 기억되며, 태블릿은 기본 접힘·PC는 기본 펼침입니다.
  • 히트맵 너비 반응형 — 학습 히트맵은 위젯이 놓인 폭에 맞춰 8~26주 범위를 알아서 보여줍니다.

14. 태그 자동 분류 · 태그 관리자

"이런 태그가 붙은 문서는 이 분류에 넣어줘"를 규칙으로 등록해 두면, 반입할 때마다 앱이 분류 연결을 제안합니다.

  1. 규칙 만들기

    설정의 규칙 관리에서 대상 분류와 태그 조건을 지정합니다. 조건은 단순하게 — 태그 하나(정규화) 또는 OR 결합(정규화 OR 트랜잭션)만 됩니다.

  2. 제안 확인

    문서가 반입되거나 태그가 바뀔 때 조건이 맞으면 제안함에 쌓이고, 홈·탐색에 "제안 N건" 배지가 뜹니다. 제안함에서 문서·대상 분류를 보고 승인/거절합니다. 거절한 제안은 다시 올라오지 않습니다.

  3. 기존 문서까지 훑기

    규칙을 만들거나 고친 뒤 [일괄 스캔]을 누르면 이미 들어와 있는 문서 전체를 검사해 제안을 만들어 줍니다.

auto 모드

규칙을 auto로 켜면 제안 없이 즉시 연결됩니다. 편하지만 오분류가 조용히 쌓일 수 있으니 확실한 규칙에만 쓰세요. 실수했다면 규칙 관리의 "이 규칙이 연결한 문서 일괄 해제"로 한 번에 되돌립니다.

태그 관리자 — 태그 대청소 v1.x

설정의 태그·분류 그룹 → 태그 관리자에서 태그 전체를 한 화면에서 관리합니다.

  • 목록 테이블 — 태그별 사용 문서 수와 "규칙 사용" 배지(자동 분류 규칙이 참조 중), 검색·정렬. 행을 클릭하면 그 태그가 붙은 문서들을 탐색 화면에서 바로 봅니다.
  • 유사 태그 병합 제안 — 오타로 갈라진 태그(#정규화 / #정규 화)를 앱이 찾아 "병합할까요?"라고 제안합니다. [병합]에서 남길 이름을 고르면 전 문서에 일괄 반영, [무시]하면 이번엔 넘어갑니다.
  • 이름 변경 — 태그 이름을 바꾸면 붙어 있는 모든 문서에 즉시 반영됩니다. 바꾼 이름이 기존 태그와 겹치면 병합을 쓰라고 안내합니다.
  • 삭제 — 아무 데도 안 쓰이는 태그만 지울 수 있습니다. 사용 중인 태그의 정리는 병합으로.

  • 켜기/끄기 v1.x — 각 카드의 토글로 엔진을 "사용 안 함"으로 끌 수 있습니다. 꺼진 엔진은 자동 선택·폴백 어느 경로로도 절대 호출되지 않습니다 — 예를 들어 종량 과금인 Claude API를 키는 등록해 둔 채로 꺼 두면, 뜻하지 않은 과금 호출을 원천 차단할 수 있습니다. 꺼도 카드의 진단·설정은 그대로 보이고, 켜면 즉시 복귀합니다. 모든 엔진을 끄면 카드 목록 상단에 안내가 뜨고 변환·생성 기능이 동작하지 않습니다.
  • 모델 선택 v1.x — 카드에서 그 엔진으로 쓸 모델을 목록에서 고를 수 있습니다 (직접 입력은 없습니다). 여기서 고른 모델은 반입 변환·해설 보완·응용 문항 생성 등 모든 LLM 작업에 일관 적용됩니다. Claude CLI는 "엔진 기본(미전달)"을 고르면 CLI에 설정된 기본 모델을 그대로 씁니다.

쓸 수 없는 엔진은 눌리지 않습니다 v1.x

변환 시작·사이트에서 가져오기·AI 응용 모의고사 등 엔진을 고르는 모든 화면에서, 지금 쓸 수 없는 엔진은 선택 자체가 막히고 사유가 함께 표시됩니다 — "사용 안 함"(꺼 둔 엔진) · "설치 필요" · "키 미등록" 등. 방금 설치·로그인·키 등록을 마쳤는데 아직 막혀 보이면 [다시 확인]을 누르세요(상태 진단은 최대 1분 캐시됩니다).

Codex로 시작하기 v1.x

Claude 구독이 없어도 ChatGPT 구독만 있으면 API 키나 터미널 지식 없이 변환을 쓸 수 있습니다. 설정의 LLM 엔진 그룹에서 Codex CLI 카드를 찾아 아래 순서로 진행하세요:

  1. 설치 — 카드의 [설치] 버튼을 누르면 앱이 자동으로 다운로드해 앱 전용 폴더에 설치합니다(시스템 PATH는 건드리지 않습니다). PC에 이미 Codex CLI가 설치돼 있으면 다운로드 없이 그것을 그대로 씁니다. 몇 초 안에 끝납니다.
  2. 로그인 — PC에 이미 Codex 로그인 기록이 있으면(다른 도구에서 로그인해 둔 경우) 이 단계는 자동으로 건너뜁니다. 없으면 터미널에서 codex login을 실행해 브라우저로 로그인한 뒤, 카드의 [다시 확인]을 누르세요.
  3. 진단 — 카드에 설치·로그인 상태가 그대로 표시됩니다. 정상이면 다른 엔진처럼 변환·재생성에 바로 쓸 수 있습니다.
개인정보 고지

Codex CLI로 변환을 돌리면 그 원문이 이 PC의 전역 ~/.codex 로그·세션 기록에 남습니다 (Claude CLI/API와는 별개의 저장소입니다). 카드에도 같은 안내가 항상 표시됩니다.

한도에 걸리면

구독 한도를 초과해도 알 수 없는 오류 코드가 아니라 사람 말로 알려줍니다 — 예: "Claude 구독 세션 한도 초과 — 오늘 21:40 리셋". 우선순위상 다음 차례 엔진을 쓸 수 있으면 [◯◯로 재시도] 버튼이 함께 떠서 그 자리에서 이어갈 수 있습니다(버튼 이름은 다음 차례 엔진 이름으로 자동으로 바뀝니다 — 예: [Claude API로 재시도], [Codex CLI로 재시도]). 리셋 시각 전에 다시 변환을 시도하면 시작 전에 경고 배너로 미리 알려줍니다.

API 키 보관

Claude API 키는 데이터베이스가 아니라 프로젝트 루트의 로컬 파일(secrets.json)에만 저장되며, 백업 zip에 포함되지 않습니다(git에도 올라가지 않음). PC를 옮기면 키는 다시 등록해야 합니다. Codex CLI는 키 대신 ~/.codex의 전역 로그인 자격증명을 쓰므로 이 화면에 등록할 것이 없습니다.

16. 문제 오류 신고

변환 과정에서 보기 순서가 밀렸거나 정답이 이상한 문제를 발견하면, 그 자리에서 고칠 수 있습니다.

  1. [오류 신고] 버튼 — 문서 상세·학습 모드·퀴즈 해설 어디서든 누르고, 무엇이 이상한지 적습니다.
  2. 재생성 대기 — 앱이 LLM 엔진(15장 — 설정한 우선 엔진·폴백 정책 적용)으로 그 문서만 다시 만듭니다(원본 출처 정보가 있으면 대조). 진행 중 배지가 문서 상세에 표시됩니다.
  3. 나란히 비교 — 완료되면 문서 상세에서 기존 vs 신규를 비교해 보고 [교체] 또는 [폐기]를 선택합니다.
안심

교체해도 문서 번호는 그대로라 풀이 이력·오답노트·복습 일정이 전부 유지됩니다. 승인 없이 자동으로 덮어쓰는 일은 없습니다.

AI 풀이 생성 — 해설 없는 문제 채우기 v1.x

답지·해설지 반입이 정본 경로이고, 답지가 아예 없을 때 쓰는 보조 경로입니다. 문서 상세에서 [정답·해설 보기]를 눌러 펼치면 나타나는 [AI 풀이 생성] 버튼으로 LLM이 직접 푼 해설을 받을 수 있습니다(문제 문서 중 해설이 비어 있는 경우에만 버튼이 보입니다).

  1. [AI 풀이 생성] 버튼 — 확인 다이얼로그가 뜨고, 사용할 엔진과 과금 형태(구독형/종량 과금)를 보여줍니다. 확인하면 LLM을 1회 호출합니다.
  2. 초안 확인 — 생성된 해설(원본에 정답이 없던 문제는 정답도 함께)이 "AI 생성 — 오개념 가능" 배지와 함께 나타납니다.
  3. [승인 반영] / [버리기] — 승인하면 해설이 저장되고, 마음에 들지 않으면 버려도 원본 문서는 그대로입니다.
생성분 표시 — 마커

승인된 해설은 맨 앞에 > [AI 생성 해설] 날짜 · 엔진명 — 원본 자료에 없는 LLM 생성 풀이입니다. 오류가 보이면 오류 신고로 재생성하세요. 형태의 인용구가 자동으로 붙습니다(정답까지 함께 채운 경우 [AI 생성 해설·정답]). 이 표시로 원본에서 온 해설과 항상 구분됩니다 — 오개념이 보이면 위의 [오류 신고]로 다시 만들 수 있습니다.

오답노트에서는

오답노트(9장)의 카드에서는 직접 생성하지 않고, [해설 보완 (문서 상세)] 버튼으로 문서 상세로 이동해 위 흐름을 이어갑니다.

17. 백업과 복원

  • 백업 만들기 — 설정 화면의 [백업 생성]. DB 스냅샷과 원본 파일(sources/)이 backups/ 폴더에 시각과 함께 저장됩니다.
  • 자동 백업 — 설정에서 켜면, 마지막 백업 후 24시간이 지난 채로 서버가 켜질 때 자동 실행됩니다.
  • 복원 — 백업 목록에서 선택 후, 실수 방지를 위해 확인 문구를 직접 타이핑해야 진행됩니다. 복원 직전 상태도 자동 스냅샷으로 한 벌 남깁니다.
  • 복원 후 새로 불러오기 v1.x — 복원이 끝나면 "복원 완료 — 앱을 다시 불러옵니다" 모달이 뜨고, 확인하면 화면 전체가 새로고침되어 복원된 데이터로 이어집니다 (서버 재시작 없이). 혹시 그 뒤에도 화면이 이상하게 동작하면 서버를 한 번 재시작하세요.
참고

LLM API 키(15장)는 보안상 백업 zip에 포함되지 않습니다 — 복원하거나 다른 PC로 이사한 뒤에는 설정에서 키를 다시 등록하세요.

수동 백업

앱이 꺼진 상태라면 프로젝트 루트의 study.db 파일을 다른 곳에 복사해 두는 것만으로도 백업이 됩니다. 학습 기록 CSV가 필요하면 설정의 통계 내보내기로 풀이 기록 전체를 내려받을 수 있습니다.

20. 문제 해결 (FAQ)

폰에서 접속이 안 돼요

  1. 폰과 PC가 같은 와이파이인지 확인 (모바일 데이터 꺼보기)
  2. 서버를 --host 0.0.0.0으로 켰는지 확인 (이 옵션이 없으면 PC 밖에서 못 들어옵니다)
  3. IP가 맞는지 ipconfig로 다시 확인 — 공유기가 IP를 바꿨을 수 있습니다
  4. 그래도 안 되면 Windows 방화벽에서 Python(8000 포트) 인바운드를 허용 — 처음 실행 때 뜨는 방화벽 허용 창에서 "허용"을 눌렀는지 기억해 보세요

"포트가 이미 사용 중" 오류

이전 서버가 아직 떠 있는 경우입니다. 기존 창을 Ctrl+C로 끄거나, 다른 포트로 켜세요: uvicorn main:app --host 0.0.0.0 --port 8001 (접속 주소도 8001로).

변환(원본 파일로 시작)이 실패해요

PC에 Claude Code가 설치되어 있고 터미널에서 claude 명령이 되는지 확인하세요. 안 되면 방법 A(Claude Code 대화로 JSON 생성)를 쓰면 됩니다. 결과는 같습니다.

"이 형식은 자동 변환할 수 없습니다"류 안내로 끝났다면 파일 포맷 문제입니다 — 지원 파일 포맷 표의 "알아둘 것" 열이 해결책입니다(한글 → PDF 저장, zip → 압축 해제, 구버전 doc/xls → docx/xlsx 저장). 원본은 이미 sources/에 저장돼 있으니 파일을 잃을 걱정은 없습니다. "추출된 텍스트가 너무 깁니다"는 원본을 과목·회차 단위로 나눠 다시 반입하면 됩니다.

데이터는 어디에 있나요?

전부 프로젝트 폴더 안입니다 — DB는 study.db, 원본은 sources/, 백업은 backups/. 이 폴더만 통째로 복사하면 다른 PC로 이사할 수 있습니다.

화면이 이상하거나 옛날 화면이 보여요

프론트를 새로 빌드한 직후라면 브라우저 캐시 문제일 수 있습니다. Ctrl+Shift+R(강력 새로고침)을 해 보세요. PWA로 설치한 폰에서는 앱을 완전히 닫았다 다시 여세요.

복습이 갑자기 너무 많이 쌓였어요

며칠 쉬면 기한 지난 카드가 몰립니다. 하루 상한(기본 30)이 있으니 오늘 치만 소화하면 됩니다 — 밀린 것은 우선순위 순으로 매일 조금씩 나옵니다. 상한은 설정에서 조절. 또 하나 — 시험일이 14일 이내면 D-Day 복습 강화가 상한을 자동으로 늘린 상태일 수 있습니다 (복습 화면 상단에 강화 배지가 보입니다). 원치 않으면 설정에서 토글을 끄세요.

변환하다가 "한도 초과"라고 떠요

우선 엔진(Claude 구독 또는 ChatGPT 구독)의 사용 한도에 걸린 것입니다. 메시지에 표시된 리셋 시각까지 기다렸다 다시 하거나, 우선순위상 다음 차례 엔진을 쓸 수 있으면 [◯◯로 재시도] 버튼으로 그 자리에서 이어갈 수 있습니다 (15장 — 다음 차례가 Claude API면 사용량만큼 과금됩니다).

이 경로는 큐넷 공개문제 하나만 다룹니다(방법 D). 증상별로 —

  • 탭에 안내 화면만 보인다 — 서비스키가 아직 등록되지 않은 상태입니다. 설정 → 데이터 → 큐넷 오픈API 카드에서 등록하세요.
  • 검색 결과가 0건이다 — 대부분 정상입니다. 큐넷 공개문제는 실기 작업형·도면 위주라 필기·필답형(예: 품질경영기사) 기출은 아예 없습니다. 그 자료는 파일·URL 반입으로 넣으세요.
  • "오늘 호출 한도 초과" · "서비스키가 올바르지 않습니다" — 각각 내일 다시 시도하거나 설정에서 키를 다시 등록하면 됩니다.
  • "압축파일만 있습니다"라고 끝난다 — 도면·과제 묶음 게시물입니다. 원본은 sources/에 저장돼 있으니 압축을 풀어 [파일 반입으로 이어가기]로 진행하세요.
  • 그 밖의 실패 — 언제든 파일 반입 · URL 반입이 대안 버튼으로 함께 제시됩니다. 이 두 경로는 외부 서비스와 무관하게 항상 동작합니다.

반입된 문제의 내용이 이상한 경우는 문제 오류 신고로 그 문서만 다시 만들 수 있습니다.

변환에 실패했는데 다시 해도 똑같이 실패해요

"응답이 중간에 잘렸을 수 있습니다"라고 나왔다면 문항이 너무 많은 원본입니다 — 재시도해도 결과가 같습니다. [파일 나눠서 다시 올리기]로 원본을 과목·회차 단위로 쪼개 올리거나, 다른 엔진(15장)으로 재시도하세요.

변환해 둔 결과가 날아간 것 같아요

변환에 성공했던 결과는 파일로 보관되므로, 시간이 지나거나 서버를 껐다 켜도 같은 미리보기로 복구됩니다 (화면 위에 "이전 미리보기를 복구했습니다" 표시). 그래도 불안하면 미리보기·실패 화면의 [변환 JSON 내려받기]로 파일을 받아 두고, "반입 JSON 파일 선택"으로 넣으면 됩니다. 보관은 최근 50건까지이며 백업에는 포함되지 않습니다(5장).

모의고사 결과를 나중에 다시 보고 싶어요

모의고사 화면의 응시 이력에 지난 응시의 점수·합격 여부 요약이 남습니다. 다만 문항별 상세 리뷰는 제출 직후의 결과 화면에서만 볼 수 있으니, 해설은 그 자리에서 확인하세요 — 틀린 문제 자체는 오답노트에 전부 남아 있습니다.

21. 반입 개선 루프 v1.x

반입이 실패하거나(변환 오류·신뢰 게이트 탈락) 문제를 신고하면, 그 실패가 조용히 사라지지 않고 실패 사례로 자동 쌓입니다. 쌓인 사례를 골라 LLM에게 개선안을 만들어 달라고 하면 — 사례집에 처리 예시를 더하거나, 변환 프롬프트를 고치거나, 코드로 고쳐야 할 문제는 재현 패키지로 정리해 줍니다. 사람이 승인해야만 실제로 반영되고(자동 반영은 없습니다), 반영 뒤에는 과거 실패 사례를 다시 변환해 개선이 실제로 통했는지 확인할 수 있습니다.

① 실패 사례가 쌓이는 곳

아래 세 가지 상황에서 앱이 자동으로(비용 없이) 사례를 기록합니다 — 직접 할 일은 없습니다:

  • 반입 실패 — 변환 잡이 파싱 실패·출력 불완전·미지원 형식으로 끝난 경우
  • 신뢰 게이트 탈락 — 미리보기에서 "원문과 불일치 (창작 의심)" 항목이 하나라도 있었던 경우
  • 오류 신고 — 문제 오류 신고(16장)를 보낸 경우

쌓인 사례는 제안함(/suggestions)의 [반입 개선] 탭 → 실패 사례에서 볼 수 있습니다. 사례마다 유형·발생 경위·최근 발생 시각이 표시되고, 필요 없는 사례는 [제거]로 지울 수 있습니다.

보관 범위

사례는 최근 50건까지만 보관되고(오래된 것부터 정리), 백업(17장)에는 포함되지 않습니다. 사라져도 손해는 "사례 재수집"뿐 — 실제 원본과 문서는 그대로입니다.

② 개선 제안 만들기 — 예상 사용량부터 확인

사례를 고르고 [개선 제안 생성]을 눌러도 곧바로 LLM이 호출되지 않습니다 — 먼저 사용할 사례 수·예상 입력 토큰·엔진·과금 형태를 보여주는 확인 화면이 뜨고, 확인해야만 [생성 시작]을 누를 수 있습니다.

  1. 사례 선택 — 실패 사례 목록에서 체크박스로 고르고 [개선 제안 생성]
  2. 예상 사용량 확인 — 선택한 사례 수, 예상 입력 토큰, 사용 엔진과 과금 형태(구독형/종량 과금)를 확인합니다. 이 단계까지는 LLM을 부르지 않아 비용이 들지 않습니다.
  3. 생성 시작 → 진행 — 확인 후에만 LLM이 호출되고, 진행 상황(단계·경과 시간·토큰)이 실시간으로 표시됩니다.
  4. 결과 요약 — "제안 N건 생성"과 함께, 통과하지 못한 안이 있으면 폐기 사유별 건수가 함께 표시됩니다 — 조용히 줄어드는 일은 없습니다.

③ 제안 카드 — 승인해야만 반영됩니다

생성된 제안은 [반입 개선] 탭의 제안 목록에 카드로 쌓입니다. 카드를 열면 세 종류 중 하나이고, 반영 방식이 다릅니다:

종류뜻승인하면
사례집 추가앞으로의 변환에 참고할 처리 예시를 덧붙이는 안 변환 프롬프트의 부속 사례집 끝에 그 예시가 추가됩니다
프롬프트 수정변환 규칙 문구 자체를 고치는 안 본문이 실제로 바뀝니다 — 바뀌기 전/후를 나란히 확인한 뒤 승인하세요
코드 수정 필요앱 코드를 고쳐야 해결되는 문제 앱이 스스로 코드를 고치지 않습니다 — [인계 완료] 처리(아래 ④ 참고)

어떤 종류든 승인하기 전에 반영될 내용 전문을 먼저 봅니다 — 사례집은 추가될 문장 그대로, 프롬프트 수정은 바뀌기 전/후 나란히 비교와 적용 후 전체 본문까지 확인할 수 있습니다. 마음에 들지 않으면 [거절]하면 그 제안은 사라지고 파일은 그대로 남습니다.

정책 잠금

"창작 금지"처럼 이 앱의 핵심 규칙 문장은 잠겨 있어 어떤 제안으로도 고칠 수 없습니다. 이 구간을 건드리는 프롬프트 수정 제안은 생성 단계에서 자동으로 걸러지고, 혹시라도 카드까지 올라오면 승인 시점에 위반 표시와 함께 거부됩니다. 정책 문장 자체를 바꾸려면 이 기능이 아니라 개발 쪽에서 계획을 먼저 세워야 합니다.

④ "코드 수정 필요" 제안 — 개발 세션에 인계하기

"코드 수정 필요"로 분류된 제안은 앱이 스스로 코드를 고치지 않습니다 — 대신 원인·재현 방법·기대 동작을 정리한 재현 패키지를 만들어 줍니다.

  1. 카드 열기 — 재현 패키지 전문을 확인합니다.
  2. [복사] — 버튼 하나로 클립보드에 담깁니다.
  3. 개발 세션에 전달 — Claude Code 등 개발 세션에 그대로 붙여넣습니다.
  4. [인계 완료] — 카드를 정리합니다(같은 제안이 계속 대기 중으로 남지 않도록).

⑤ 회귀 재검증 — 개선이 실제로 통했는지 확인

제안을 승인 반영한 뒤에는, 과거에 실패했던 사례들을 다시 변환해 이번엔 통과하는지 확인할 수 있습니다. 반입 대기열이나 실제 문서에는 아무 영향이 없는 검증 전용 실행입니다.

  1. [회귀 재검증] — [반입 개선] 탭의 회귀 재검증에서 반영된 제안을 고릅니다.
  2. 사례 선택 — 그 제안의 근거 사례와 같은 유형의 사례가 기본으로 골라져 있고(최대 10건), 직접 더하거나 뺄 수 있습니다.
  3. 예상 사용량 확인 → 실행 — 여기서도 확인해야만 LLM이 호출됩니다.
  4. 결과 확인 — 사례마다 통과(재발 없음) · 재발(같은 유형) · 다르게 실패 · 원본 접근 불가 중 하나로 표시되고, 그 사례의 누적 회귀 이력에도 남습니다.
신고 사례는 대상 아님

오류 신고로 쌓인 사례는 자동 회귀 판정 대상이 아니라 선택 목록에 뜨지 않습니다 — 신고는 오류 신고(16장)에서 사람이 직접 확인하는 영역입니다.

검증 전용 — 흔적을 남기지 않습니다

회귀 재검증은 사례 기록에만 결과가 남고, DB나 실제 문서·반입 대기열에는 아무 흔적도 남기지 않습니다. 검증에 통과한 자료를 실제로 넣으려면 평소처럼 반입(5장) 경로로 다시 들여와야 합니다.

22. LLM 작업 센터 v1.x

변환·풀이 생성·응용 문항 생성 같은 모든 LLM 작업의 진행 상황을 한 곳에서 보는 패널입니다. 어느 화면에 있든 열 수 있습니다:

  • PC·태블릿 — 왼쪽 사이드바 맨 아래 버튼(도움말 위). 진행·대기 중인 작업 수가 배지로 표시됩니다.
  • 폰 — 왼쪽 위 메뉴(☰)를 열면 LLM 작업 항목이 있습니다. 하단 탭은 그대로 5개입니다.

패널은 화면 위로 살짝 덮이는 방식이라 지금 하던 것(퀴즈·시험 응시 포함)이 끊기지 않습니다. 목록에는 진행 중 → 대기(순번) → 최근 끝난 작업(완료·실패·취소) 순으로 보이고, 각 항목의 [화면으로 이동]을 누르면 그 작업을 시작한 화면으로 갑니다.

취소

  • 대기 중인 작업 — 즉시 취소됩니다. 아직 아무것도 실행되지 않았으므로 비용 0입니다.
  • 실행 중인 작업 — 확인을 한 번 묻고 중단합니다. 이미 처리된 토큰만큼은 요금이 발생할 수 있습니다(취소 결과에 그때까지의 사용량을 표시합니다). 중간까지 만들어진 결과물은 저장하지 않고 버립니다.

일시정지

패널 위의 일시정지 토글은 "다음 작업부터 보류"라는 뜻입니다 — 지금 실행 중인 작업은 끝까지 진행됩니다(LLM 호출은 중간에 멈췄다 이어갈 수 없고, 다시 하면 요금이 이중으로 나가기 때문입니다). 보류 중에도 각 화면에서 작업을 새로 걸 수는 있고, 대기 목록에 쌓였다가 재개하면 순서대로 실행됩니다.

작업 화면에서 모델 바로 고르기

엔진을 고르는 작업 화면(반입·풀이 생성·응용 생성 등)에서 특정 엔진을 고르면 그 엔진의 모델도 바로 고를 수 있습니다. 여기서 고른 모델은 그 작업 1회에만 쓰이고, 설정(15장)의 저장된 선택은 바뀌지 않습니다. 고르지 않으면 설정값 그대로입니다.

진행 표시 복원

생성 중에 다른 화면으로 갔다 돌아와도 진행 표시가 자동으로 복원됩니다("진행 중 작업을 복원했습니다" 표시). 응용 모의고사처럼 오래 걸리는 생성도 안심하고 화면을 떠나도 됩니다.

알아둘 것

작업 목록은 최근 1시간 안의 기록만 보여주고, 서버(실행 창)를 껐다 켜면 목록이 비워집니다 — 영구 이력이 아닙니다. 변환이 끝난 결과물 자체는 사라지지 않습니다(최근 50건 보관, 5장 참고).

부록. 앱 내 탑재 메모 (결정 완료 — A안 구현됨)

이 문서를 앱 안에서 열 수 있게 하는 방안으로 검토했던 후보들 (v1 완성 시점의 메모):

방안내용비용
