## 확정 규약 (구현 전 결정 — 이 문서 + api §4.29 + screens §5.3 S35가 정본)

### A. 저장 모델·전환 판정 (DDL 3컬럼 — 마스터 §6.2 정본·R42)

- `content_blocks TEXT`(NULL 허용) — 앱 중립 블록 JSON `{version, blocks}`. **NULL = 미전환 문서.**
  NOT NULL이면 이 문서 **본문의 소스 오브 트루스**이고 `content`는 프로젝션으로 역할이 바뀐다.
- `explanation_blocks TEXT`(NULL 허용) — 해설 동일 규약. **전환 문서에서 해설이 없으면 NULL** —
  따라서 **전환 판정에 쓰지 않는다**.
- `blocks_version INTEGER`(NULL 허용) — `content_blocks.version`의 컬럼 사본(**서버가 채운다** — notes 전례 준용).
  **전환 판정·지연 마이그레이션 SQL 조회의 단일 기준**: 전환 문서 = `blocks_version IS NOT NULL`.
- 마이그레이션은 컬럼 추가뿐 — **기존 행 소급 0**(전부 NULL = 미전환으로 태어난다). 인덱스 신설 없음
  (개인 규모 수백 건 — YAGNI). 백업(F27)은 VACUUM INTO 자동 포함 — 개정 0.

### B. API 계약 (api §4.29 — 신규 엔드포인트 0)

- `GET /api/documents/{id}` 응답에 3필드 추가(`content_blocks`·`explanation_blocks` = 객체|null ·
  `blocks_version` = 정수|null). **목록·batch는 무변경**(블록 필드 미포함 — 인쇄는 프로젝션 소비).
- `PATCH /api/documents/{id}` — **동반 규칙 2쌍**(notes §4.28 ③ 준용): `content_blocks`↔`content` ·
  `explanation_blocks`↔`explanation` 각각 **항상 함께**(한쪽만 = 422 `projection_required`). 두 쌍은 서로 독립
  (본문만·해설만 저장 가능). `explanation_blocks: null` + `explanation` 동반 = 해설 블록 제거.
  `content_blocks: null` 전송은 불허(전환 해제는 클라이언트 명령이 아니다 — 규약 C).
- **얕은 검증만**(§4.28 ③ 동일 — version 1 이상 정수·blocks 배열까지. 딥 검증 금지: 스키마 정본은
  `frontend/src/editor2/schema/blocks.ts` 하나다). 상한 = 블록 필드 각 1,000,000자. 에러 3종
  (`blocks_invalid`·`projection_required`·`too_large`)은 §3 규약·코드 4종 불증.
- **프로젝션은 서버가 만들지 않는다** — 클라이언트 변환기(M32 `blocksToMarkdown`) 산출물을 함께 저장만.
- title·answer·choices·difficulty·style·tags 등 **다른 필드의 계약은 무변경**이며 전환 상태를 건드리지 않는다.

### C. 전환 해제(강등) 규약 — 이중 저장 드리프트의 원천 차단 (이 단계의 심장)

`content`를 직접 쓰는 기존 서버 경로(F30 재생성 [교체], F44 답지 해설 반영·해설 채택 등)는 블록을 모른다.
결선 없이 두면 전환 문서에서 **블록이 구본으로 남아, 다음 편집이 최신 본문을 옛 블록으로 되돌리는 조용한
손실**이 생긴다. 이를 규약으로 차단한다:

- **블록을 동반하지 않고 `content` 또는 `explanation`을 기록하는 모든 경로는 같은 트랜잭션에서 3컬럼을
  NULL로 되돌린다**(전환 해제). 해당 경로 = ⓐ 클라이언트 PATCH(구 편집기·DocEditor 모달 저장)
  ⓑ 서버 내부 기록 전부(**전수 조사 목록은 B-3에서 작성해 완료 기록에 표로** — 누락 1곳이 곧 조용한 손실 경로다).
  구현은 **공용 헬퍼 1곳**(경로별 복붙 금지).
- **전환 해제는 손실 이벤트가 아니다** — 프로젝션(그 시점의 최신 본문)이 소스로 승격될 뿐이고, 다음 편집
  저장에서 지연 전환이 재전환한다(복구 경로 겸용). 단 블록에만 담기던 표현(프로젝션 손실 목록 —
  M36 문서화 대상, 현재 표본 0~미미)은 그 시점 프로젝션 기준으로 남는다 — **알려진 동작으로 매뉴얼 명시**
  (조용한 손실 아님 — 규약으로 선언된 동작).
- **파생 응답 봉인**: quiz/session·resolve-embeds 등에는 블록 필드가 **부재**한다(필터링이 아니라 부재 —
  불변 규칙 1. `explanation_blocks`가 새 정답·해설 유출면이 되지 않는다).

### D. 저장 파이프라인·사이드카 결선 (인계 2·6 — 위반 시 즉시 가시 변형)

- 로드: `content`/`explanation`가 아니라 **`content_blocks`/`explanation_blocks`가 있으면 그것을** 어댑터로
  적재. 미전환 문서는 Markdown → `markdownToBlocks` 메모리 변환(규약 E).
- **어댑터 호출은 반드시 사이드카와 함께**: `toBlockNote` 결과의 sidecar를 보관하고, 저장은
  **`fromBlockNoteResult` 경유**(sidecar 전달)로만 한다. `fromBlockNoteBlocks`를 사이드카 없이 부르는
  **새 호출부 금지** — 흡수 7종(hardBreak·link title·image title/height·block meta + 2026-08-17 판정분
  listSpread·listGroupBreak·tableAlign)이 조용히 사라진다. 느슨한 목록 실문서가 실재하므로(3건)
  결선 누락은 **저장 즉시 눈에 보이는 변형**이 된다.
- **마이크로 마크 접힘 고지**: `fromBlockNoteResult().microMarkCollapses > 0`이면 기존 배너(노트의
  pasteNotice 계열 재사용)로 고지 — documents는 편집기 밖에서 만들어진 본문이 들어오는 첫 표면이다.
- 저장 = `PATCH { content_blocks, content }`(+해설 편집 시 `explanation_blocks, explanation`) —
  **항상 동반**(규약 B). 자동 저장·저장 상태 4종·IME 조합 중 보류는 **노트 규약(screens §5.16) 그대로 재사용**.

### E. 지연 전환 수명주기 (R36 — 일괄 변환 금지)

- **열람·편집 진입은 DB를 쓰지 않는다** — 변환은 메모리에서만(리더 무변경·쓰기 증폭 0).
  **블록 쌍을 처음 동반한 저장이 곧 전환**이다(별도 전환 엔드포인트 없음 — api §4.29 ③).
- 메모리 변환이 **미지원 사유를 보고하면** 그 문서는 **기존 편집기로 열린다**(읽기 전용 폴백이 아니라
  구 편집기 = 완전한 편집 경로가 퇴로다). 임의 손실 수용 금지(R34) — 신규 사유는 보고.
- 최초 전환 저장 시 1회 안내(저장 상태줄 — 문구는 구현 재량, 신규 컴포넌트 0).
- **배치 변환 스크립트**(F-5)는 API 경유 별도 수동 도구 — 서버 기동·마이그레이션에서의 자동 일괄 변환 금지.

### F. 진입점·퇴로 (screens §5.3 S35)

- **이 단계의 새 편집기 진입점 = 문서 상세(`/docs/:id`)의 편집 1곳.** 분기: 퇴로 토글 ON이고
  ⓐ 전환 문서이거나 ⓑ 메모리 변환이 미지원 0으로 성립 → 새 편집기 표면(본문·해설 2표면 —
  노트 §5.16 골격 재사용. **제목·choices·answer 등 나머지 필드는 기존 폼 유지** — D7 대기, 표면 통합은 M35).
  그 외 → 기존 편집기 그대로.
- **퇴로 토글**: 설정 실험실 카드 확장 — "문서 편집에 새 편집기 사용", **기본 ON**(기본 OFF면 실사용이
  일어나지 않아 D1 확정 실측이 나오지 않는다). OFF = 구 편집기 완전 복귀.
- **신규 문서 작성·DocEditor 모달 등 기존 진입점은 이 단계 무변경**(구 편집기) — 그 경로가 전환 문서를
  저장하면 규약 C에 따라 전환 해제된다(알려진 동작·매뉴얼 명시. 해소는 M35 표면 통합에서).
- **notes 표면은 실험실 격리 유지** — §5.16의 "격리 해제는 M34에서 함께 결정" 조항의 이행 결정 =
  **정식 노출하지 않는다**(documents가 정식 표면을 얻었으므로 승격 사유 소멸 — 재론은 M36 퇴역 판단과 함께).

### G. 리더 이미지 `{w=}` 반영 (M33 이월분 — "리더 무변경"의 명시 예외 1건)

- 판단 근거: documents 탑재 후 사용자는 **실문서에서** 이미지 크기를 조절하는데 리더가 무시하면
  정식 표면의 가시 결함이 된다(노트 베타 시절과 체감이 다르다). 이월분을 이 단계에 **편입 확정**.
- 계약: 공용 `MarkdownView` 계열(remarkStudy)이 이미지 크기 표기 `{w=}`(M32 확정 표기)를 폭으로 반영 —
  전 화면·인쇄 자동 파급(F43 앵커 원칙). **`{w=}`가 없는 이미지·기존 문서의 렌더 diff 0이 계약**이며,
  저장 전환 계층의 "무변경 확인"과 섞이지 않게 **별도 커밋으로 격리**한다(F-6).
