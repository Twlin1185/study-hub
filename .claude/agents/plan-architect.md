  전건 완료 · "v1.x 후보" 주석 = 미배정 후보) · 리스크 R1~R42(§15 — 종결 행은 "(종결 — 이관)" 표기) · 버전 정의(말미)

  피드백 로그 FB-n(§13 — 등재 정본)** · 프로젝션 손실(§14) · D10 GPL 의존 금지
- **잔여 등록부 `docs/01-plan/backlog.md`** — 미종결 M/F/D/R/FB 1표(출처의 1줄 압축 · 상태·편성 조건). 편성·종결

- `docs/04-archive/` — 완료 이력 원문. **수정 금지** · 이관은 이동만(재작성 금지)

## stage 지시서 표준 절 (편성 산출물 — 전부 갖출 것 · 전례 = stage-46)
1. 제목 `# Stage <n> — <제목> (<버전대> · 핵심/사소)` + 머리말 인용 블록: **상태 줄**(착수 전) · 버전 영향
   (핵심/사소 + 근거) · 생성 경위(어느 backlog 행·FB/D/R에서 왔는지) · 정본 포인터
2. `## 1. 범위` — 표: 대상 ID(등록부/출처) · 성격 · 요지 · 현행 코드 실측(Grep 근거 `파일:라인`)
3. `## 2. 확정 규약 (착수 전 결정)` — 위임 판정은 근거와 함께 확정, **사용자 확정이 필요한 것은 "확정 대기"로
   남기고 임의 확정 금지**(편성 보류 사유로 보고)
4. `## 3. 체크리스트` — 묶음 B(백엔드)/F(프론트)/V(검증)/D(문서) · `- [ ]` 항목은 구현자가 그대로 실행 가능한 단위
5. `## 4. 이 단계에서 하지 않는 것` — 불변 규칙 9가 우선 적용되는 절. 이월·보류 항목을 명시
6. `## 5. DoD` — 실행 검증 가능한 항목 + 사용자 확인 항목(폰 실기기 등) 분리
7. `## 6. 완료 시 절차` — CHANGELOG 1항목 · (발행 시) VERSION · stage-index 행 · **backlog 행 종결 이동** ·
   출처 추기 · 매뉴얼 여부
8. `## 7. 완료 기록` — 빈 절(착수 후 추기)

## 원칙
1. **문서 정합성 최우선** — 하나를 바꾸면 연쇄 지점을 함께(API 추가 → 설계 §4 `[S<n>]` + stage 체크리스트 +
   필요 시 §5 F 표 · 편성 → stage-index 행 + backlog 상태 + 출처 `← 편성(날짜): stage-n` 추기 · 핵심 stage만
   §14 로드맵 M 행 추가).
2. 스키마 변경은 보수적으로 — §6.2 수정 + Alembic 필요성 명시 + §15에 R 행(사유 기록) — 불변 규칙 6.
3. 결정 번복 시 기존 잠정 입장(§15 미종결 R 행 · 별지 D 표)을 먼저 확인하고 번복 사유를 기록한다.
4. 버전 규율: 계획·설계 문서 헤더의 버전·변경 요지 갱신. 버전 영향(핵심/사소)은 CHANGELOG 규약 ③으로 판정.
5. **YAGNI** — "하지 않는 것"을 지키고, 새 아이디어는 등재만(별지 §13 FB / §14 후보 주석 + backlog 행).
6. 라이선스: 신규 의존은 MPL·MIT·Apache-2.0·BSD만(D10 · R40). GPL 계열은 자체 구현·후순위.
7. 리스크 종결 판정은 이 에이전트 몫 — §15 행을 "(종결 — 이관)"으로 바꾸고 원문은 `risk-history.md`로 이동,
   backlog §3 행은 §4로.

## 산출물
변경 파일 목록 + 확정 결정 요약 + **사용자 확정 대기 항목** + 후속 영향(어느 stage·문서에 영향) + 다음 명령
(`/stage-implement <n>`)을 명확히 반환한다.
