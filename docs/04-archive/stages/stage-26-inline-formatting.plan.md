## 결정 요약 (plan §14 F52 ①~⑧ — 원문이 정본, 여기는 구현 관점 요지)

- **① rehype-raw(원시 HTML) 기각 유지**: `documents.content`에는 손편집분 + LLM 변환 산출물 + URL 반입 + docx/xlsx 추출 텍스트가 같은 컬럼으로 들어오고 원문 대조 게이트는 마크업을 검사하지 않는다 — raw 허용 = 전 반입 경로의 주입구. 대안 = remark-directive 인라인 확장 + 마이크로 문법 3종(화이트리스트만 — 임의 CSS·스크립트가 표현될 문자열 자체가 없다).
- **② 문법 5종 확정**: 밑줄 `++텍스트++` · 형광펜 `==텍스트==`(기본 노랑) · 인라인 스포일러 `||텍스트||` · 통합 인라인 directive `:t[텍스트]{c=red bg=yellow s=large}` · 콜아웃 `:::note[제목]`·`:::warn[제목]`·`:::tip[제목]`. 구현처 = `components/markdown/remarkStudy.ts` + 공용 `MarkdownView` 1곳(전 화면·인쇄 자동 파급 — F43·F51 전례).
- **②-1 우연 매칭 방어 3겹**: ⓐ 코드 스팬·펜스·수식·표 셀은 인라인 변환보다 앞 단계에서 소비(원리적 안전 — xlsx 추출 표의 `|`는 위험하지 않음) ⓑ 엄격 플랭킹(여는 기호 바로 뒤·닫는 기호 바로 앞 공백 금지 — `C++ and D++`는 구조적으로 탈락) ⓒ **기존 저장 문서 표본 실측 = 착수 계약**(R26 ② — 아래 0절).
- **③ 색 = 의미 팔레트 7색 고정**: `red·orange·yellow·green·blue·purple·gray` — 자유 hex 기각. 사용자는 이름만 고르고 다크 대응은 토큰이 담당(색 이름의 단일 출처는 screens §6 계약).
- **④ 편집 UX**: 툴바(선택 영역 래핑) + 단축키 + 분할 라이브 미리보기. 저장 소스는 Markdown 텍스트 유지 — F43 "WYSIWYG 기각" 불번복.
- **⑤ 인쇄 = 색 그대로**: `print-color-adjust: exact`(+`-webkit-` 병기)를 **형광펜·글자색 요소에만**. 인쇄 전용 색 토큰 0개(`@media print`가 항상 라이트 팔레트 — 흰 종이와 동일 조건). 흑백 프린터의 색 구분 소실은 물리 한계로 수용·매뉴얼 명문화. 팔레트 강제 조건 = 7색 전부 검정 글자 대비 확보.
- **⑥ 파급 검사**: 검색 스니펫 문법 문자 노출(경미·수용) · 임베드 카드 안 적용 유지 · 인라인 스포일러 ≠ 채점 경계(매뉴얼 명시).
- **⑦ 애니메이션 = 후속 이월**(기각 아님 — 재개는 계획서 먼저. 기존 F43 접기/가리기 전환·F09 카드 뒤집기는 그대로).
- **⑧ LLM 경계**: 표현 문법은 **사용자 손편집 전용** — 반입 변환 프롬프트(`convert.md`)는 무변경(창작 금지 R7과 표현 자유를 섞지 않는 유일한 선).

## 목표

끝났을 때, 사용자가 문서를 손편집할 때 밑줄·형광펜(7색)·글자색(7색)·부분 글자크기·문장 중간 단어 스포일러·콜아웃 3종을 툴바 버튼이나 단축키, 또는 문법 직접 타이핑으로 넣을 수 있고, 그 표현이 문서 상세·학습·퀴즈·시험·플래시카드·오답노트·인쇄 전 화면에서 동일하게(다크 모드는 토큰으로 자동 대응) 보이며, 인쇄 미리보기에서도 형광펜·글자색이 브라우저 배경 그래픽 설정과 무관하게 색 그대로 찍힌다. 기존 저장 문서의 표시는 우연 매칭 없이 그대로이고(표본 실측으로 보증), 백엔드·API·DB·프롬프트·LLM은 전부 무변경이다.

### 2. 파싱 — `components/markdown/remarkStudy.ts` 확장 (결정 ①·②·②-1)

- [x] **2-1. 마이크로 문법 3종**: `++밑줄++`·`==형광펜==`(기본 노랑)·`||인라인 스포일러||` — **엄격 플랭킹**(여는 기호 바로 뒤·닫는 기호 바로 앞 공백 금지 + 빈 내용 불가 — remark-math `$` 규칙과 동일 관례), 백슬래시 이스케이프(`\++` 등)로 리터럴 표기 가능. 코드 스팬·펜스·수식·표 셀 내부는 선행 파싱이 소비해 원리상 미매칭임을 구현에서 확인(테스트 표본에 포함).
- [x] **2-2. 통합 인라인 directive `:t[텍스트]{c= bg= s=}`**: 속성 화이트리스트 — `c`(글자색)·`bg`(형광펜 배경) ∈ 7색 이름, `s`(크기) ∈ **`small`·`large`·`xl`**(기존 font_scale 명명 `small|default|large` 계열 + xl — F53 size 명명 통일 결정 연동. 기본 크기 = 속성 생략. 결정 ② 원문의 `s=lg`는 예시 축약 표기로 판정 — 아래 리스크 참조). **화이트리스트 밖 값·미지 속성 = 해당 스타일만 무시하고 텍스트는 그대로 렌더**(오류 아님 — 조용히 깨지지 않게).
- [x] **2-3. 콜아웃 컨테이너 directive 3종**: `:::note[제목]`·`:::warn[제목]`·`:::tip[제목]` … `:::` — 기존 `:::fold`/`:::hide`(F43)와 같은 remark-directive 계열, 이름 화이트리스트 확장만. 미등록 directive 이름의 기존 처리 방식은 무변경.
- [x] **2-4. on/off 퇴로**: `MarkdownView`에 `inlineFormat?: boolean`(기본 `true`) prop — 마이크로 문법+`:t`+콜아웃 확장분을 1줄로 끌 수 있게(F51 `breaks?` prop 전례 — 전면 회수 퇴로가 계약).
- [x] **2-5. 신규 의존 0 실측**: 마이크로 문법 3종이 자체 플러그인 확장으로 충족되는지 확인 — 불가피하게 기성 플러그인이 필요하면 **계획서 등재 후 추가**(F43·F51 전례)하고 사유를 완료 기록에 남긴다.

## DoD (완료 정의)

**자동 검증 가능 항목** (전부 무비용 — 실 LLM 불요):

1. **문법 5종 렌더**: `++`·`==`·`||`·`:t{c= bg= s=}`·콜아웃 3종이 계약대로 렌더되고, 엄격 플랭킹 위반·화이트리스트 밖 값은 변환되지 않는다(원문 노출 — 오류 아님).
2. **표본 실측 완료(착수 계약)**: 기존 저장 문서 우연 매칭 실측이 재현 기준과 함께 기록되고, 충돌 0이거나 대응(기호 변경/스코프 축소)이 사유와 함께 기록됨 — "조용한 전면 적용" 0.
3. **토큰 정합**: 신규 색 = `--ink-*`·`--mark-*` 14개뿐(라이트·다크 쌍 + `@media print` 라이트 값 포함), 하드코딩 색 추가 0(invariant-scan PASS), mark 7색 전부 검정 글자 대비 확보.
4. **프론트 전용 확인**: 백엔드 파일 diff 0 · API·DB·프롬프트 무변경 · LLM 호출 0 · 신규 의존 0(불가피 시 계획서 등재 후 추가·사유 기록).
5. **회귀 0 + 퇴로**: F43·F51 기존 렌더·편집 기능 회귀 0, `npm run build` 통과, `inlineFormat` prop 1줄로 신규 문법 전체 off 가능.
6. **채점 경계 불변**: quiz/session 응답 계약 무변경(불변 규칙 1 — 백엔드 diff 0으로 충족) + 매뉴얼에 스포일러 오해 방지 명시.

**사용자 이행 항목**:

7. **실사용 확인**: 실 브라우저에서 툴바·단축키·분할 미리보기로 실제 문서를 편집하고, 라이트/다크 양 테마에서 7색 가독·스포일러 토글·콜아웃 표시를 확인 — 결함 표본은 기록(개선 입력).

## 리스크

- **우연 매칭(R26 ② — 이 단계의 최대 리스크)**: `++`·`==`·`||`는 기존 문서에 흔한 문자열 — 방어 3겹(선행 파싱 소비 + 엄격 플랭킹 + **착수 계약 표본 실측**)과 `inlineFormat` 퇴로를 계약에 내장. 충돌 실측 시 기호 변경/스코프 축소(조용한 전면 적용 금지).
- **`s=` 값 명명의 결정 간 긴장(전개 중 발견 — 보고 완료)**: 결정 ② 원문 예시는 `s=lg`, F53 확정은 "size 명명 통일(기존 3단계 명명 + xl)"이고 기존 font_scale 명명은 `small|default|large`다. 이 지시서는 **통일 결정을 우선해 `small·large·xl`로 전개**(`lg`는 예시 축약 표기로 판정 — 문법 *형태*는 결정 ②, 값 *명명*은 F53 통일 결정이 각각 정본). 구현 착수 전 사용자 한 줄 확인 권장 — 뒤집히면 screens §5.3·§6과 이 문서를 함께 갱신(연쇄 수정 3곳뿐, 착수 전이면 비용 0).
- **인쇄 속성 최초 도입**: `print-color-adjust: exact` 사용 0건 상태에서 첫 도입 — 적용 범위를 mark/ink 요소로 좁혀 부작용 면을 최소화, 실측은 DoD 8(사용자 이행).
- **파싱 확장의 전 화면 파급**: MarkdownView 1곳 확장이 전 화면·인쇄에 동시 적용(이점이자 리스크 — F51 remark-breaks 전례) — 표본 실측(0절)·회귀 확인(7-4)·퇴로(2-4)로 상쇄.
